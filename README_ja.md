# NPP：二者・三者のLLMによる記憶・承認・協調

**正しい答えが出ても、記録が正しいとは限らない。合意を忠実に実行できても、その合意が適切とは限らない。**

二者・三者のLLMによる実験で、正答の裏に残る出典の誤り、全体の成績には表れない局所的な修復、不適切な合意に忠実に従う後続回答が観測されました。実際に保存された記録と、次の入力・回答を対応づけて、こうした違いがどこで生じるかを追跡しています。

**NPPは、各役に属する情報・判断・承認を保ちながら協調を進めるために、何を別々に点検すべきかを調べる研究です。** このフォルダには、第一〜第四報、知見を統合した故障学・設計論、可読コード、実験の証拠をまとめています。

[English README](README.md) · [実験一覧](experiments/README.md) · [Apache 2.0](LICENSE)

## 見えてきたこと

| 知見 | 観測されたこと | 対応する論文 |
|---|---|---|
| **正答と誤出典が共存した。** | 内容が正しい保存ノートに誤った出典IDが結び付き、後続回答も正しい判断と誤IDを一緒に引き継いだ。 | [第一報](papers/paper-01/manuscript-v0.11-2026-09-23.md) |
| **全体の成績に表れない修復があった。** | 同じ更新案への比較で、共同の答えが正しくても各役の観測記録が古い条件と、観測記録が直っても別の不備が残り、全工程の成立数が変わらない条件を確認した。 | [第二報](papers/paper-02/manuscript-ja-v0.4-2026-09-27.md) |
| **安定した本人判断と不適切な合意が共存した。** | 各役の推奨が保たれた実行でも、課題の目的に照らして劣る共同案を承認し、後続回答はその合意に忠実に従った。 | [第三報](papers/paper-03/manuscript-ja-v0.2-2026-09-29.md) |
| **全体は正しく保留しながら、個々の返答を読み違えた。** | 三者系の読出しで、合意と実行を正しく保留しつつ、未返答を本人の明示的な保留と記述した。 | [第四報](papers/paper-04/manuscript-ja-v0.2-2026-10-13.md) |

これらの観測は、**答えの正しさ、記録の正確さ、合意の適切さ、実行の忠実さを分けて測る必要性**を示しています。また、局所的な修復と全工程の成立を併せて見ることで、直った箇所と残った不備の両方を捉えられます。

## 設計への示唆

[故障学・設計論](papers/two-role-failure-design/manuscript-ja-v0.6-2026-10-13.md)では、観測を次の設計原則へつなぎ、具体例と実装コードで説明しています。

- **記録と、その次の利用を照合する。** 内容を人物・版・出典と結び付け、保存物と実際の後続入力の双方で対応を確認する。
- **修復した単位で成果を測る。** どの欄が直り、どこに不備が残ったかを、全工程の成否と併せて報告する。
- **本人判断・案の評価・実際の票・実行許可を分ける。** 実行許可は届いた票と合意規則から判定し、本人の推奨と共同計画での担当行動を区別して保持する。
- **ルールで決まる転記・形式検査・集計をコードへ分ける。** LLMが生成する提案や解釈との接続を点検し、その処理が担当していない欄も評価する。

## どう調べたか

各実験では、**同じLLMを別々の文脈で二役または三役として実行**します。各役へ異なる情報や経験を与え、比較条件に応じて、モデルと管理コードによるノートの更新・共有、候補案の評価、承認状態の読出しを行います。実際に保存されたノートを後続の入力へ渡し、保存物・次の入力・その回答を対応づけます。

例えば、担当客の希望を犬／猫の絵柄で区別し、共同の案内方法を紙／デジタルから選ぶ課題を使います。誰に属する情報かと、共同で決める内容を見分けやすくするための題材です。後続の課題では、経験に基づく本人の推奨と数値で比較する共同案を扱い、三者系では未返答・明示保留・承認も区別します。

各知見は、小規模な合成課題で得た探索的な結果です。共同案の適切さは各課題で指定した目的に対して評価しています。対象モデル・条件・標本単位・欠測・不確実性は、各論文に記載しています。

## コードと実験記録を見る

最初の例には、[OR01：保存先別の修復比較](experiments/OR01/README.md)が分かりやすいです。同じ更新案に四つの保存処理を適用し、直った欄・残った不備・その後の利用を比較しています。各試験の `logs/` で入力・原回答・保存ノートを読み、`archives/` で返送された原ZIPを確認できます。

三者系は[TAR01](experiments/TAR01/README.md)から、未返答・明示保留・全員承認の入力と回答を比較できます。[実験一覧](experiments/README.md)には、全試験の略号と記録への入口をまとめています。

実装を読むには、[OR01のソース](experiments/OR01/generation/source/)や[TAR01のソース](experiments/TAR01/generation/source/)を参照してください。各試験の`generation/`には、普通のPythonファイルと固定材料・設定を収録しています。`run_colab.py`の通常起動はファイル照合のみで、モデル実行はColab上で`--run`を明示した場合に行います。[可読コードと生成手順](docs/READABLE_GENERATION.md)。

## 保存結果を検算する

オフライン再集計は、保存済み回答を採点・集計する処理です。GPU・モデルの取得・認証情報・API呼出しは不要です。

現在の実行手順は **[RUNNING.md](RUNNING.md)**（2026-10-29）を優先してください。NPP研究ルートの環境はPython 3.13.17です。この研究フォルダ内では、NPPルートからファイル整合性だけを確認できます。

```sh
.venv/bin/python GitHub公開用/replay.py --verify
```

公開用フォルダを別の場所で単独利用する場合は、そのコピーのルートに専用の `.venv` を用意し、`.venv/bin/python replay.py --verify` を使います。hash検査は標準ライブラリだけで動き、原ZIPを含めて読み取り照合します。

`--trial`・`--paper-01`・`--all` と[第四報データ再生成](tools/rebuild_paper04_data.py)は、計算結果をファイルへ書き込みます。対応する固定仕様・依存版を確認し、別の作業コピーとその `.venv` で実行してください。

保存済み回答の再集計では、第一報・後続28試験・初回TB01エラー記録が元の集計と一致しました。第四報の本文用データと事例抜粋も、26原資料からbyte一致で再生成できています。[検証の要約](VERIFICATION.md)／[詳細記録](verification/README.md)。

## 収録資料と評価範囲

第一報は原回答1,127件を保持し、うち792件を再採点します。残る335件の初期回答と元集計も収録しています。後続28件のQwen試験は、完走29原ZIP・5,080回答ファイルを収録し、TB01の初回0生成のエラーZIPを別に保持しています。このうち三者系5試験は459回答です。

回答数・役・分岐・反復をそのまま独立したNとして数えず、各論文の分母を使います。正式な欠測と事後参考分析は区別しています。実験の入力・回答は元の日本語を保持しています。

[収録範囲](PUBLICATION_SCOPE.md)には、各論文に先立つ探索の文書や対象外資料を明記しています。論文と実験記録に対応する資料を選んで収録しています。
