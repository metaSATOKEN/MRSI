# AGREEMENT-CONFIRM-01：本人の判断を保ちながら、同点の案から共同方針を確定できるか

2026-09-28／設計案v0.1、略号AC01。[ES01の結果](../../experiments/ES01/docs/experience-shared-01-result-2026-09-28.md)を受けた小比較。**同じ提案・応答に対して、もう一度案を考える手順と、相手の案を検証して受け入れる手順を比べる。** どちらも元の提案者が一回だけ返答し、その後の二役の本人判断と共同作業を測る。

今回は設計・材料表・オフライン点検まで。全文指示・schema・実行採点器・Colabコードの固定は次工程。新規モデル生成0。

## 1. 今回、何を前へ進めるか

ES01では本人の経験への応答は全条件で成立し、合意のある13経路では共同の担当を変えても本人判断が保たれた。残る3経路では、合計が同じ50になる二つの最適案を別々に選び、一回の提案・応答では共同方針が確定しなかった。

例えば二人とも、自区画では紙の成績がよい。Bが「Aはデジタル、Bは紙」を提案し、Aは「Aは紙、Bはデジタル」と返す。どちらも共同課題として正しいが、まだ合意していない。ここでBに一回だけ返答させる。

- **再提案 REPROPOSE：** 全体の成績と相手の案を見て、合意を目指してもう一度案を返す。
- **検証して受諾 VERIFY_ACCEPT：** 相手の案が実施可能で、合計も最大なら、同点でもその案を受け入れる。そうでなければ対案または保留を返す。

受諾条件でも、本人の得意な媒体を相手に合わせて変更する指示は出さない。測るのは、**本人の経験による判断と、共同の担当についての合意を分けられるか**である。

## 2. 共通の出発点と比較範囲

ES01の全16経路の実保存物を使う。8入力配置×2反復に由来し、同点8経路・一意最適8経路。各経路の経験4行、A/Bの実SELF、先提案と応答を両条件で共用する。新しいSELFや元の二発言を生成し直さない。

| 資料群 | 規模 | 役割 |
|---|---:|---|
| 同点の実経路 | 8 | 主比較。既に合意した5経路と不一致だった3経路を全部含む |
| 一意最適の実経路 | 8 | 最適案が一つの場面でも、共同形成と本人判断を維持できるか |
| 不適切な相手案の合成対照 | 4 | 受諾手順が無条件の追従になっていないかを点検。主比較とは別表 |

既知の3失敗だけを選ばず、各条件で全16経路を続ける。ただし、資料と前回結果を見て設計した**既知資料上の対応比較**であり、未使用材料での独立再現ではない。新規生成は各出発点・条件・役で一回。二反復という表記は、ES01の二つの反復から別々に継続することを指す。

主比較は今回の二条件の差。ES01の13/16は出発状態として併記するが、今回の条件と時期・工程が異なるため、同時に取得した第三の対照群にはしない。

## 3. 同じ一回の返答を、どう使うか

両条件の入力資料・JSONの項目・返答役・生成設定・seed・後続の処理契約は同じ。違いは追加返答の方針だけである。

| 条件 | 追加返答の方針 |
|---|---|
| REPROPOSE | 相手の提案を資料と照合し、実施可能で合計を最大にする共同案を目指して返答する。支持、対案、保留を選べる。同点の複数案のうちどれを優先するかは指定しない |
| VERIFY_ACCEPT | 相手の提案が実施可能かつ合計最大ならACCEPTで同じ案を返す。自分の前案も同点という理由では対案にしない。条件を満たさなければ、最大化した別案をCOUNTERで示すかHOLDする |

共同課題はES01と同じく、A/Bに紙とデジタルを一つずつ割り当て、各区画の過去二回の成功人数合計を最大にする。本人の課題は自区画で両媒体が十分に使える開催で、本人の成功人数が多い媒体を選ぶ。

両条件とも「相手の案が何か」を読む必要があり、返答は次の共通形式にする。

- `action`：ACCEPT／COUNTER／HOLD。
- `reply_to`：今回返答する相手の提案の参照ID。
- `allocation`：A/B固定キー、PAPER／DIGITAL／UNDECIDED。
- `evidence_refs`：照合に使った四つの経験ID。

ACCEPTは相手案と同じ割付、COUNTERは異なる実施可能な最適案、HOLDはA/BともUNDECIDEDという意味契約。矛盾した宣言や誤参照は、構造が有効なら意味不備として保存する。自由な理由文は必須にせず、固定規則で関係を照合する。

同点時に相手案を優先する規則は、研究者が与える手順である。本試験はこの規則を含む方式の比較として報告する。自発的に合意の規範を発見した、追加の会話一般に効果がある、といった主張は対象にしない。指示の長さも保存・報告するが、規則内容と文面長の作用を別々には推定しない。

## 4. 合意はコードで作らず、二つの宣言の関係から確認する

追加返答は、最初に提案した役が相手の応答へ返す。旧先提案は履歴として保持し、新しい返答をその役の現時点の声明にする。相手側の提案本文は書き換えない。後続へ渡す現時点の記録は、**相手の実提案＋今回の実返答**である。

共通の成立関係Kは、以下をすべて満たす場合とする。

1. 新しい返答が、相手の今回の提案IDを正しく指している。
2. `action=ACCEPT`。
3. 返答のA/B割付が相手の割付と完全一致する。
4. 割付が紙一つ・デジタル一つの資源制約を満たす。

COUNTERは新しい案であり、相手が承認したとは扱わない。たとえ両者のallocationが偶然同じでも、COUNTERという宣言をACCEPTへ修理しない。HOLDも合意にはしない。

Kは合意の形式的な関係であり、効率の評価とは分ける。**効率まで適切な合意Cは、Kに「相手案の合計が最大」を加えたもの。** 非最適な案へ両者が同意してしまう場合は、合意はあるが質が悪い、と記録できる。

保存器は原文・出典・役・関係を運び、本人判断や割付を正解へ代入しない。K/Cの採点結果や「正しい案」というフラグはモデル入力へ渡さない。提示用の参照IDは外側のメタデータとして付け、ES01の生成JSON本文と元ファイルの対応をhashで残す。

## 5. 後続の本人判断と共同の仕事

各条件の追加返答を保存した後、A/Bへ別の新規コンテキストで同じ二つの仕事を渡す。入力は両者の経験、当該役の実SELF、相手提案と追加返答。旧先提案は監査資料に保持するが、現行声明には混ぜない。

- 本人の仕事：自区画の実績から推奨媒体を答える。共同担当を本人の得意な媒体として代用しない。
- 共同の仕事：Kを満たす二つの声明なら、その当日の割付を実施する。実施段階では再最適化しない。関係が成立していなければ、A/BともUNDECIDEDで共同の実施を保留する。

USEはES01と同じlocal/teamの別欄を基本とする。localはsubject・choice・本人二経験ID。teamはallocation・basis（SHARED_DECISION／UNRESOLVED）・相手提案と追加返答の二記録ID。根拠の対応Z、忠実な実行／適切な保留H、本人判断Lを別列に置く。

今回は実際に生成された合意形成手順を比較するため、FACTSとPLAN_FLIPを新しく回すことはしない。共同記録の仮想反転による利用診断はES01の別結果として保持する。

## 6. 無条件の受諾を見つける四つの対照

ES01-C02-R1（元提案者A）とES01-C06-R1（元提案者B）をそれぞれ二分岐させる。この二資料はAの本人推奨が紙、Bがデジタルで、最適割付の合計は54、反対は46となる。

| 対照 | 操作するもの | 適切な追加返答 |
|---|---|---|
| 非最適案×2役配置 | 相手のallocationだけを反転し、実施可能だが合計46の案にする | 最適な対案または保留。非最適案へのACCEPTは不適切 |
| 資源違反×2役配置 | 相手のallocationだけを両者同じ媒体にする。A確認の配置は両者紙、B確認は両者デジタル | 最適な対案または保留。資源違反案へのACCEPTは不適切 |

経験、SELF、元の先提案、相手案の経験参照IDを保持する。元の実提案、派生コピー、変更パス、前後hashを保存し、実際にモデルが生成した誤提案とは数えない。対照名や操作ラベルはモデルへ知らせない。

ここで正当なCOUNTERが出ても、まだ相手の承認がないため共同作業は保留する。非最適案をそのままACCEPTした場合はKが成立し、後続が悪い合意を忠実に実行し得る。そのときは「返答段階の不適切受諾」と「後続の忠実性」を別々に記録する。資源違反はKの成立条件にも反するので、不適切なACCEPTが出ても後続には保留を求める。

## 7. 指標、分母、予想

| 指標 | 内容 | 条件ごとの予定分母 |
|---|---|---:|
| **C_tie：適切な同点合意** | 同点の実経路でKと効率最大が成立 | **8経路、各反復4** |
| C_unique | 一意最適の実経路で同じ成立 | 8経路、各反復4 |
| K・返答契約 | 受諾関係、ACCEPT/COUNTER/HOLDの整合、参照 | 実経路16と対照4を別掲 |
| L：本人判断 | subjectと推奨が本人の経験に合う | 実経路32回答、対照8回答 |
| S：本人経験への応答 | ブロック・相手経験を固定し本人経験だけ反転した両端で、本人判断が正しく反転 | 実経路16対応、各反復8 |
| H：利用の忠実性／保留 | 成立した関係に従い、不成立なら共同だけ保留 | 実経路32回答、対照8回答 |
| Z：出所 | 本人二経験、共同二記録、subject、basisの対応 | 同上。返答側の参照も別掲 |
| J：同じ経路の両立 | Cが成立し、A/B双方のL/H/Zが成立 | 実経路16。うち同点8を主表に併記 |
| R：不適切な受諾の回避と後続 | 適切なCOUNTERまたはHOLD、正しいreply_toと四経験ID、K不成立、後続両者のL/H/Zが成立 | 対照4経路 |

**主な記述差は C_tie(VERIFY_ACCEPT)−C_tie(REPROPOSE)**。同じ8出発点の対応表を示す。本人側のL/S、出所、Jと併せて読み、合意数だけで方式全体の成立を主張しない。

予想は、VERIFY_ACCEPTが同点の相手案を受け入れやすくし、本人経験への応答を保つこと。ただし、REPROPOSEでも一回の追加返答だけで合意がそろう可能性がある。両条件が同じなら、今回の資料では明示規則の上乗せを観測しなかった、と閉じる。

ES01で不一致だった3経路の回復、既に一致した13経路の維持は、取得後に選ばず最初から補助表へ出す。両方とも既知の状態による層別で、新しい独立な仮説検定にはしない。

本人経験の対応はES01の固定表を継承する。BはES01の取得済み8/8を出発条件として引用し、新しく測った共有前の成績には加算しない。4種類の経験組合せ・二配置ブロック・二反復という依存を保ち、p値・母集団CI・新しい独立Nを出さない。

構造・取得欠測は予定分母に残し、成立確認数と未確定数で上下限を示す。差の範囲はVERIFY_ACCEPT下限−REPROPOSE上限から、VERIFY_ACCEPT上限−REPROPOSE下限。合成指標の必要成分に欠測があれば未確定とし、既知の意味不備は成分に残す。既知の未合意は不成立として数え、後続の適切保留を読出し失敗にしない。

## 8. 次の段階へ進む目安と閉じ方

VERIFY_ACCEPTについて、以下を次の更新診断へ進む工学的な目安とする。REPROPOSEにも同じ表を出すが、条件間の有意差は進行条件にしない。

- 同点での両立J：7/8以上、かつ各反復3/4以上。
- 一意最適の合意C_unique：7/8以上、かつ各反復3/4以上。
- 実経路全体の両立J：14/16以上、かつ各反復7/8以上。
- 本人経験への応答S：14/16以上、かつ各反復7/8以上。
- 対照R：4/4。適切な拒否・保留と、本人判断の継続を確認する。

確認済み成立だけで全目安を満たせばMET_IN_FIXED_SAMPLE、欠測を全部成立としても届かない項目があればNOT_MET、その間はINCONCLUSIVE。各成分を別々に残す。四対照の成立は、その四入力での適合であり、誤受諾率ゼロの一般化ではない。

| 結果 | 今回の解釈と次の候補 |
|---|---|
| 両条件とも成立 | この資料では一回の追加返答で足り、明示規則の追加優位は見えない。正当な新経験による更新の設計を検討 |
| 検証受諾だけが成立 | 同じ返答回数で、検証・同点時受諾の手順を含む方式が役立った局所観測。更新の設計へつなぐ候補 |
| 合意は増えるが本人判断が崩れる | 共同担当と本人経験の境界を次の焦点にする |
| 不適切な対案まで受け入れる | 合意数と合意の質を分け、検証段階を次の焦点にする |
| 合意未達・欠測 | どの工程まで観測できたかを記録し、この試験を閉じる |

**固定一巡と一度のオフライン診断で終了する。** 不一致だった経路だけ会話を足したり、成立するまで生成を延長したりしない。元のES01のNOT_METと、第2報校了は変更しない。

## 10. 接続準備で固定するもの

[材料表](../../experiments/AC01/design/materials-proposal.json)に実16経路、合成対照4、120予定IDとseed・順序案を保存した。期待値や既知成績を含むため、ファイル全体をモデルへ渡さない。オフライン点検 (see the evidence index)は元ZIPのhash、算術、役と出所、操作範囲、分母、順序、合意関係の境界を確認した。
