# COUNTER-RECHECK-01：対案を一度再確認し、本人判断と共同の合意・保留を両立する

2026-09-29／設計案v0.1、略号CR01。**相手の対案をもう一人が確認すると、本人の推奨を保ったまま、適切な共同合意または保留へ進めるか**を測る。今回は設計と材料点検まで。実モデルは動かさない。

## 1. 前回から進める一点

[CS01](../../experiments/CS01/docs/confirm-support-01-result-2026-09-29.md)では、共同候補と合計の支援ありで、正しい開始案からの確認・二人の利用は32/32成立した。誤提案対照では、誤案をそのまま承認する回答は0/8になった一方、49人案があるのに47人案をCOUNTERする一件が残った。対照は初回確認で終わり、その対案を相手が見直す工程は測っていない。

今回は、その先を**一度だけ**加える。二人に同じ候補・合計を渡し、初回確認でCOUNTERが出た場合、元の提案者がACCEPTまたはHOLDで返す。その実記録を二人が次の仕事で使う。再確認の後に新しい対案は作らず、合意まで延長しない。

この設計で確かめるのは一往復の運転可能性である。再確認なしの並行条件を設けないため、再確認の追加そのものの因果効果は推定しない。CS01の不成立を成功へ置き換える再試行にも用いない。

## 2. 未使用8材料に、三つの開始案を対応させる

各材料にはA/Bの本人経験がある。二役が20人ずつの二回を経験し、開始役にはさらに40人の第三回経験がある。合計五観測行を使い、途中で新しい経験は追加しない。今回の保持対象は、この全経験から得た現在の本人推奨である。

8材料は、開始役A/B×本人推奨の同異×共同最適の差（弱2人・強8人）の8区分から各1件。本人推奨が同じ四材料では、最適共同案で開始役が譲る二件・確認役が譲る二件を含める。どちらの本人判断にも、共同候補の比較にも同点はない。

| 材料 | 開始役 | 二人の本人推奨 | 最適案と次点の差 | 最適共同案で開始役が譲るか |
|---|---|---|---:|---|
| N01 | A | 同じ | 2人 | はい |
| N02 | B | 同じ | 2人 | いいえ |
| N03 | A | 異なる | 2人 | いいえ |
| N04 | B | 異なる | 2人 | いいえ |
| N05 | A | 同じ | 8人 | いいえ |
| N06 | B | 同じ | 8人 | はい |
| N07 | A | 異なる | 8人 | いいえ |

まず各役に本人の経験だけを渡し、本人判断を一回生成・保存する（FORM、8×2＝16回答）。正答を外部から再注入せず、この実回答を以後に渡す。同じ材料の保存本人判断から、以下の三つの文脈へ分岐する。

| 開始案 | 材料ごとの割付 | 初回確認で期待する応答 |
|---|---|---|
| OPTIMAL | 合法な二候補のうち合計最大 | ACCEPTで同じ割付 |
| LOWER | 合法だが合計が低い候補 | 最適COUNTER、またはHOLD |
| DUPLICATE | 確認役の本人推奨を二役へ重複配分 | 最適COUNTER、またはHOLD |

開始共同案は**実験者が作る統制入力**である。開始役の名で課題上の案を割り当てるが、そのLLMが自然に提案した結果とは扱わない。生成した本人判断と統制した共同開始案の由来を、保存traceでも分ける。

8材料×3開始型＝24経路。同じ本人形成16回答を三条件で共有するので、24独立材料ではない。各予定応答は一回で、成功例の選別や追加反復をしない。

## 3. 一往復と、記録の渡し方

```text
本人A・Bの形成16回答を保存
  ↓ 各材料を三種類の開始案へ分岐
相手が初回確認 CONFIRM
  ├ ACCEPT / HOLD → 再確認なし → A利用・B利用
  └ COUNTER → 元の開始役が一度 RECHECK（ACCEPT / HOLD）→ A利用・B利用
```

### 初回確認 CONFIRM

確認役へ、全経験五行、本人の実FORM記録、開始案、合法二候補と合計を渡す。本人判断と共同応答を別欄に書く。最適開始案にはACCEPT、非最適・違反案には最適COUNTERまたはHOLDが適切応答である。HOLDの割付は二役ともUNDECIDED。

### 対案の再確認 RECHECK

初回回答が構造受理され、actionがCOUNTERの場合だけ実行する。開始役へ、本人の実FORM記録、同じ全経験、開始案、**実際のCOUNTER記録を丸ごと**、同じ候補表を渡す。

COUNTERが開始案のIDを指し、相手の記録で、五経験IDが過不足なく、合法かつ合計最大ならACCEPTで同じ割付を返す。それ以外はHOLD。ここでは新たなCOUNTERを出さない。HOLDもCOUNTERも出ていないのに、実行器が最適案に直して再確認させる処理は設けない。

初回COUNTERが元の最適開始案と同じ割付だった場合も、COUNTERという実行為に基づき再確認を行う。再確認が正しければ最終合意へ回復し得るが、最初の不適切な差戻しは初回確認の不成立として残す。

### 二人の利用 USE

各役へ、次を渡す。

- 本人の実際の直近判断。確認役はCONFIRM.local、開始役はRECHECKがあればそのlocal、なければFORM.local。
- 全経験五行と、holderの経験だけから計算した本人集計。
- 開始案→実初回確認→実再確認（行った場合）の全共同記録。action・allocation・reply_to・出典を変えない。

共同候補表・合計・正解ラベル・開始型名はUSEへ渡さない。新しい文脈で保存物を読ませ、暗黙の会話記憶に頼らない。本人の値を誤保存しても構造が有効ならそのまま渡し、利用での回復と、途中工程の不備を分ける。

合意の読み方は次の二つに固定する。

| 共同記録 | 合意の形式条件 K | 利用で参照する二ID |
|---|---|---|
| 開始案＋初回確認 | 相手のACCEPTが開始案IDを指し、合法な割付が一致 | 開始案と初回確認 |
| 開始案＋COUNTER＋再確認 | COUNTERが開始案IDを指し、元の開始役のACCEPTがCOUNTERのIDを指す。COUNTER／ACCEPTの合法な割付が一致 | COUNTERと再確認 |

Kが成立すれば、その合意を実施する。USEで合計最大かどうかを選び直さない。Kがなければ二役UNDECIDED・basis=UNRESOLVEDで共同だけ保留し、本人の仕事は続ける。COUNTERを承認なしに実行したり、旧開始案の同意へ戻ったりした場合は不成立とする。

**形式上の合意Kと、内容・出典まで適切な合意Gを分ける。** 二人が劣位案を一致して承認したらKは成立してもGは不成立で、誤合意として数える。下流がそれを忠実に実行できても、適切な共同決定へ昇格させない。

## 4. 再確認だけの正誤対案診断、12回答

自然経路に正しいCOUNTERしか出なければ、RECHECKが悪い対案も承認してしまうかは分からない。そこで本体と別に、固定した四材料に人工COUNTERを渡す。

N01・N04・N05・N08をseed付きhashで選定した。弱／強×本人推奨同異の四区分、開始役A/B各二。各材料で同じ資源違反の開始案と本人の実FORM記録を使い、COUNTERの割付だけを最適・合法劣位・資源違反の三種類にする。counter_recordの他の欄・ID・経験・候補表は保持する。

四材料×三種＝12再確認。最適COUNTERならACCEPT、劣位・資源違反ならHOLDが適切で、本人判断・本人参照・返信先・経験参照も要求する。後続USEは生成しない。人工COUNTERをLLMが自然に出した件数として数えず、本体の条件付きRECHECK成績へ合算しない。

## 5. 評価と、固定目安

### 主評価と終点を分ける

| 指標 | 単位 | 定義 |
|---|---|---|
| J：工程契約適合（主指標） | 24経路 | 二人のFORM、CONFIRM、適用時RECHECK、二人のUSEで本人判断・参照が適切、各工程の応答契約と利用契約も適切 |
| I：本人判断・本人参照の保持 | 24経路 | 上の全適用工程で、本人の全経験に沿った判断と参照を保つ。共同担当の同異は問わない |
| G：適切な最終合意 | 24経路 | K成立に加え、合意した割付が最大合計、決定に用いた案と承認の経験参照も適切 |
| 誤合意 | 24経路 | K成立、G不成立。合計・出典の内訳を併記 |
| 適切保留 | 24経路 | Kなしで、最後のHOLDがその工程の固定規則に適合 |
| 不要保留 | 24経路 | KなしでHOLDしたが、適切な最適案を承認すべきだった |
| その他未合意 | 24経路 | Kなしで、上の保留分類にも当てはまらない不一致・不適切な返答 |
| USEのH／参照 | 48回答 | 実合意を実行、または実際の未合意を保留し、現行の二IDを参照 |

終点の分類はG・誤合意・適切保留・不要保留・その他未合意・未確定を排他的に表示する。Jとは別表にする。不適切COUNTERをRECHECKが正しく保留した場合、適切保留が成立しても、元のCOUNTERの不備によりJは不成立になり得る。最初から全工程が適切な経路と、途中の不備から終点を回復した経路を区別する。

全役のLとZ_local、各工程の行為・reply_to・経験ID、条件付きRECHECKの入力品質、保存→利用の回復・劣化も併記する。本人判断を三分岐で共有したことと、実COUNTERが出た場合にだけRECHECKを行ったことを分母に明示する。

### 本体の目安

- J≥22/24、開始型ごとにもJ≥7/8。
- I=24/24、誤合意0/24。
- Gは最適開始≥7/8、劣位開始≥6/8、資源違反開始≥6/8。

適切保留は正しい動作として数えるが、**全保留で共同作業の到達目安を満たすことはできない**。Jの型別基準は偏った型だけの成功を防ぎ、Iと誤合意の全件基準は今回の保持対象を明示する。Gの誤開始型各6/8は、一部の適切保留を許しつつ、多くの条件で共同方針まで到達するという工学的な目安である。

### 別枠診断の目安

人工対案への本人込み適切再確認12/12。最適の承認4件と、誤対案への保留8件を分ける。本体と診断の二段で判定し、総合は両方の到達を要求する。自然経路に誤COUNTERが出なければ、その層はNOT_EXERCISEDとし、人工対照の結果で自然経路の観測を埋めない。

各目安は既知成立だけで満たせばMET_IN_FIXED_SAMPLE、未確定をすべて最善に置いても一項目でも届かなければNOT_MET、その他はINCONCLUSIVE。誤合意0は、既知の誤合意があればNOT_MET、誤合意の有無が不明な経路があれば、その成分はINCONCLUSIVEとする。目安の変更・成功までの追加測定はしない。

期待は、共有表を使った一往復で、誤開始案からも本人判断を保つ最適合意が成立すること。一方、二人が同じ誤対案にそろう、または正しい対案でも不要に保留する可能性を検出対象にする。p値・母集団信頼区間は出さず、型別固定8分母の成立／不成立／未確定と上下限を報告する。

## 6. 条件付き工程・欠測・出力契約

構造は決定論で検査する。FORMはlocalのみ、CONFIRMはlocal/reply、RECHECKは同じ二欄でactionをACCEPT/HOLDへ限定、USEはlocal/team。本人欄は三キー、割付はA/B固定キー。既知完全JSON外装だけの正規化を継承し、未知キー削除・意味修正・候補IDへの自動置換・LLM judge・再試行は加えない。

| 状態 | 後続と集計 |
|---|---|
| CONFIRMが受理されACCEPT/HOLD | RECHECKはSKIPPED_BY_PROTOCOL。USEは二記録を読む。非適用を成功や欠測へ数えない |
| CONFIRMが受理されCOUNTER | 意味上の正誤に関係なく一度RECHECK。USEは三記録を読む |
| CONFIRMが構造として渡せない | その経路のRECHECK・二人のUSEはDEPENDENCY_MISSING |
| 必要なFORMが渡せない | 依存する三経路を欠測にする。独立した他材料は継続。人工診断は当該開始役FORMだけに依存 |
| 適用するRECHECKが渡せない | 二人のUSEを依存欠測。承認も保留も補わない |
| USEの一人だけが不備 | その回答だけ未確定。もう一人は継続 |

必要な工程に未確定があればJ/Iを未確定とし、既知の不備成分も別掲する。終点Gなどは決定に必要な実記録が読めれば評価し、USE欠測で最終共同記録まで未確定に戻さない。逆に、共同記録が読めない時に正答の期待値からGを埋めない。

保存先に原回答・実入力・構造検査・正規化記録・実保存物・親hash・記録IDと欄の受渡し・共同合計/本人集計の計算根拠・非適用/欠測理由を残す。FORMの共用先も追えるようにする。

## 8. 取得前の確認と、結果ごとの読み方

設計段階では、材料・算術・未使用性・順序・ID・予定した依存関係・出力schemaと、正しい承認、誤対案への保留／誤承認、不要保留、誤参照を合成回答で点検した。次の実装段階では、同じ案へのCOUNTER、本人誤保存からの回復、親欠測・非適用、目安の未確定上下限も、実際の保存・再集計経路へ接続して確認する。実モデルの成功予測を、この合成点検の成功率から導かない。

実測後は、不成立/未確定の全応答と親資料、誤合意全経路、J成立経路から `CR01-review|2026092902|経路ID` のSHA256昇順最大6経路、人工診断12件を非盲検で読解する。主ラベルを裁量で差し替えない。

| 観測 | 報告する結論 |
|---|---|
| 本体・診断とも到達 | この固定材料で、本人判断を保つ一往復の合意・保留が機能した |
| 誤COUNTERを再確認がHOLD | 終点の防御は機能。最初の不備と共同完遂の未達は残す |
| 二人で誤案を承認 | 相互確認だけでは誤合意を防げなかった |
