# CROSS-MODEL-E1-01：不成立を記録しながら継続する本番方針

2026-09-24。ユーザーの希望は「Colabを放置しても、不成立のたびに人間を待たず進める」こと。**回答の不成立は実験全体の停止理由にしない。**

## 現状と説明の訂正

スモークv0.4は既にこの挙動になっている。REWRITE・BのMERGEで現在参照の不備が出た後も、REWRITE・AのMERGEと、A/Bの独立したPROBE計4応答を生成して終了した。飛ばしたのは、不適合ノートに依存するREWRITE・BのPROBE1件だけ。直前の「規則どおり停止」という説明は、この1件の未実行を指しており、Colab全体の停止と紛らわしかった。

## 継続規則

| 発生したこと | 記録と後続の扱い | 独立した次の実験 |
| --- | --- | --- |
| 内容・出典の正しさで不成立だが、保存契約は通る | 不成立を記録し、誤りを含む実ノートをそのまま後続へ渡す | 続行 |
| JSON構造・現在参照の検査で不成立 | 生回答と理由を残す。保存ノートを作らず、そのノートを必要とする後続だけ依存欠測にする | 続行 |
| 応答が生成長上限に到達 | 生回答と打切りを保存。未確定として扱い、当該ノートからの後続は依存欠測 | 続行 |
| PROBEで不成立 | 回答・採点・理由を残してその予定枠を閉じる | 続行 |
| 正常に生成・記録を続けられない実行例外、保存不全・hash不一致 | 回答の不成立と分けて原因を記録し、回収可能なZIPを出して終了 | 復帰手順で扱う |
| 事前に固定した全体の時間・要求上限に到達 | 到達点と未実行枠を記録し、ZIPを出して予定どおり終了 | 上限を超えない |

**不合格を合格へ直したり、合格するまで再生成したりはしない。** 欠測を記録することも、その予定枠の処理完了に含める。未実行・依存欠測・回答済み不成立を同じ数へ潰さない。

## 放置運転に向けて変更する設計

旧案の「最大90分の窓×8、窓の再開は手動」は、本番の進行を人間待ちにする。次の本番実装では、各窓を**定期保存・集計の区切り**とし、全体上限内なら同じセルの処理を自動継続する。モデルを区切りごとに再ロードする必要もない。

途中結果は応答ごとに保存し、定期的なZIP作成後も次の未処理枠へ進む。最後は集計とZIPダウンロードまで自動で実施する。Drive接続は行わない。途中ZIPはColab内なので、ランタイムが破棄されると未ダウンロード分は失われる。中断後は回収済みZIPを戻し、完了済み応答を照合して未処理の独立枠から再開する本番手順を用意する。

この方針は本番の実行管理の設計。小試行の成立条件・旧成績・凍結した指示・採点は変更しない。本番1,536生成の実行コード、ZIPからの実復帰、定期保存と自動継続はこれから実装・点検する。約13時間規模の見積りを踏まえた全体時間上限は、本番前に具体化する。

## 確認済みの範囲

実際の不適合回答をfixtureとして、既存コントローラに合成2材料・16予定枠を与えた。最初の材料の1件を現在参照不適合にした状態でも、依存する子1件だけが欠測となり、次の独立材料8応答をすべて処理。合計15合成応答＋1依存欠測で16枠を完了し、再読出しでは追加生成0だった。GPU・実モデルは使っていない。
