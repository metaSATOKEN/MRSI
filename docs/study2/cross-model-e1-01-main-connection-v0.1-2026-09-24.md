# CROSS-MODEL-E1-01 — 本番2分割の1セルコード

2026-09-24 / 接続準備v0.1。ローカルでは模擬応答で確認し、実モデルのロード・生成は行っていない。

## 実行するファイル

[Readable code and current instructions](../../experiments/XM01/generation/README.md) の**全文**をColabの1セルへ貼る。前回のスモーク用セルは使わない。

先頭の設定だけ変更する。

```python
PART = 1         # 前半は1、後半は2
RUN_MAIN = True  # 配布時はFalse。実行時にTrueへ
RESUME_ZIP = ""  # 初回・別PARTの開始は空欄
```

1. ColabでA100 80GB以上のGPUランタイムを選ぶ。
2. 前半は `PART=1` にして実行。環境準備から生成・採点・保存・ZIPダウンロードまで自動で進む。
3. 終了時の `npp-xm01-main-part1-…zip` をダウンロードして保管する。ブラウザが自動DLを止めた場合は、Colab左側のファイル欄で `/content` の該当ZIPを取得する。
4. 後半は、新しいランタイムで同じセルを `PART=2` にして実行する。**PART1のZIP・保存ノートは不要。** 両PARTを同時に同じGPUで走らせない。
5. `part1` と `part2` の終了ZIPを返送する。こちらで原回答・保存物・次入力を照合し、合算する。

各回は32材料×両方式×2役×2工程×3反復＝**768予定応答**。実際に生成されなかった依存欠測等も、予定数から落とさず報告する。生成時間は各約6.4〜6.7時間というスモーク由来の参考値で、準備・保存等は別。各回の時間上限は準備を含め累計8時間、モデル処理終了・記録用に最後の90秒を確保する。終了ZIPの圧縮・ブラウザへの転送はその後に完了する。

## 進行と保存

- JSON不備、出典不適合、内容不成立、生成長上限を記録して次の独立した応答へ進む。合格するまでの再生成はしない。
- 保存契約を通ったノートは、内容が誤っていても実物を後続へ渡す。契約を通らない親に依存する後続だけを欠測にする。
- 応答ごとに `/content/npp_xm01_runs/xm01-main-v01-part1` または `part2` へ保存する。
- 64応答の処理ごと、または直前保存から30分経過後の応答終了時に、`/content/npp_xm01_checkpoints/` 内へmanifest付きZIPを作る。ここでは人間待ちやモデル再ロードを挟まない。
- 内容不成立と実行障害は別。GPU/ロード例外・保存不全・証拠不一致では記録を残して停止する。通常の中断ボタンで停止した場合も、終了処理が動けば終了ZIPを出力する。
- Driveの接続・同期・認証は行わない。ランタイム自体が破棄されると、未回収のデータは失われる。定期ZIPもColab内の一時保存である。

## 同じPARTを中断後に再開するとき

同じランタイムの保存物が残っているなら、同じ `PART`・`RESUME_ZIP=""` で再実行する。保存済みを先に照合し、完了応答を再生成しない。768予定応答が処理済みなら、モデルをロードせずZIPだけ返す。

新しいランタイムへ移す場合は、**直前に停止した実行の最新の終了ZIP**を使う。

```python
PART = 1               # ZIPと同じ番号
RUN_MAIN = True
RESUME_ZIP = "UPLOAD"  # 実行開始時に、そのZIPを1個選択する
```

開始直後にファイル選択が1回ある。その後は残りを自動で進める。Colabの `/content` に手動アップロード済みなら、そのZIPの絶対パスでもよい。ローカル保存先が既にある場合はZIPを上書き復元しない。

材料・指示・採点コード・実行コード・割付・ID・seed・親保存物・モデル設定を照合する。同じPARTの再開では保存済み環境も照合し、Python／ライブラリ／GPU等が違えば停止して報告する。PART間の環境はそれぞれ記録し、合算時に差異を表示する。

生成開始だけが残った応答は `INTERRUPTED_UNCERTAIN` として閉じ、自動再生成しない。停止までに消費した時間は引き継ぎ、再開しても8時間をリセットしない。ロックが残った場合の `RECOVER_INTERRUPTED_RUN=True` は、前の処理が停止済みであることを確認したときだけ使う。

**運転中のcheckpoint ZIPからは自動復帰しない。** そのZIPの後に処理が続いていた可能性があり、二重生成や使用時間の過小計上を防ぐためである。ハード切断で終了記録がない場合は残り時間を保守的に全額計上する。checkpointしか残らない場合は、そのZIPを診断用として返送する。別のRUN_IDで最初からやり直す機能は設けていない。別ランタイムへ古いZIPを持ち込んだこと自体は検出し切れないため、必ず最新の終了ZIPを使う。
