# CU01：Colab一セル版の使い方と接続準備

2026-09-26。承認済みの[設計案](../../experiments/CU01/docs/customer-update-01-plan-v0.1-2026-09-26.md)に沿い、材料・指示・採点・実行コードを固定した。**全文を一つのセルへ貼って実行できる。Drive接続、設定の手編集、過去ZIPのアップロードは不要。**

## 使い方

1. [Readable code and current instructions](../../experiments/CU01/generation/README.md)を開き、全文をコピーする。
2. ColabのGPUランタイム（A100 80GBまたはRTX PRO 6000 Blackwell級）のコードセル一つへ貼り、そのまま実行する。
3. 終了時に自動ダウンロードされる **`npp-cu01-result-日時-ID.zip`** を保管して返送する。

自動ダウンロードがブラウザに止められた場合は、Colab左のファイル欄から `/content/npp-cu01-result-*.zip` を回収する。ランタイムを破棄する前にZIPを確保する。

同じランタイムで再クリックした場合は、新しい回答を生成せず、保存記録の再照合とZIP再返却だけを行う。途中停止した実験の生成再開機能は置いていない。実行ロックが残る場合は重複実行を防いで記録を返す。

## 実装で固定したこと

希望の同異×変更対象A/B×対象の初期犬猫を全8ケースにした。共同案内は紙／デジタルを各4ケース、担当客の版が高い人物もA/Bを各4ケースにした。更新対象の新しい担当客版が相手より低い場合も4ケースあり、人物間の版の大小では更新を決められない。

初期ノートは新たな合成資料であり、SX02の保存物を後付け修正したものではない。担当客のsubject・animal・origin_idに専用revisionを追加した。新しい通知は対象の初期版＋1と新しい元IDを持ち、古い通知は対象の初期行をそのまま再送する。

**担当客の四欄を正解に上書きする処理は入れていない。** schemaはsubjectのA/Bを両方許し、誤った人物を保存した場合も、構造不備ではなく意味不一致として数える。共同観測は実入力の三行から人物別に最新版を選び、共同A/Bと本人観測へ行ごと複製する。担当客通知はその候補一覧へ入らない。

READの指示・schema・案内計算は前回から同一。実回答の犬猫と四値を使い、正解や初期ノートによる差し替えをしない。原文、限定したJSON外装処理、原案、転記元と保存ノート、実際の次入力、抽出値と計算結果を保存する。
