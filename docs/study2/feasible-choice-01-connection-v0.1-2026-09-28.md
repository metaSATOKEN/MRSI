# FC01：Colab一セル版の準備報告

2026-09-28。[承認済み設計](../../experiments/FC01/docs/feasible-choice-01-plan-v0.1-2026-09-28.md)を実装した。**下のPython全文をColabの一セルへ貼れば実行できる。** Drive接続、設定編集、過去ZIPの手動アップロードは不要。

## 使い方

1. [Readable code and current instructions](../../experiments/FC01/generation/README.md)を開き、全文をコピーする。
2. ColabでA100 80GBまたはRTX PRO 6000 Blackwell級のGPUランタイムを選び、一つのセルへ貼って実行する。
3. 終了時に自動ダウンロードされる `npp-fc01-result-日時-ID.zip` を保管して、このチャットへ返す。自動DLが始まらない場合は、Colab左のファイル欄から同名ZIPをダウンロードする。

**最大256回答、準備込み90分上限。** 提案64→相手確認64→二役の後続利用128からなる64経路を、一つずつ進める。各経路は4回答で、二経路終了ごとに途中ZIPも保存する。

誤答・誤参照・不適切な配分・未合意でも記録を残して進む。構造不備や候補IDの結付け不能は、その回答に依存する後続だけを欠測とする。OOM・モデル例外・時間上限では停止してログを回収する。自動再生成は行わない。

## 実装した比較

EU01の全32共通出発条件を使い、両方式へ同じ実行可能な二候補を提示する。本人の推奨と根拠参照は、両方式ともモデルが答える。

| 方式 | 共同提案 | 後続への受渡し |
|---|---|---|
| DIRECT | A/Bの割付を直接書く | 実回答をそのまま渡す |
| SELECT | X/Yの候補IDを答える | 指定された候補の割付だけを複製して渡す |

SELECTの複製器は正解の計算や選び直しをしない。非最適な候補を選んだ場合も、その候補が後続へ届く。候補IDの大小文字や綴りを直す処理も加えていない。UNDECIDEDは共同保留の割付へ変換し、明示的な非選択として記録する。

原回答は `answer.txt` と `saved-answer.json`、受渡し用の回答は `carry-answer.json` に分ける。候補表のhash、指定ID、複製元の位置、変換前後のhashを `candidate-binding.json` に記録し、次入力には親のhashを結び付ける。本人欄と参照IDは修正しない。

確認・後続利用の指示とschema、合意・最適性・本人判断・参照・利用の採点規則は、封印したEU01コードから継承した。候補表・候補ID・方式名・検査の合否は後続のモデル入力へ加えない。

主比較Pは「本人判断と根拠を保った適切提案」の32条件中の成立数。候補選択O、本人判断L、参照Zを成分として残し、下流の合意C、利用H、全工程J、二条件両立Qと分けて報告する。元の本人更新と相手保持の保護条件、予定分母、欠測上下限、進行目安を固定した。
