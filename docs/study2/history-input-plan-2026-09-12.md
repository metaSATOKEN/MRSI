# HISTORY-INPUT-01：今生成できる応答で履歴介入の傾向を測る

2026-09-12、v0.2。**犬派／猫派を含む改訂案。モデル発行は未実施。** ユーザーの「架空場面に、犬派か猫派かっての入れて欲しいw」を反映。旧v0.1の材料・指示・カード・未実行の準備runは保持し、新しい版で入力を固定し直す。

## 目的

同じ新しい出来事を説明するLLMに、過去の説明を渡す／渡さない／別の説明へ入れ替えると、説明の焦点がどの程度変わるかを測る。データはこの実験のモデル応答として現在生成できる。将来の実イベントや、人間の持続的communityを取得できることを開始条件にしない。

最初は**研究者が作った共有記録を割り当てる入力介入**に限定する。8場面は独立に発生した8つの社会集団ではない。LLM自身が交流して履歴を形成する過程、H/S/Oの分離、未来予測損失としてのNPPは次段階。今回は「同じ事象で入力履歴だけを変えたときの説明フレームの差」が結果になる。

## 比較する3条件

| 条件 | 入力 |
| --- | --- |
| KEEP | 現在の出来事＋元の過去記録 |
| DROP | 同じ現在の出来事。過去記録欄を省く |
| SWAP | 同じ現在の出来事＋別の説明を重視する過去記録 |

SWAPは同一場面・同じ過去の事実・同じ登場役を保ち、解釈の焦点だけを変更した**反実仮想の割当記録**。実在する別集団の記録とは呼ばない。KEEP/SWAPの文字数差は長い方の10%以下を要求し、文章の数も同じにする。トークン数が厳密に同じとは主張しない。DROPとの比較には入力長や記録の存在自体の影響も含まれる。

KEEP−DROPを履歴追加の全体効果、KEEP−SWAPを履歴内容への感応性として併記する。いずれも自発的な集団記憶の証明や、人間NPPの因果説明にしない。

## 材料と発行数

- 固定材料 (see the evidence index)：架空の図書館、工作会、盤上ゲーム会など8場面すべてに犬・猫のマスコットやキャラクターを入れる。現在の出来事は複数の説明が可能な観察事実だけにする。
- 説明軸は「参加者の好み・意向 P」と「配置・案内・運営等の場の条件 C」。元履歴の焦点はP/C各4場面。人間AIニュース用F1〜F5をそのまま移植しない。
- 元履歴の焦点P/C×過去に人気だった犬/猫×犬猫の提示順を2×2×2の8通りに配分する。現在の観測で人気の犬猫も4場面ずつ。場面内容そのものまで同一ではないため、提示順や犬猫だけの因果効果を独立に推定したとはしない。3条件内の事象・選択肢・提示順は同一。
- KEEP/SWAPで「どちらが人気だったか」という過去の事実は共通にし、理由づけだけを変える。最初から犬派／猫派と決まった人格を与えない。
- **8場面×3条件×2回＝48応答**。各応答は新しいGPT-5.6 Luna、mediumのサブエージェントで生成する案。会話継承なし、前史は当該packetの入力だけ。使い回し・条件間でのメッセージ共有なし。
- 別の新しい採点セッションを、各場面についてGPT-5.6 Sol／Luna各1回、計16回。各採点者は匿名化・順序無作為化した6応答を全件判定する。**合計64セッションで終了**。
- 採点者は現在事象と応答とルーブリックだけを見る。履歴本文・条件名・元履歴の焦点・他の採点・研究仮説は渡さない。出力から履歴の存在等を推測できる可能性は残る。
- 生成指示：response (see the evidence index)。採点指示：judge (see the evidence index)。本会話やThroughline、HN原文・プロフィールは実験入力に含めない。

モデル・reasoning指定と利用枠の消費は実行ツールに従って記録する。[公式サブエージェント資料](https://learn.chatgpt.com/docs/agent-configuration/subagents)でもモデル指定・設定継承・利用量増加を確認した。会話継承なしはこの環境のspawnツールで`fork_turns="none"`を指定する。共通のシステム指示やツール権限まで消えるとは置かず、厳密な隔離実験環境とは区別する。

## 出す傾向値

主ラベルは `P / C / MIXED / OTHER / UNSCORABLE`。元履歴の焦点と同じラベルが**主な説明**なら1、それ以外の採点可能ラベルなら0。MIXEDを都合よく1へ含めない。UNSCORABLE・欠損・構造不正はunknown。

主採点者をSol、Lunaを感度点検とし、採点者別に計算する。多数決を正解としない。

1. 各条件の元履歴フレーム採用率。各場面で2応答を平均してから8場面を等重みに平均する。
2. 場面ごとの対応差 `d_drop = rate(KEEP) − rate(DROP)` と `d_swap = rate(KEEP) − rate(SWAP)`。全8場面の差と平均差をポイントで表示する。
3. P/C別の結果、別履歴側へ移った割合、MIXED/OTHERの割合、採点者間の不一致、引用不一致、無効・欠損数。

補助として、生成応答に**担当者として次回のマスコットを選ぶなら犬派か猫派か**の`preference`欄を追加する。DOG / CAT / BOTH（どちらも）/ UNDECIDED（今は選ばない）の4択とし、どちらかへ強制しない。説明文は今回の参加者の行動、preferenceは担当者としての次回の選択で、対象を区別する。これは役割上の選択の自己申告であり、モデル固有の本当の好みを測ったとはしない。

選択は条件別件数・率と場面ごとの対応差を別集計する。BOTHとUNDECIDEDは有効な別カテゴリーで、欠損でも犬猫への半票でもない。不正なpreferenceは補助結果のunknownとし、有効な説明フレームを無効化しない。逆に説明が形式不正でも、選択欄が有効なら補助結果に残す。条件漏洩等の実行違反は両方unknown。予定分母16応答／条件でunknownの上下限を出す。**採点者にはpreference欄を提示せず、説明だけを採点**させる。犬猫の選択率を主効果へ置き換えない。

合計48応答・96採点を独立Nと呼ばない。設計上のまとまりは8場面、同じテンプレートを使う依存もある。2反復や採点者追加は測定の反復で、独立した社会集団・出来事の追加ではない。

主試験ではないためp値・検出力達成・確認的95%区間を出さず、8場面すべての効果と範囲、中央値、平均を示す。unknownは予定分母へ残し、0/1を両方当てた上下限を出す。条件差の下限はKEEP下限−対照上限、上限はKEEP上限−対照下限。有効例だけで分母を縮めた単一点を主結果にしない。

符号は先に保証しない。差が小さい、逆向き、場面で異なる、採点者で割れる結果も同じ形式で出す。有意になるまでの追加、結果を見た履歴の書換え、都合のよい場面の除外はしない。

## 上限・停止・保存

- 生成48＋採点16を上限とし、モデルの代替・修復再発行・追加標本0。Codex利用枠を消費するが、直接の課金APIや有料データ取得は0。
- 初回発行から60分で新規発行を停止。実行中の処理は最長15分の終了猶予を置き、未完了は中断・欠損として保存する。これは上限であり終了時刻の予測ではない。
- 実験サブエージェントの同時数は最大3。参照先は割当packetだけ。外部検索・他packet閲覧・他エージェントとの会話を禁止し、違反が記録された場合は条件漏洩として扱う。
- 結果を返すだけの新しいセッションを基本にし、主タスク側で逐語保存。ツール使用／出力を追跡できる範囲を記録する。環境から監査不能なら「隔離を完全確認」とはしない。
- 実行前に材料・指示・schema・解析と予定48 ID／16採点IDを固定する。全生成を保存・hash固定した後に採点packetを作り、採点終了前に条件別の成績を見ない。
- 採点packetは小さく保ち、6件すべてのID集合・重複・全件完了を機械照合。引用が応答の連続部分文字列であることも照合する。引用の一致だけを意味の正しさにしない。
- 不正応答・範囲外のツール参照・全件未完了を元記録に残し、unknownで扱う。明らかな条件漏洩・保存障害なら新規発行を停止する。
- 新しい`study2/runs/`配下へ入力・出力・割当・発行履歴・監査・集計を保存。個別出力はrestricted、保持期限は2026-10-12 17:41:23 JST。合成の材料・プロトコル・個人情報を含まない集計は研究記録として保持する。実SNSの原文やBARログは使わない。

## 実行準備と確認

材料・プロンプトに加え、packet準備・採点パーサ・集計器 (see the evidence index)と合成点検 (see the evidence index)を実装した。v0.2の合成点検は10件で、48応答→16採点packet→集計の接続、unknownの予定分母、欠損・重複・別ID、引用不一致、履歴の条件間混入防止、犬猫の配置、説明と選択の独立した形式判定、採点packetへの選択欄非提示を点検する。架空のテスト出力を使った検査であり、LLMで効果を観測した結果ではない。

`prepare`は材料・コード・テスト・カードをコピーしてhash固定し、48個の匿名packetと非公開の割当を作る。モデルやネットワークを呼ぶ機能は持たない。採点準備にはexecution／generation-closed、集計にはratings-closedの記録を要求する。実発行はユーザーのバッチGOをexecutionへ記録した後、新規の実験サブエージェントで行う。予定IDと発行実績・ツール参照・終了状態の照合は運転時にも必要で、準備済みを実測済みにしない。
