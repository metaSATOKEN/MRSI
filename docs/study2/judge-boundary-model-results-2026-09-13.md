# JUDGE-BOUNDARY-01 — 初回実測は受信容量で未成立

2026-09-13。**INCONCLUSIVE**。Solへの最初の要求は送信されたが、原SSEの受信サイズが専用送信器の上限を超え、完了前に停止した。固定ルールに従ってLunaは未発行。受理評価0／予定32、全32意味レビューは未実施。分類基準に適合したかは評価できない。

## 実測と原因

ユーザーのGO後、準備封印66ファイルと外部仕様5ファイルを照合。固定16例・期待・新judge v0.2を変更せず、両モデルの要求を先に凍結した。Solは11,815 bytes、Lunaは11,816 bytesで、差はmodel名の長さだけ。両方の入力gateは事前PASS、同一の採点packetを保持していた。

実際に発行した推論用CLIはSolの1起動、外向きモデル要求1、再送0。起動から約36.085秒、controllerの閉鎖まで約36.437秒。モデルが処理を継続・完了したかは通信切断後には確認できず、使用トークンは不明。0とは数えない。

| 保存された観測 | 値 |
|---|---:|
| 原SSEの受理上限 | 262,144 bytes（256 KiB） |
| 保存された途中SSE | 264,112 bytes |
| 超過分 | 1,968 bytes |
| 完全に読めたSSEイベント | 984 |
| うち本文deltaイベント | 978 |
| 途中本文のUTF-8量 | 3,527 bytes（1,411文字） |
| response.completed / output_text.done | いずれも0 |

原SSEには細かい本文断片ごとにイベント名・ID等が付く。今回は本文だけでなく、その包みを含むサイズで上限に達した。送信器の固定コードは、最大8,192 bytesを追加読取した後に受信総量が256 KiBを超えたらValueErrorで停止する。保存量が上限を1,968 bytes超えるのは、この読取単位による。全プロセスが約36秒で終わっているため、同じ分岐にある120秒の読取時間上限ではない。

HTTPステータスと最終ヘッダーを保存する処理は受信ループ終了後に置かれており、今回は到達していない。上流のHTTPステータスは記録なし。CLIが表示した403は、localhostの門番がSEND_UNCERTAINを返したもので、提供元の403を観測したわけではない。

## 停止と評価の扱い

予定・実送信・SQLiteの要求bytesは一致し、実行時の入力gateもPASS。SQLiteの状態はSEND_UNCERTAIN、send_invoked=true、TRANSPORT_RAISED。途中の原SSEはファイルに保存されたが、完全応答としてのSQLite responseはNULLで、出力gateには進んでいない。CLIに研究本文は返さず、既知の起動通知と失敗通知だけを記録した。

受信したitemにはreasoning／messageだけが見られ、操作要求や操作完了は観測されなかった。ただし完了を取得していないため、応答全体の内容については評価しない。途中のラベルや根拠を抜き出して期待と比較することもしない。

Solの16評価は応答未受理、Lunaの16評価は未発行として、全32予定行の状態を保存した。採点形式や意味基準のFAILには分類せず、観測未成立のINCONCLUSIVEとする。固定した2要求のうち、残るLunaを発行して見えた票だけで成功を判定しない。

## 照合と限界

別スクリプトで元ファイル、SQLite、CLI、SSEイベントの型・連番・サイズを読み、**812点通過・失敗0**。この数字は停止状況と記録の整合を確認した件数で、実験が成功した件数ではない。旧実験・仕様準備・旧pointer等726ファイルの集合／hashを維持。認証header値非保存と補助的な資格情報パターン点検も通過した。

初期のlogin statusではPATH alias作成の権限警告が出たが、既存ChatGPTログインを確認でき、実要求は送信されている。今回の停止原因として扱わない。新規APIキーや直接課金APIは使っていない。

全件取得用の検算スクリプトは実測と並行して作成したが、完了条件を満たさなかったため実行せず保存した。停止用の別検算を用い、全件取得の前提を緩めて成功にしていない。新runはdir0700/file0600、保持期限2026-10-12 17:41:23 JST。旧票・旧5／6一致・本試験の未実行状態を保持する。

## 次の修正点

研究本文や16例の構成を変えず、入力上限と原SSEの上限を分離する設計を推奨する。今回確認できたのは256 KiBが不足したことだけで、完了時の必要量は未知。容量を増やしても無条件に応答を受理せず、型・ID・連番・完了・本文一致・操作拒否・二重発行拒否は維持する。
