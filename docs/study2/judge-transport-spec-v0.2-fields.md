2026-09-13。事前カード (see the evidence index)、提示指示v0.3 (see the evidence index)、受理器v2 (see the evidence index)。旧ラベル定義と分類手順を保持し、理由の記録条件と保存形式を別版にする。旧dispatcher／本試験へは未配備。

## モデルが返す欄と保存する欄

入力は従来のinstruction/current_event/items。itemはid/explanationだけで、正解・実験条件・他票を追加しない。ラベルはBEGIN_LABELSとEND_LABELSで囲み、従来どおり`i001 P`等を全ID各1回返す。根拠はBEGIN_EVIDENCEとEND_EVIDENCEで囲み、ID単独行に続けて以下の8欄を各1回返す。

| 出力欄 | 保存先 | 記入条件 |
| --- | --- | --- |
| Q | quote | 原説明内の連続引用。必要なら全文 |
| R_ADOPTION | reasons.adoption | 現在の採用／未選択とラベルの根拠 |
| ALT_STATUS | reasons.alternative.status | 他の説明・候補・見解があればAPPLIES、なければNOT_APPLICABLE |
| R_ALTERNATIVE | reasons.alternative.reason | 他方が採用・同等採用・可能性・否定・撤回のどれか。非該当なら何が本文にないか |
| UNC_STATUS | reasons.uncertainty.status | 原因や因果的な優勢の確実性への留保があればAPPLIES、なければNOT_APPLICABLE |
| R_UNCERTAINTY | reasons.uncertainty.reason | 留保と現在の採用の関係。非該当なら何が本文にないか |
| CHANGE_STATUS | reasons.change.status | 明示的な撤回・変更・新しい選択の経緯があればAPPLIES、なければNOT_APPLICABLE |
| R_CHANGE | reasons.change.reason | 何から何へ変わり、現在何が残るか。非該当なら何が本文にないか |

欄名で対応付ける。出力順が変わっても欄の意味は変わらず、重複・未知・欠欄は拒否する。コロン直後は半角スペース1個。本文は1物理行だが複数文可。JSONとしてのエスケープは不要。Qと4つの理由は別の役割で、全文引用や他欄の説明だけで理由欄を省略しない。保存時に単一のreasonへ結合する互換処理を設けない。

## 全例に共通する意味レビュー条件

以下はモデルの自己申告ではなく、原説明・Q・各理由を読むレビューで点検する条件。適用条件は組5／組6などのfixture名に依存させない。本文に該当する論点が複数あれば全部の説明を必要とする。

1. 現在の採用：主説明とラベルを具体的に説明する。MIXEDは両方の同等採用、OTHERは未選択・撤回後の未採用またはP/C以外の主説明を記録する。単なる候補列挙を同等採用にしない。
2. 他方の説明：現在の主説明以外の候補・見解が本文にあれば、その採用／留保／否定／撤回を区別する。両方採用なら同等か主従があるかを記録する。本文にない場合はNOT_APPLICABLE＋その不在を説明する。
3. 確実性：本文に原因や主因の確実性への留保があれば、採用を取り消すのか、事実上の確信度と採用を別にしているのかを説明する。単に他方が可能性と書くだけでは、この欄の説明を代用しない。変更の有無にかかわらず適用する。
4. 変更：撤回・変更があれば以前と現在を説明する。未選択→採用、採用→未選択、別説明への変更を同じ条件で扱う。確実性も同居すれば双方の欄を記録する。
5. 非該当：本文に論点がないことと、その説明が対応しているかを点検する。NOT_APPLICABLEと非空理由があるだけでは正しいと認定しない。

逐語一致ではなく意味を採点する。許容例：「原因の不確実性は留保にとどまる」は、採用内容と対応していれば撤回ではないという説明になり得る。不足例：「希望を採用し、配置は可能性」は、不確実性と採用の関係自体を説明していない。同等採用という記述から未選択ではないことが分かる場合、否定文の復唱は求めない。曖昧で裁定できなければ懸念を残し、機械的充足へ押し込まない。

UNSCORABLEはQのみ空を許す。4理由に分類不能／論点を評価できない具体的事情を書き、三つのSTATUSはNOT_APPLICABLEにする。解析上のanalysis_label=nullは欠損フレームを明示する内部値であり、今回禁止する理由欄のNULLとは別。無理にP/Cを記入させない。

## 欠欄と診断

4理由はいずれも必須。空、空白のみ、NULL／None／N/A／未記入／裸のNOT_APPLICABLE等を拒否する。検出対象の有限集合は受理器のPLACEHOLDERSに明記。検出時のみNFKC、空白／不可視書式文字除外、casefoldを使い、保存する原文・受理した文章には適用しない。特定の文字数や意味語を必須化せず、任意の無意味な文章を自動検出できるとは主張しない。

欠欄・不正が1つでもあればLABELS_ONLY、研究用accepted_ratingsは空。ID、欄名、MISSING_FIELD／EMPTY_NULL_OR_INVALID_REASON等のコードと記入要求文を返す。複数IDの不足はまとめて通知する。例：`i001 / R_CHANGE: EMPTY_NULL_OR_INVALID_REASON`。非空のSTATUS欄だけで理由欄を代用しない。

原出力・入力・判定・hashを先に保存し、封印と再計算一致のあるreceiptだけを読み出す。エラーの診断文も保存する。診断をLLMへ送る処理や自動再提出は持たない。再提出する実験を行う場合は、元失敗を残し、新ID・上限・初回と修正版の集計区別を別途固定する。

## 局所成立の限界

ACCEPTED_COMPLETEは欄・引用・ID・完了・保存の成立。内容の正しさや実モデルが全欄を埋めることの保証ではない。虚偽のNOT_APPLICABLEや無関係な非空理由が通る合成負対照を保存する。

v0.3の入力本文はv0.2より長く、返答欄も増える。実モデルの応答量・容量・時間・理由改善は未測定。原SSE／復元本文の上限を変更せず、旧の不合格票を新仕様で補修・再集計しない。
