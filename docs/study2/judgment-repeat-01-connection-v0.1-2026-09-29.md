# JUDGMENT-REPEAT-01 — Colab一セル版の使い方と接続準備

2026-09-29。承認済み[設計](../../experiments/JR01/docs/judgment-repeat-01-plan-v0.1-2026-09-29.md)に沿って、[Readable code and current instructions](../../experiments/JR01/generation/README.md)を作成した。旧ST02の本人形成32入力と共同確認48入力を、新しい三seedで反復する。通常・最大240回答、見積もり25分前後、準備込み45分上限。実モデルはユーザーのColabで実行する。

## 使い方

1. ColabでA100 80GB、またはRTX PRO 6000 Blackwell級のGPUランタイムを使う。
2. [Readable code and current instructions](../../experiments/JR01/generation/README.md)の**全文**を一つのコードセルへコピーして実行する。設定の編集、前回ZIPのアップロード、Drive接続は不要。
3. 終了時に自動ダウンロードされる `npp-jr01-result-日時-ID.zip` を保管して、このスレへ返す。

自動ダウンロードが始まらなかった場合は、Colab左のファイル欄にある `/content/npp-jr01-result-*.zip` を取得する。40回答ごとの途中ZIPは `/content/npp_jr01_runs/` に保存される。途中停止した場合も、終了ZIPをそのまま返す。

**同じランタイムでの再クリックは追加生成を行わず、既存記録を照合してZIPを返す。** 実行中ロックが残る場合は二重実行を止め、そのログを回収する。ランタイムを削除すると未回収の一時記録も失われるので、ZIP取得を確認してから終了する。新しいランタイムでの再実行は別実行になるため、結果が悪かったことを理由に繰り返さない。

## 不成立・停止と集計

本人判断の不適合やJSON不備は、そのまま保存して残りの固定入力へ進む。今回の共同確認の親は保存済みなので、新しいFORMが不成立でもCONFIRMを依存欠測にしない。既知の完全JSON外装だけ正規化し、未知キーの削除・値の補完・意味修正は行わない。

実行継続不能な例外、入力の不一致、時間上限では記録を回収し、未実行分も240予定回答に残す。回答の途切れ・構造不備と、読めた答案の内容不適合を分ける。原文のない場所を合成fixtureで補填しない。

- FORM：本人の選択と本人参照Fを反復ごとに16対応で比較し、差の平均・範囲と各固定入力の0/3〜3/3を示す。
- CONFIRM：共同応答と参照C、本人判断と参照B、双方Vを別々に表示する。行為がCOUNTERとHOLDの間で変わっても、両方適切なら成否の変動と分ける。
- 各固定入力：三回適合／三回不適合／成否混在／未確定あり。未確定があっても既知の成否混在を消さない。
- 合意：この一確認でのK0/G0と誤承認を表示する。対案再確認・後続利用を含む全工程I/Jは計算しない。
- 欠測：固定分母と0/1補完の上下限を表示する。p値・母集団CI、旧回答を足した四反復の集計は行わない。

原文点検対象も固定規則で選び、実行直後の報告は `PENDING_OFFLINE_REVIEW` のままにする。返送後、原文と固定親を読んだ記録を別に追加する。この一巡の照合後は、安定・混在・欠測のどの結果でも第三報へ進む。
