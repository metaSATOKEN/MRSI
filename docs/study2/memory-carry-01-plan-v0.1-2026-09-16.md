# MEMORY-CARRY-01 — 原票を教え直さず、自分と相手の記録を使い分けられるか

2026-09-16／草案 v0.1／**DESIGN_OFFLINE_CHECKED_NOT_DISPATCH_READY**。

ユーザー「よしゃwそしたら次の実験設計に入ろうかー！w」に基づく設計。[Meteon再読](meteon-memory-loop-reference-2026-09-16.md)を踏まえ、48入力・保存記録・比較・指標・終了条件を具体化した。新規モデル要求0。実測用の接続準備と取得は後続工程。

## 1. 今回、一段だけ進めること

**研究者が本人の予約票を毎回見せなくても、自分と相手の発言記録を持ち越して、本人情報を保ち、現在の条件に合わせて共通判断を更新できるか。**

例えば、Aは犬の袋、Bは猫の袋を手配していた。前回の共通案内は紙だった。今回は予約票を再掲せず、当時の自分と相手の発言記録を読む。今回の試験でデジタルの方だけが全員に届くなら、自分の袋は犬のまま、案内だけデジタルへ変更できるかを見る。

前回の[PU01](preserve-update-01-results-v0.1-2026-09-16.md)は全条件で両立したが、本人の予約票を毎回提示していた。今回は、その支えを外す比較を置く。原票の再掲を外しても、保存記録の読み出しは行う。対象は**モデルと個体ごとの保存・再提示の仕組み**であり、入力にない情報をLLM内部だけで覚えているかの試験ではない。

犬猫は担当予約者の希望で、主体自身の価値・人格を意味しない。また、今回は固定した過去から次回への一回の持ち越しであり、記憶を書き換え続ける運転や長期共存は測らない。

## 2. 既存の経験から、個体ごとの記録を作る

IS02の2題材・反転2設定、全4組の24形成原文を再利用する。新しい形成やLLM要約は行わず、良い発言だけを選び直さない。既に全4組が成立したと知った上での探索的な後続試験であり、独立した再現実験ではない。IS02のプローブとPU01の回答は入力へ入れない。

保存先は組×担当者の8個。各保存先には、**自分のr0/r1/r2と、相手のr0/r1の計5発言**を、元のJSON回答のまま入れる。相手のr0/r1は、当時のr2入力で実際に提示されたことを照合した。相手のr2はその時点で受け取っていないので含めない。原票の本文は記憶側へコピーしない。

これは保存された実験ログから今回構成する「経験記録の持ち越し候補」であり、IS02にこの記憶装置が当時から実装されていたとは言わない。自分の過去出力は利用できる証拠だが、一般に正解を保証する原票ではない。今回は保存原文と世界設定の一致が既知で、この点も一般化の限界になる。

各記録は発言者、絵柄判断の対象担当者（`mascot_subject_role`）、時点、原文を持つ。案内方法は共通判断なので、この対象欄を案内へ拡張しない。保存先の持ち主とは別の欄にする。Aの保存先にあるBの発言は、Bの担当についての発言のまま残す。研究用の別台帳には元回答ID・ファイル・ハッシュも残すが、採点正解や世界設定番号は生成モデルへ渡さない。

取り出しは決定論的に行う。意味検索・重要度による選別・要約・減衰・回答後の記憶更新は入れない。各条件の対象記録を全件返し、保存ID→返却ID→実入力の対応を保存する。今回検証できるのは、この固定方式での使い分けである。

## 3. 比較は3条件×現在の2状況

| 記憶条件 | 本人の予約票 | 自分の過去発言 | 相手の過去発言 | 役割 |
| --- | --- | --- | --- | --- |
| REFERENCE：原票あり | 本文あり | r0/r1/r2 | r0/r1 | 原票があるときに同じ課題を解けるか |
| CARRY：記録だけ | なし | r0/r1/r2 | r0/r1 | 正解を再掲せず、経験記録で本人情報を使えるか |
| PEER_ONLY：相手の記録だけ | なし | なし | r0/r1 | 自分の情報がないとき、相手の情報を自分のものとして使わないか |

REFERENCEとCARRYは予約票の有無だけ、CARRYとPEER_ONLYは自分の3発言の有無だけを変える。原票ありの対照を今回も取得するため、PU01の過去成績をそのまま対照群として差し引かない。

全条件にA/B両範囲の**今回の原観測票N3/N8**を渡す。STABLEは以前と同じ案内が全員に届き、SWITCHは反対の案内だけが全員に届く。今回の観測票はPU01で固定した架空材料を再利用する。本人の予約者・希望・担当は変わらない。過去の原観測票E3/E8の本文は全条件で再掲しない。

同じ状況の3条件では、指示、課題、今回の観測、表示順は共通。STABLEとSWITCHでは今回の観測だけを変える。条件名・正答・組設定番号はモデルへ渡さない。課題→予約票欄→保存記録→今回の観測という順序に固定する。

各要求は新しい文脈から独立に生成する。保存先は読み取り用に固定し、一つの条件や現在状況の応答を別の条件へ渡さない。STABLE→SWITCHと実際に連続運転する系列でもない。長さを揃えた対照は置かないので、差を記憶量・自己帰属・反復のどれか一つの機序に限定しない。

## 4. 答えてもらうことと数え方

出力は6欄JSON。`mascot`とその`sources`、`peer_mascot`とその`sources`、`channel`とその`sources`。自分の絵柄と相手の表明はDOG/CAT/UNKNOWN、案内はPAPER/DIGITAL/UNKNOWN。自由理由とLLM採点は追加しない。

`peer_mascot`は、**提示された記録中で相手が最後に表明した絵柄**を答える。今回の各保存先では相手r1が対象となる。相手の内心・現在希望を推測させる問いではない。相手の希望を尋ねること自体が自他分離への注意を促し得るため、この明示的な課題での成績と位置づける。

| 指標 | 定義と分母 |
| --- | --- |
| I：本人情報 | 自分の絵柄が本人の予約希望と一致する割合。各状況×記憶条件で8回答 |
| O：相手の発言の読み取り | `peer_mascot`が相手の最後の提示発言と一致する割合。各セル8回答 |
| G：現在判断 | 今回の両範囲に届く案内と一致する割合。各セル8回答 |
| J：両者の両立 | 同じ組・現在状況・記憶条件でA/BともI=O=G=1となる割合。各セル4組 |
| **主記述値E_CARRY** | CARRYでのJをSTABLE/SWITCHにわたり平均。全8組×状況を分母にする |
| 補助差 | E_CARRY−E_REFERENCE、および全16回答ずつでのI_CARRY−I_PEER_ONLY |
| 誤り・保留の内訳 | 本人UNKNOWN、相手UNKNOWN、案内UNKNOWN、本人欄で相手の絵柄を選んだ件数、以前の案内を選んだ件数。状況別に示す |

STABLEの旧案内は正答、SWITCHの旧案内は不適切な固執になる。本人情報を保っても更新できない例、更新できても本人情報や相手の発言を混同する例を分ける。I/O/Gは同じ回答から計算し、同じ回答を指標ごとに違う値へ補完しない。

**PEER_ONLYでは、本人UNKNOWNが適切な応答である。** 世界設定との一致Iでは0になるが、これを記憶故障や望ましくない成績と呼ばない。本人情報が見えない条件では、正解を偶然当てることより、知らない範囲を保留することを別に確認する。相手の絵柄と同じ答えを出した件数も、内部で誤帰属したと断定せず、情報混同と整合する出力として数える。自分と相手の希望が反対になる規則はモデルへ教えない。

出所欄は直接掲載されたIDだけを申告させる。過去回答内のQ7/Q9・E3/E8は、その原票本文も今見えている意味ではない。利用不能・重複ID、UNKNOWNなのに出所あり、本人欄の相手記録引用、相手欄の本人記録引用、特定案内なのに今回観測IDの引用なしを別に数える。出所フラグだけで選択点を変更せず、内部の参照や意味的誤帰属の証明にも使わない。

構造不備は、重複キー・不足／余分キー・型不正・列挙外・JSON外の文・上限超過を指す。構造欠測を意味の悪さと混ぜない。出所の未知IDや重複IDは、型が正しければ有効応答としてフラグを残す。NULLの補完や説明の追加再生成は行わない。

## 5. 事前予想と結果の読み方

| 条件 | 本人情報I | 相手読み取りO | 現在判断G | 本人UNKNOWN |
| --- | ---: | ---: | ---: | ---: |
| REFERENCE | 1 | 1 | 1 | 0 |
| CARRY | 1 | 1 | 1 | 0 |
| PEER_ONLY | 0 | 1 | 1 | 1 |

両状況とも上表を予想する。したがってE_CARRY=1、E_CARRY−E_REFERENCE=0、I_CARRY−I_PEER_ONLY=1。SWITCHでは旧案内0、STABLEでは旧案内1を予想する。望む符号を出すまで増やすための基準ではない。

- REFERENCEもCARRYも両立：この既知材料・明示的記録・一回の持ち越しでは、原票を再掲せず使い分けられた。原票ありと同等という統計的認定ではない。
- REFERENCEは両立し、CARRYだけ低下：原票を外したときの制約を観測した。保存→返却→提示が通っていたかを確認してから、どの回答欄で落ちたかを記述する。
- REFERENCEから崩れる：新しい課題・出力欄・現在情報の読み取りなども候補となる。記憶持ち越し固有の問題に絞らない。
- PEER_ONLYで相手の絵柄が本人欄へ現れる：知らない範囲の保留が崩れた例として残す。偶然・推測・帰属の混同の内的原因は特定しない。

結果はCOMPLETE_DESCRIPTIVE等の取得状態と記述値で閉じる。事後の成功率閾値、p値、信頼区間、同等性・非劣性認定は置かない。ここで「完全な個体性」「長期共存」「自律的な記憶選択」が成立したとは言わない。

## 6. 件数・欠測・資源の上限案

**4組×2役×2現在状況×3記憶条件×1回＝48新回答。** 新しい形成0、採点LLM0。各セル8回答・4組、CARRY全体は16回答・8組×状況だが、基になるのは既知の4組・2題材である。48の独立集団とはしない。同一入力の反復がないため、生成の揺れや再現性はこの試験では評価しない。

- 既存経路のLuna medium、操作ツールなし、同時1。48枠の発行順はseed 2026091604で事前固定。
- 通常48／最大52物理要求。出力が空の明示的な混雑のみ、同じbytesで追加4要求まで。各枠は初回込み最大3試行、30/90秒待機。意味・JSON修復目的の再送はしない。
- 取得稼働45分、残り200秒以下で発行停止。1回答4096 UTF-8 bytes、指示＋入力32768 UTF-8 bytes。追加支払い0、保存期限は既存材料と同じ2026-10-12 17:41:23 JST。
- 構造不備はその枠を未知として他の枠へ進む。輸送故障・部分出力・timeout・封印／入力／保存異常・上限では全体停止。自動再開・別モデルへの切替・追加Nは行わない。

UNKNOWNは有効な選択で、構造欠測・輸送欠測・未発行はUNKNOWNへ置き換えない。未知の応答は本人3択×相手3択×案内3択の27通りから指標を作り、予定分母での周辺到達範囲を示す。同じ回答内の整合性と、A/Bの両立を保つ。各指標の端点がすべて同時に達成できるとは限らず、これは信頼区間ではない。欠測した出所の意味やフラグは補完せず、観測可能件数を併記する。

固定48入力は指示込み**94,120文字、178,744 UTF-8 bytes、1入力最大4,035 bytes**。PU01の入力総文字数109,440より少ないが、今回は出力欄が増えている。要求数や文字数をtoken節約率へ換算せず、実測した上流usageで報告する。

この48枠で一度閉じる。全件正答でも、失敗が出るまで会話や難度を増やさない。自己生成要約、保存内容の更新、検索の選択、長期系列のどれを次に測るかは結果を読んで別に設計する。
