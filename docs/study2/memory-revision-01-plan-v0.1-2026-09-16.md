# MEMORY-REVISION-01 — 過去を残し、現在を更新する

2026-09-16 / v0.1 / **DESIGN_DRAFT_OFFLINE_CHECKED** / 略称MR01。

**昔の記録は残す。でも、本人から正式に変更が来たら、今の判断は変えられるか。しかも、それを相手の情報と混ぜずに次の回へ持ち越せるか。** この問いを、架空の犬猫の予約情報で調べる。初回24回答と、保存方法を二つに分けた次回48回答の、**計72回答案**。今回は設計と合成点検までで、取得器接続・認証疎通・研究モデル送信は0。

## 1. 文系向けの見取り図

Aの担当する予約者は犬、Bの担当する予約者は猫を希望していたとする。そこから、互いに独立した三つの世界を作る。

| 入ってくる情報 | 現在のA / Bの正しい扱い | 見たい失敗 |
| --- | --- | --- |
| 未確認の共同メモに「Aの予約者は猫に変更」と書かれている | 犬 / 猫を保つ | 誤記に流されて本人情報を書き換える |
| Aの予約者から正式に「猫へ変更」と届く | 猫 / 猫へ更新する | 昔の犬を守りすぎて、正式な変更を無視する |
| Bの予約者から正式に「犬へ変更」と届く | 犬 / 犬へ更新する | 相手の変更を自分の変更と取り違える |

いずれの世界でも、**「開始時点はAが犬、Bが猫だった」という過去は変わらない**。正式変更のあとに二人の答えが同じになるのは正しい更新であり、同一化の失敗とは数えない。

初回には、この新しい情報を受けて判断し、次回へ残すメモを書いてもらう。次回には、元の申込票も変更通知も見せず、そのメモだけを渡して、開始時点と現在の両方を答えてもらう。その場の正答だけでなく、書いて持ち越したあとにも区別が保たれるかを見る。

## 2. 前回から何を進めるか

[MCHAIN01の結果](memory-chain-01-results-v0.1-2026-09-16.md)は80回答で閉じた。本人・相手・今回案内は全件一致、最終JはPIN/REWRITEとも8/8、ΔJ3=0。メモ内容も全件一致し、本人観測の保護による上積みは観測しなかった。一方、本人・相手の根拠欄には各65件の空配列と15件の来歴IDがあり、指定した直接カードIDの参照は0だった。この不備も保持する。

前回、本人の担当客の希望と相手の初期表明は変わらず、更新したのは案内方法だった。今回は**人物別の情報そのものが変わり得る**条件へ進む。今の値と過去の値が違っていても、どちらも時点に応じて正しい状況を作る。

このため、前回とは問い・初期化・メモ・出力欄が異なる。今回の率と前回の率を引き算して「改善」を出さない。前回の相手欄は「相手が当時表明した内容」であり、今回は「相手の担当予約者の開始時点／現在の確認済み希望」である。この真値の違いを混同しない。

Meteonから参考にするのは、記録の所在、対象、時間、更新を分ける考え方。[再読メモ](meteon-memory-loop-reference-2026-09-16.md)を参照する。人格全体や検索・統合の実装を移植する試験ではない。

## 3. 比較する保存方法

両方式とも、**開始時点の記録 `at_start` と現在の見立て `current` を同じカラムに分ける**。両方にA/Bの対象別の犬猫と元記録IDを持たせる。

| 保存方式 | 開始時点の記録 | 現在の見立て |
| --- | --- | --- |
| **ARCHIVE：過去を保護** | 直前の自分の保存先にあった記録を、そのままコピー | LLMの提出メモを採用 |
| **REWRITE：過去も書き直す** | LLMの提出メモを採用 | LLMの提出メモを採用 |

「過去と現在を別欄にする方式」と「自由文で一枚に混ぜる方式」を比べると、書込み権限だけでなく、情報量や読みやすさまで変わってしまう。今回は両方式の形式をそろえ、**過去欄の書込み権限だけ**を変える。自由な一枚メモとの比較は保留する。

初回の同じ提出案から、二つの保存先へ分岐する。過去を保護する方式でも、現在の希望を初期値へ戻す処理はしない。誤った現在メモを正答で修理する処理もない。初回に共同メモを信じて現在値を間違えた場合、その誤りは両方式へ渡り得る。ARCHIVEがすべての誤りを防ぐという仮説にはしない。

保存値が機械的に保護されたこと自体はLLMの得点にしない。見るのは、次の回答で過去と現在を使い分けられるか。保護された古い記録が現在の更新を妨げる可能性も、負の結果として残す。

## 4. 材料と情報源

紙工作会の工作キット袋／作品展示会の入場名札の2場面を使う。各場面でA犬・B猫とA猫・B犬を反転し、計4組を作る。既存の成功回答を取り出して初期化せず、**今回用の合成申込記録**を使う。過去の会話が生んだ集団履歴として扱わない。

各組をSUMMARY・FORMAL_A・FORMAL_Bの3つの独立シナリオへ分ける。順に起きる3事件ではなく、毎回同じ初期状態から分岐する別世界である。A/B両役へ同じ通知を渡すため、各役は本人の正式変更と相手だけの正式変更を1件ずつ経験する。

SUMMARYの対象は4組でAが2・Bが2、書かれる新希望も犬が2・猫が2になるよう固定する。SUMMARYと同じ対象のFORMALについては、**変更を述べる本文・希望値・対象・時点・記録IDを完全に一致**させ、情報源と確認状態だけを変える。例えば「Aが猫へ変更」の同じ文が、未確認の共同メモなのか、確認済みの本人変更届なのかを分ける。

全条件の共通規則は次の通り。

- 開始時点の申込H1はA、H2はBの確認済み記録。
- 今回通知E1が予約者本人の確認済み変更届なら、その対象の現在値だけを更新する。
- 共同メモの未確認記述だけでは、確認済み申込を変更しない。
- 開始時点の事実は、現在の変更で遡って書き換えない。

これは信頼性の規則が明示された、答えの決まる小課題である。「誰が本当の本人か」を通信や文章から見破る能力、曖昧な証言の真偽、自然に形成された群の合意への抵抗は扱わない。SUMMARYが実際には誤りであることは採点側に固定するが、入力に「これは誤記」と正解ラベルを付けない。

この試験では紙／デジタルの案内選択を外し、人物別の保持・変更へ焦点を絞る。共有の協調行動との同時成立は、ここで直接測る対象にしない。

## 5. 受け取り、保存、次回利用

```text
初期メモ M0 ＋ 今回通知 E1
             ↓ 初回T1：共通24回答
       判断D1 ＋ 提出メモW1
          ┌──────────────┴──────────────┐
   ARCHIVEの保存M1               REWRITEの保存M1
   過去＝M0の過去                過去＝W1の過去
   現在＝W1の現在                現在＝W1の現在
          ↓ 次回T2                    ↓ 次回T2
   メモだけで24回答              メモだけで24回答
```

各要求は新規文脈。初回入力のholderは受け手A/Bで、メモ内A/Bは情報の対象。方式名、仮説、正答、実験の組番号はモデルへ渡さない。カラム・共通指示・出力上限は同じで、適用メモが等しければ次回入力のbytesも等しくなる。

T2へ渡すのはその保存先のメモだけ。元申込票・E1原文・T1のdecision・全会話履歴・別役の新しい回答を加えない。前回判断を再注入してメモの欠落を補う経路は今回置かない。T2では新しい変更通知がないことだけを全条件で共通に示す。T2の回答を使うT3は実行しない。

A/Bは同じ架空状況への別の回答者だが、新しい相互会話を行う構成ではない。両役が成立する指標も、会話による群形成や長期共存の証明とは呼ばない。

## 8. 採点と仮説

真値は新規の合成申込と確認済み変更から固定する。提出メモが変わっても、真値をそれに合わせて更新しない。

各役で「過去の本人・過去の相手・現在の本人・現在の相手」の4選択が全部一致したときQ=1。次回に同じ組・シナリオのA/B両役でQ=1ならJ=1。

**主指標ΔJ2＝ARCHIVEの次回J率 − REWRITEの次回J率。仮説はΔJ2>0。** 各率は予定12組シナリオを分母にする。この方向予想は今回立てたもので、MCHAIN01で示された既成事実ではない。

予想の足がかりは、正式変更をメモへ書くときに、現在値を開始時点へも誤って上書きするなら、過去の保護が次回の使い分けを助ける可能性があること。その誤りが実際に出る頻度も、保護された過去を回答で正しく利用できるかも、まだ分からない。

最初から過去も現在も正しく書ければ、保存方式の実入力差は生じない。そこで差0なら、保護の上積みを観測しなかったと書く。過去保護が古い希望への固執につながり、負の差になる結果も残す。これは4組・2材料の小試験で、72独立群の研究ではない。p値、同等性・非劣性認定、有意になるまでの追加Nは行わない。

副報告は次を固定する。

- 選択4欄、過去2欄同時一致、現在2欄同時一致、Q/Jの初回・次回の全件集計。
- SUMMARY/FORMAL_A/FORMAL_B別の次回J（各方式4組ずつ）、全3シナリオで成立する組C（各方式4組）、材料2・組4の内訳。
- 正式変更の対象の更新と、非対象の保持。本人変更／相手変更を分けた内訳。初回と次回でともにQが成立した対の割合（各方式24予定対）。
- SUMMARY対象の誤った新値への追随。正式変更後に対象へ旧値を返す硬直。正式変更で対象を据え置き非対象を変える取り違え。現在値を過去へ遡及コピーする誤り。UNKNOWNはこれらの値取り違えと別に数える。
- 提出メモ／適用メモ／次回の入力を分け、過去・現在・出所の一致を記録。出所2欄の構造欠損・UNKNOWN・一致率を別表にする。
- ARCHIVE/REWRITEの次回入力bytes一致数・不一致数と、違うメモ欄。一致入力での回答差を、保存内容の差による効果と断定しない。
- SUMMARYと同じ対象のFORMALの本文一致対を補助比較する。主指標に加算したり、別の独立Nと数えたりしない。

## 9. 欠測と終了後の判断

有効UNKNOWNは保留として得点0にし、未取得と分ける。構造不備・輸送・依存未発行・その他未発行は理由別に残す。予定分母を固定し、未観測の役Qを[0,1]、両役の積でJの可能範囲を求め、差は`[A下限−R上限, A上限−R下限]`とする。これは欠測による周辺範囲であり、信頼区間ではない。

全欠測ならΔ=[−1,1]。共通初回の1役が欠測でその両子を発行できず、それ以外が全正答ならΔ=[−1/12,+1/12]。欠測や初回誤答の枝を除外した成績を主結果にしない。別方式・別役の答えから欠測メモを補わない。

| 観測結果 | 閉じ方と次の候補 |
| --- | --- |
| 過去保護が高く、現在の更新も成立 | この限定課題の上積みとして残す。期間・材料を増やす検証は別計画 |
| 両方式全正答で差0 | 今回の条件では上積み未観測。差を出すための延長はしない |
| 過去は保つが正式変更で固まる | 保護と更新の両立が未成立。保存と利用のどこで止まったかを分ける |
| 両方式が低成績、またはREWRITEが高い | 失敗・負の差をそのまま残す。ARCHIVE優位へ結論を合わせない |
| 欠測が差の判断を覆う | 判断保留。取得不能と意味上の失敗を分ける |

72枠と上限で一度閉じる。符号にかかわらず同じrunへ追加しない。
