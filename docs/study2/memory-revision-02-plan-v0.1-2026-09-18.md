# MEMORY-REVISION-02 — 変更を重ねても、昔と今を引き継げるか

2026-09-18 / v0.1 / **DESIGN_DRAFT_OFFLINE_CHECKED** / 略称MR02。

**本人の希望が変わる。別の人も変わる。さらに一人が元の希望へ戻る。そのあと未確認の共同メモが届いても、誰の・いつの・何に基づく情報かを、引き継ぎノートだけで保てるか。** 前回合意した方向を、同じ世界で進む5段階・計72要求の小試験にした案。今回は設計と合成点検までで、取得器接続・認証疎通・研究モデル送信は0。

## 1. 文系向けの見取り図

A担当のお客さんが犬柄、B担当のお客さんが猫柄で始まる例。

| 段階 | 今回入ってくる情報 | 正しい現在のA / B | 現在の元記録 |
| --- | --- | --- | --- |
| 開始前 | 最初の確認済み申込 | 犬 / 猫 | A=H1、B=H2 |
| T1 | Aが正式に猫へ変更（E1） | 猫 / 猫 | A=E1、B=H2 |
| T2 | Bが正式に犬へ変更（E2） | 猫 / 犬 | A=E1、B=E2 |
| T3 | Aが正式に犬へ戻す（E3） | 犬 / 犬 | A=E3、B=E2 |
| T4 | 未確認の共同メモに「Bは猫へ変更」（E4） | 犬 / 犬を保つ | A=E3、B=E2を保つ |
| T5 | 新しい通知なし。保存メモだけで次の受付 | 犬 / 犬を保つ | A=E3、B=E2を保つ |

**どの回でも「開始時点はAが犬、Bが猫」は同じ。** 正式変更で二人とも同じ希望になることは成功として扱う。T3でAが犬に戻っても、現在の根拠は最後の変更届E3であり、最初のH1へ巻き戻さない。

毎回その場の答えだけでなく、次に残すメモも作る。次の回へ渡すのは、その保存メモと今回の新しい通知だけ。元の申込票・過去の変更届・前回の回答を外から配り直さない。最後のT5は通知もなく、書いて引き継いだ記録だけで確認する。

前回の説明では未確認メモを「二人とも猫」と例示した。今回は通知の単一subject形式を継承し、**片方Qの未確認変更**に限定する。複数対象の通知処理を同時に増やさないための具体化である。

## 2. 前回から進める一点

[MR01](memory-revision-01-results-v0.1-2026-09-16.md)は、同じ出発点からSUMMARY／FORMAL_A／FORMAL_Bという三つの別世界を作る2段階試験だった。72回答すべてで4選択と現在の出所が一致し、ARCHIVE/REWRITEの次回Jは12/12、ΔJ2=0。初回メモが全件正しく、次回の入力は24/24対で同じだった。保護の上積みという前回予想>0は未達のまま保存する。

今回は**同じ世界で更新を重ねる**。一つ前の段階で自分が書いたメモが、次の変更を判断する土台になる。途中で誤っても最後に戻れば満点、という測り方を避け、全経路の成立と最終回の成立を分ける。

これは期間の長さだけをランダムに割り当てる比較ではない。MR01と今回の率を引き算して、時間だけの因果効果を推定しない。既使用の2場面と構造化メモを継承する探索で、未使用材料による一般化検証ではない。旧実回答や成功メモを選んで初期化せず、定めた合成申込から新しい回答を取得する案である。

## 3. 固定する材料と系列

紙工作会／工作キットの袋、作品展示会／入場名札の2場面。各場面でA犬/B猫とA猫/B犬を反転し、計4組。各組にA/Bの2役を置く。犬猫は担当者自身の嗜好ではなく担当予約者の希望であり、人格そのものを測る課題ではない。

最初に変わる対象をP、他方をQと書く。Pは4組でA/B各2、役としてはどちらの対象も本人／相手の両方から読まれる。系列は全組で次の構造に固定する。

1. E1：PがQの初期希望へ正式変更。
2. E2：QがPの初期希望へ正式変更。
3. E3：Pが自身の初期希望へ正式に戻る。
4. E4：Qが自身の初期希望へ変わる、という未確認共同メモ。
5. 通知なし。

E1〜E3のみ反映する。E4では現在値も元記録IDも変えない。真値は初期申込と確認済みの変更列から研究側で固定し、LLM提出メモに合わせて正答を変えない。

材料・対象割当 (see the evidence index)とイベント・真値 (see the evidence index)に全文を保存した。初期の犬猫とPの割当は固定された小標本で、材料・変更先の犬猫・順序の完全な要因計画ではない。例えばM1のE1は猫、M2のE1は犬になる。材料差・犬猫差・誰が先かの効果を分離して主張しない。

確認済みかどうかは架空課題に与えた属性で、本人認証や曖昧な証言の真偽を判別する試験ではない。A/B間の新しい相互会話も加えない。

## 4. 二つの保存方法と、情報の所在

| 保存方式 | 過去の欄at_start | 現在の欄current |
| --- | --- | --- |
| ARCHIVE | 毎回、直前の自分の保存メモからコピー | その回のLLM提出案 |
| REWRITE | その回のLLM提出案 | その回のLLM提出案 |

両方式とも、at_start/current × A/B × animal/source_idという同じ欄・同じ情報量を使う。ARCHIVEも初期原票を再読せず、直前に保存していた過去欄だけを引き継ぐ。現在欄を正答へ修理したり、別役の正しいメモで補ったりしない。

```text
合成初期メモ＋E1 → 共通T1：8回答（判断＋提出メモ）
                         ├ ARCHIVEへ適用 → T2(E2) → T3(E3) → T4(E4) → T5(通知なし)
                         └ REWRITEへ適用 → T2(E2) → T3(E3) → T4(E4) → T5(通知なし)
```

T1の同じ提出案から二方式へ分岐する。T2以降は同じ組・同じ役・同じ方式の直前メモを使う。共通T1を二回生成して別標本にすることはない。モデルへ渡すのは場面、担当holder、今回の段階種別、保存メモ、今回通知だけ。方式名・仮説・採点・実験ID・未来の出来事の内容は入力しない。

過去通知を原文で再掲しなくても、LLMがメモへ残した元記録IDは引き継がれる。これは元記録そのものの再取得とは区別する。T2以降のdecisionも次の入力へ回さない。

各段階で、受信メモ、提出メモ、方式適用後のメモ、次の実入力を別々に保存する。全方式・全時点で正しい場合の合成入力は共通指示と例 (see the evidence index)に示す。これは実応答や実際の後続入力ではない。

## 5. 出力と門番

T1–T4はdecisionとnext_memory、T5はdecisionのみ。decisionはMR01と同じ4選択と2出所を持つ。

- 選択：self_at_start / peer_at_start / self_now / peer_now。DOG/CAT/UNKNOWN。
- 出所：self_now_source / peer_now_source。H1/H2/E1/E2/E3/E4/UNKNOWNの単一値。
- メモ：at_start/current、それぞれA/Bのanimal/source_id。

**現在の元記録IDは、その現在値を最後に確定した記録。** 変更届を反映したらそのIDを残し、犬→猫→犬と戻ってもH1/H2へ戻さない。この定義は採点側だけでなく、両方式共通の指示にも明示する。複数変更に必要なID拡張と意味の明確化であり、出所指示の効果を単独で測る比較ではない。

JSON破損・重複キー・非JSON数値・余分な未知キー・サイズ超過は全体不備。その後、選択4欄・出所2欄・提出メモを独立に検査する。出所が省略/nullだからといって、正常な4選択を消さない。

メモが構造有効なら、その回の選択が不備でも継続する。次入力にdecisionを使わないためである。メモ不備なら同じ役・同じ枝の子孫だけを依存未発行にする。共通T1の1役で不備なら両方式のその役T2–T5、計8枠を止める。ARCHIVEのT2の1役で不備なら、その役の同方式T3–T5、計3枠を止める。他の役・組・独立した枝は続ける。

構造有効な誤値・誤った既知ID・UNKNOWNは修復せずに採点し、メモならそのまま次へ渡す。既知の将来ID（例えばT1のE4）も構造有効だが、意味上は不一致として別に数える。構造検査を使って意味上の失敗を分母から外さない。許可IDの列挙は共通指示にあるが、将来の通知内容は見せない。

T5にnext_memoryを要求しないことをメモ欠測とは数えない。意味・形式を直すための再提出はしない。

## 6. 主指標と今回の予想

各役・各回で、過去/現在×本人/相手の4選択が全部正しければQ=1。その回に同じ組のA/B両役でQ=1ならJ=1。

**主指標C_PATH：同じ組の両役がT1〜T5の全回でQ=1になった組の割合。方式ごと予定4組。** 事前に指定する方式差はΔC_PATH＝ARCHIVE−REWRITE。最終回だけのJ5も必ず別に報告する。

**今回の有限標本への予想は、両方式C_PATH=1、ΔC_PATH=0。** MR01で正しいメモを生成できたことを足がかりに、明示した規則と固定欄ならこの系列でも使い分けを保つと予想する。この予想を9月18日に立てた。MR01の元予想>0を変更したり、今回の予想を過去に遡って存在したことにしたりしない。

現在判断の出所2欄も全時点・両役で一致する**C_PATH_SOURCE**を副指標にする。副予想は両方式で1。4選択が正しくても元記録IDが古ければ、主C_PATHは成立し得る一方、この副指標は不成立になる。その場合は「値の使い分けは成立、現在判断の来歴は未成立」と分けて書く。過去メモ内の出所が正しいかはメモ品質の別報告であり、C_PATH_SOURCEだけから全保存欄の正しさを主張しない。

## 7. 必ず残す内訳と欠測

主結果と一緒に、次を固定して報告する。

1. 全72枠の状態。各回・方式の4選択、過去2欄、現在2欄、Q/J、UNKNOWN、構造欠測。共通T1は一つのセル。

4. 現在の元記録IDの一致、UNKNOWN、古い確認済みIDへの巻戻し、未確認E4／その時点より先のID／別対象のIDの申告。分類は重なり得るため一つの排他的原因へ押し込めない。

6. 各経路で最初に観測された誤り・不備と、その後の観測結果。後に新しい正式変更で回復しても、途中の失敗を全経路指標から消さない。欠測区間の内部や発生原因を推測で埋めない。
7. T2–T5の方式間入力は各8対・計32対。一致/不一致/比較不能と、違う欄を保存する。T2以降は両枝で別の回答を生成するので、後の入力差にはそれ以前の生成のばらつきも含まれる。差を全部「保護の効き目」と解釈しない。
8. 物理要求、再送、停止理由、実送信bytes、上流reported usage。reasoning tokensはoutputの内数として扱い、未取得を0としない。

未観測の成分は[0,1]、有効UNKNOWNや観測された誤りは0、正答は1。その積から役・両役・全時点の成立範囲を計算する。既知の誤りがあれば他時点が欠測でも全経路は0。差は[A下限−R上限,A上限−R下限]。これは欠測による周辺範囲で、統計的な信頼区間ではない。共有した欠測の依存で範囲を狭めることはしない。

全欠測ならΔ=[−1,1]。共通T1の1役のメモだけが不備で、その8子孫以外は正答なら64発行、Δ=[−0.25,+0.25]。ARCHIVEのT2の1役のメモ不備でその後の3枠だけ止まれば69発行、Δ=[−0.25,0]。予定分母を成功枝だけへ縮めない。
