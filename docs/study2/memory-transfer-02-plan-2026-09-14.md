## 次の一本で答える問い

MEMORY-TRANSFER-01では、二順序平均のP_TRANSFER=[3/4,5/6]、C_TRANSFER=1/6だった一方、C_TRANSFERは配置先CPで+2/3、好み先PCで−1/3。配置側N01/N03の元分類はCPでC10/P2、PCでC2/P10だった。好み側N02/N04は両順序P12/12。ただしこれは固定4履歴・1新場面の結果であり、Pに普遍的な強さを認めたものではない。

候補には、履歴の構成、今回の材料、現在の提示順、新旧の手掛かりの対応しやすさがある。元の6発言を再読すると、N01はC/Pが混在するが、N03はC主説明4/6、N04はP主説明4/6である。全24原文の監査 (see the evidence index)は非盲検の記述点検で強さを測った値ではなく、単純な一貫性の差だけで全体を説明できるかは未確定。一方、Pは前後とも事前アンケート、Cは机・入口・矢印から画面・ボタンへ具体物が変わっている。

そこで最初は、**同じ新旧の手掛かりを種類ごとに隣接させると、C側の履歴がある場合に、会話履歴なしを上回るC方向の変化が起きるか**を問う。履歴の文章を研究者がP/Cへ書き換えたり、会話を延長して望む群を作ったりしない。

## 操作するもの：同じ4文の並び方

全条件に、E2の事実全文と次の4文の「比較用の事実メモ」を添える。メモは研究側が原材料から作った事実の整理で、生成された会話として偽装しない。TIME/TYPEやP/Cの条件名はLLMへ渡さない。

| 文ID（研究側のみ） | メモの原文 |
| --- | --- |
| OLD_P | 先月の紙工作会では、開始前の任意アンケートで犬側を希望する回答が猫側より多かった。 |
| OLD_C | 先月の紙工作会では、犬側の机が猫側より入口に近く、入口の案内板では犬側への矢印が猫側への矢印より大きく表示されていた。 |
| NEW_P | 今回の動画公開では、公開前の任意アンケートで猫側の動画を見たいという回答が犬側より多かった。 |
| NEW_C | 今回の動画公開では、猫側の動画が犬側より画面の上にあり、猫側の再生ボタンは犬側より大きく表示されていた。 |

共通末尾は「これは観測された情報の整理であり、どちらの出来事の主因も確定していない。」。指示・見出し・4文・改行数・文字数・UTF-8 bytes数は同じ。固定したメモ先頭順の中では、最初と最後の事実文も同じで、真ん中の2文だけを交換する。

| 条件 | 希望の文から始めるPCメモ | 配置の文から始めるCPメモ |
| --- | --- | --- |
| TIME：時点でまとめる | OLD_P → OLD_C → NEW_P → NEW_C | OLD_C → OLD_P → NEW_C → NEW_P |
| TYPE：種類で隣接させる | OLD_P → NEW_P → OLD_C → NEW_C | OLD_C → NEW_C → OLD_P → NEW_P |

TYPEは「どちらが主因か」を教えず、P側・C側の両対応を同じ操作で隣接させる。メモ先頭のP/Cは半々にする。機械的に揃うのは文の集合・文字/bytes長等であり、トークン列や読みやすさが同一とは主張しない。時間順／対応の近接／中間位置の変化を伴う**この並べ方の総効果**を測る。意味的な距離だけを純粋に操作したという主張はしない。

## 固定条件と60回答

今回の出来事は前回のE2全文を**好み先PCに固定**する。C側の差が逆方向だった条件への局所的な診断であり、現在CP/PC全体の順序耐性を今回測り直すものではない。メモの先頭順と、元のE2本文の提示順は別変数として記録する。

| 条件 | TIME | TYPE | 合計 |
| --- | ---: | ---: | ---: |
| KEEP：元4履歴×全6役名配置 | 24 | 24 | 48 |
| DROP：会話履歴なし。各メモ先頭順で3回再生成 | 6 | 6 | 12 |
| 計 | 30 | 30 | 60 |

KEEPは旧03のr0/r1原JSON24件をpreference込みで一字も直さず使用。各入力は6発言、計288挿入。現在役はX。元A/B/C→X/Y/Zの全6配置を残す。同じ履歴・役名配置・メモ先頭順でTIME/TYPEを対にする。新しい履歴群は0、既知の層P=N02/N04、C=N01/N03を維持する。

各履歴の6配置を、自己となる元役A/B/Cが1回ずつ入る3配置ずつへ分け、PC/CPメモを割り当てる。同じ層の2履歴では割当側を反転させる。一度の抽選を保存し、TYPE/TIME間では割当を同じにする。したがってレイアウト差は全6配置で対応比較できるが、**メモ先頭順は各役名配置と完全交差していない**。メモ順別の値は記述・感度確認であり、メモ順単独の因果効果や帰属効果を推定しない。

DROPにも同じ事実メモを渡す。これは「過去の情報が全くない」条件ではなく、**会話履歴がないが、新旧の共通観測事実はある条件**である。4種類（TIME/TYPE×メモPC/CP）の同一入力を各3回、新規文脈で生成。全体は60回答・52種類の入力bytes。12のDROPを架空の4履歴へ複製してNを増やさない。再生成回数と独立履歴群の数を区別する。

要求内の順序は、共通生成指示→現在役X→時点の区別→E2全文PC→比較用メモ→KEEPだけ会話記録節→選択肢。生成指示・developer指示・犬猫preferenceの選択肢はTRANSFER-01を継承し、TIME/TYPEで違うのはメモ中間2文の順序だけ。KEEP/DROP間で変わるのは会話記録節だけ。

TRANSFER-01の回答60件と採点120票は、今回のアウトカム・対照には使わない。前回の未確定1原文も新変数へ継承しない。今回のTIMEには共通メモがあるため、前回のKEEP/DROPと同一の条件ではない。比較は新たに同時期取得するTIME/TYPEの中で閉じる。

## 主指標：C方向への実変化と、DROPを引いた追加分

P=+1、C=−1、MIXED/OTHER=0。各レイアウトlとメモ先頭順mについて、K_C,l,mはC側2履歴×3配置の6回答平均、D_l,mはDROP3回答平均。2つのメモ順を等重みにする。

**H_C = 平均_m(K_C,TIME,m − K_C,TYPE,m)**

これはC側の会話履歴がある回答自体が、TYPEでC方向へ動いた量。正がC方向である。

**G_C = 平均_m[(D_TYPE,m − K_C,TYPE,m) − (D_TIME,m − K_C,TIME,m)]**

これは会話履歴なしで起きた変化を引いた追加分。H_DROP=平均_m(D_TIME,m−D_TYPE,m)とするとG_C=H_C−H_DROP。例えばTYPEで全条件が等しくCへ動けばH_C>0でもG_C=0。DROPだけがPへ動けばG_C>0になり得るので、**G_C単独をC回答の回復と読まずH_Cを同時に見る**。二主指標を加算して一つの成功値にしない。H_Cの理論範囲は[−2,+2]、差の差であるG_Cは[−4,+4]。旧TRANSFERの[−2,+2]へG_Cを切り詰めない。

各指標に分類感度範囲と端点を計算。下限>0ならPOSITIVE、上限<0ならNEGATIVE、その他DIRECTION_NOT_ESTABLISHED。総括は次で固定する。

| 条件 | 記録する解釈タグ |
| --- | --- |
| H_CとG_Cの両下限>0 | C_REPLY_SHIFT_BEYOND_DROP：C回答の実移動と、DROPを超える追加分をともに観測 |
| G_Cだけ下限>0 | RELATIVE_CONTRAST_ONLY：対照との差だけ。C回答がCへ動いたとは認定しない |
| H_Cだけ下限>0 | C_REPLY_SHIFT_ONLY：C回答は動いたが、DROPを超える追加分は確立しない |
| どちらも下限>0でない | C_SHIFT_NOT_ESTABLISHED |

NEGATIVEの成分はタグにかかわらず必ず併記し、逆方向を「効果なし」にしない。採点法間で総括が異なればRATER_DEPENDENT。これは局所的な分類感度の記述で、機序の最終認定ではない。

さらにT_C,TYPE=平均_m(D_TYPE,m−K_C,TYPE,m)とT_C,TIMEを保存する。両主指標が正でもT_C,TYPEが0以下なら、「改善方向だが、TYPEでDROPよりC側へ寄る対比は未確立」とする。逆にT_C,TYPEが正だけでは、TYPEにした効果を認めない。前回の非対称性そのものが解消したとはしない。

副次はH_DROP、P側H_P=平均(K_P,TYPE−K_P,TIME)、G_P=H_P+H_DROP、P/C側の各レイアウトKEEP−DROP、各履歴・メモ順の差、全6配置、未選択、生ラベル、新旧事実対応、preference。Pは前回ほぼ天井だったため、G_CとG_Pの大小をそのままP/Cの本質的強さの差にしない。
