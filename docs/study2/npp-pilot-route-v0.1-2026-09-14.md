# LLM版NPPパイロットへの進路 v0.1

2026-09-14 / 方針・作業範囲の具体案 / 実行入力は未封印・モデル発行0

**推奨は、N01/N03の機序探索を今回のオフライン点検で閉じ、次の一工程でNPPパイロットの材料・予測器・時系列保存を接続すること。** 最後に具体的な入力と上限を確認して実測へ進む。C履歴の弱さを完全に説明するための別実験は、開始前に挟まない。

## 何を「本丸」とするか

ユーザーが選んだ本丸はLLMへの履歴介入実験。人間のSNS取得やDevDayの到来は待たない。その人工系で、次の二つを同じパイロットから分けて測る。

| 測ること | 比較 | 言える範囲 |
|---|---|---|
| **主：LLM版NPPの予測利得** | M0：事象内容・普段の傾向等 → M1：同じ情報＋直前の群内frame state | この予測手順で、未使用の後続事象をよりよく予測できるか |
| 補助：履歴入力の作用 | 同じ未来事象のKEEPとDROP | 渡した会話履歴全体が応答分布に寄与するか |

NPP = 損失(M0) − 損失(M1)。正なら予測改善。KEEP−DROPをNPP値とは呼ばず、二つを合算しない。元の研究計画§11 (see the evidence index)も、チャネル介入と複数事象の予測評価を別にしていた。人間研究を先に行う順序や旧392生成案は今回の採用条件ではない。

今回のオフライン点検 (see the evidence index)では、同じC層でもN01/N03の履歴構成と反応が違った。したがって群の状態はP/C/MIXED/OTHERの分布で記録し、「安定したC集団が最低1つできる」ことをNPP計算の入口にしない。自発形成・会話増幅を証明する場合は別の対照が必要で、既存のNO_DIFFERENTIATIONはそのまま保持する。

## 推奨する最小範囲

| 項目 | 次の準備で具体化する案 |
|---|---|
| 人工集団 | **新4群×3役**。旧N01〜N04は開発資料に留める |
| 出来事 | **新8事象**。平和な架空の犬猫企画。E1/E2は状態の蓄積、E3〜E6は予測器の学習、E7/E8は未使用評価 |
| 初期差 | E1だけPC/CPの提示順を2群ずつ一度割り付ける。P/Cの結論や犬猫人格は指定しない |
| 各時点 | 3役が独立に回答し、全員が終了してからその3発言を次事象への履歴へ加える。同時点の他者回答は見せない |
| 履歴 | その群の終了済み事象の全原発言。自他の役は固定。逐語で渡し、動的要約・勝手な切捨てをしない。現在の事実と過去の事実／解釈を区別する |
| 現在事実の提示 | E2以降は全群共通の事前固定順。各条件で同じ事実を渡す。順序を予測器の共通特徴にも入れる |
| 生成 | KEEP：4群×3役×8事象＝**96回答** |
| 共通DROP | E7/E8で各3役×2回＝**12回答**。現在事実・旧事実の共通記録はKEEPと同じにし、会話発言だけ除く。各群に同じ対照を共有し、12個の新集団とは数えない |
| 採点 | 合計108原文をSol/Luna各1票＝**216票**。6件×18バッチ×2採点法＝36初回要求 |
| 総量案 | **通常144要求／最大180要求**。生成108＋採点36＋構造理由欠損時のみ最大36補完 |
| 分割上限 | E1〜E4：通常64／最大80要求。E5〜E8＋DROP：通常80／最大100要求。各モデル枠60分、計最大120分。全体を一度の承認範囲とし、時限超過分を翌枠で埋めない |

直近実測80要求・24分34秒を単純比例すると144要求で約44分。ただし履歴が長くなるため所要時間の保証には使わず、上表の上限で停止する。レビューと報告はモデル時間枠とは別。既選択のChatGPT利用経路を使い、追加支払い・API鍵変更は提案しない。

群の交流は「前の事象の全員の発言を次の事象で読む」形になる。同じ事象内で議論を重ねる試験や、永続する内部人格の試験とは区別する。状態が分化しなくても群を入れ替えず、8事象が終われば閉じる。

## 未来を見ずに予測する手順

1. 8事象の本文・事象特徴・提示順・役・ID・採点基準・処理順を、生成前にまとめて固定する。未来事象の本文を作成者が知ることと、未来のLLM回答を予測器が見ることを区別する。E7/E8の応答は開発に使わない。
2. E1/E2を終了し、各群のframe stateを作る。E3〜E6では過去の値だけから特徴を作り、対応する回答を学習標本として蓄積する。
3. E6を閉じたらM0/M1の係数を固定する。E7のどの回答も発行する前に、全群・両採点法の予測確率と入力hashを保存・封印する。
4. E7のKEEP/DROPを取得・採点する。E7の確定済み記録をE8の過去状態へ加えてよいが、係数の再学習・特徴選び・プロンプト変更は行わない。E8の全予測を保存してからE8を発行する。
5. E7/E8の損失差を各々報告し、actor→群→事象の順に等重み平均する。2事象のうち都合のよい一方だけを主結果にしない。

E7の結果を見て「もっとNを増やす」「E8を差し替える」は行わない。E7は係数の学習には使わず、E8時点で利用できる過去情報としてのみ使う。これは時系列を進める事前固定評価である。

## 予測モデルと測定を有限にする

**単一の正則化多項ロジスティック予測器**をM0/M1で共用し、ハイパーパラメータ探索は0とする案。M0には、公開した事象特徴（P/Cの手掛かりと結果の対応等）、群ごとの緩やかな過去分布、初期seed・現在順・過去の取得量、他群の直前分布と直前事象の特徴を渡す。必要な安定した群差・群×事象反応も、低次元の共通特徴として次の仕様で明示する。

M1が追加するのは、その群の直前事象の分布から、それ以前の基準分布を引いた偏差だけ。M0にも普段の履歴を与え、M1だけが過去の全情報を持つ比較を避ける。P/C/MIXED/OTHERの4分類を予測し、MIXEDとOTHERを得点0で潰さない。

主損失案は**4分類Brier損失**（四確率の二乗誤差の和、0〜2）。元Study 1の主log lossとは異なるパイロット指標として`NPP_Brier`と記す。M0/M1の差は−2〜2であり、旧P/C得点の差と同じ単位ではない。採点法ごとの値を別々に出し、多数決で一つの正解へまとめない。

この段階で未完成なのは、事象特徴の全列・基準分布の窓と平滑化・正則化値・学習時の欠測処理を**実行可能な仕様と合成例へ落とす部分**。次の準備で一度固定する。実測後にこの文書の曖昧なまま選ぶ余地を残さない。

測定は既存v0.4の主説明判定・全文引用・四理由・原文の対象／観測対応を継承する。新事象で同じP/C定義が適用できることは、発行前に合成例で点検する。定義変更が必要なら、その変更を隠して同じ測定版とはしない。

未裁定は無理にP/Cへ直さない。学習・過去stateでは固定した欠測表現とcoverageを両モデルへ等しく渡し、未観測を「frameなし」の0にしない。評価標本は分母から落とさず、予測を固定したまま4つの可能なラベルを使って損失差の上下限を求める。同じ原文の未知ラベルは両モデル・両採点法で共有する。この範囲は評価ラベルの扱いへの依存で、学習や過去stateに残る測定誤差全体の保証ではない。そこも別の欠測表で報告する。

## 開始条件と、求めない条件

| 開始前に必要 | 判定できる実物 |
|---|---|
| 事象と分割が固定 | 8事象・役・条件・事象系列ID・順序・生成数のmanifest。E7/E8の同じ事象の言い換えを学習側へ混ぜない |
| M0/M1が同じ条件で比較可能 | 特徴の全列・欠測・平滑化・学習重み・正則化・損失・集計式の仕様と実装 |
| 予測時点が守られる | 予測未保存なら対象生成を拒否、未来label/同時点履歴を入れた合成例を拒否、予測後変更を拒否する検査 |
| 測定と共有対照が保たれる | ラベル・原文・引用hashの対応、未裁定の固定分母、DROPの二重計上を防ぐ合成例 |
| 故障と効果を分離できる | route/保存異常・上限・構造欠損・予測不成立の停止試験、未取得IDの記録 |

これらが通れば実測を提案する。事前にP/Cが均等、全群が安定、TYPEで改善、全判定一致、機序の一意確定、既存実験のp値陽性、人間communityの取得成功を要求しない。

## 結果の閉じ方

- **COMPLETE_PILOT**：予定の時系列観測・予測保存が成立し、損失または未裁定範囲を出せた。NPPが負でも0を含んでも完了。
- **INCONCLUSIVE_PIPELINE**：生成・入力・保存・時系列の不成立で、予定した比較を作れない。理由と未取得を保存して終了し、効果0へ変換しない。
- **NO_HISTORY_VARIATION**：直前偏差が変化せずM1の追加情報がない場合の補助タグ。固定手順で出せる数値は報告するが、一般的な履歴効果の反証にしない。群や事象を追加して救済しない。

観測が成立した後の方向は、両採点法で範囲下限>0なら`POSITIVE_IN_THIS_PILOT`、両者で上限<0なら`NEGATIVE_IN_THIS_PILOT`、残りは`DIRECTION_NOT_ESTABLISHED`、異方向は採点法依存を併記する。これは有意性検定ではない。小さい学習集合と評価2事象なので、係数の意味・十分な基準調整・将来全般への一般化を認定せず、p値・検出力の保証を付けない。

各群・各事象、原ラベル・未裁定量、M0/M1損失、KEEP/DROPの分布差、実コストを必ず残す。パイロット後は一度だけ、追試の規模・基準モデルの不足・実施可能性を評価して、次の確認計画か終了報告を選ぶ。有意になるまで拡大しない。

## 次の一工程と保留棚

次の作業は**このパイロットの完全な仕様・8事象・予測器・時系列ゲートを一つの準備パッケージとして作り、合成検証・予算・封印まで閉じる**こと。実機の小試験を何本も挟む予定は置かない。既存の送信器を変える必要がなければ再資格試験を増やさない。実入力、合成結果、上限を確認可能にしてから一度だけ実測GOを求める。

| 道筋 | 費用・得るもの | 扱い |
|---|---|---|
| **推奨：上記パイロットへ直行** | 準備はオフライン、実測案は通常144／最大180要求。NPP値と履歴入力の補助比較を得る | 今回の進路提案 |
| N01/N03の内容・末尾・反復をさらに分解 | 新しい実験と採点が必要。数は別設計になる。機序説明は深まるがNPPの予測評価は進まない | 本パイロット後、特定の機序を主対象に選ぶ時に再検討 |
| 最初から多数群・多数系列の確認研究 | パイロットの実コストと欠測率がまだないため予算・規模未確定 | パイロットを閉じ、区間幅や再現性の目標を決めた時 |

SWAPは現在の明示入力だけの構成ではdonor KEEPと同じ要求になり得る。履歴外の受け手状態を独立に定義するまでは、名前だけの第三条件を足さない。SELF対照、複数モデル、長期会話、完全自発形成の再挑戦も今回の入口にはしない。

この文書はユーザーが依頼した進路判断を具体化したもので、108生成・216採点の実発行承認ではない。実装・入力封印は次工程。旧研究計画・旧結果・旧pointerを変更しない。
