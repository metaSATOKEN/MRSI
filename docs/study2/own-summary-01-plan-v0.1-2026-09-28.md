# OWN-SUMMARY-01：本人用の集計を分けて供給すると、共同担当と本人判断を使い分けられるか

2026-09-28／設計案v0.1、略号OS01。[CT01の結果](../../experiments/CT01/docs/candidate-totals-01-result-2026-09-28.md)を受け、**本人用の集計を「判断を作る時」と「保存判断を使う時」に分けて供給する**小比較を設計する。

共同用合計はCT01のTOTALSと同じ条件で維持する。本人集計の有無を二工程で交差させ、前半を共有して最大384回答に抑える。今回の作業は設計・材料・算術点検・取得前カードまで。Colab一セル実行コードとモデル実測は次工程。

## 1. 今回の問い

CT01では、合計ありで共同の最適案を32/32選べた。しかし、M12では提案時から本人判断を誤り、M03では正しい本人判断を保存した後の利用時に誤った。正しい提案への不適切COUNTERも一件残った。

本人用の支援を提案・利用の両方へ一度に足す二条件比較だけでは、どの工程で効いたか分けにくい。そこで、形成時の本人集計と利用時の本人集計を独立に切り替える。

**本人の正解は、本人自身の累積経験に合った推奨である。** 保存された判断が誤っていれば、経験から見直すことが正しい。共同の担当と同じ答えでも別の答えでも、内容をこの規則で採点する。本人記録への機械的な追従だけを保持成功とは数えない。

## 2. 四条件、実生成は384回答

| 評価条件 | 提案時の本人集計 F | 利用時の本人集計 U |
|---|---|---|
| F0_U0 | なし | なし |
| F0_U1 | なし | あり |
| F1_U0 | あり | なし |
| F1_U1 | あり | あり |

Fは本人判断を形成して共同提案を作る工程、Uは二人が保存物から本人判断と共同担当を回答する工程を指す。条件名は管理用で、モデルへ渡さない。

各資料で、F0とF1の提案を一件ずつ新規生成し、それぞれへの相手確認を一件ずつ新規生成する。同じFの**実提案・実確認を固定したまま、U0とU1を別の新規コンテキストへ分岐**する。Uの一方の回答を他方へ渡さず、二人も互いのUSE回答を見ない。

```text
32資料 ─┬─ F0提案 → 相手確認 ─┬─ U0：A利用・B利用
        │                    └─ U1：A利用・B利用
        └─ F1提案 → 相手確認 ─┬─ U0：A利用・B利用
                             └─ U1：A利用・B利用
```

32×（提案2＋確認2＋利用8）＝**最大384生成**。初回64、生成物を引き継ぐ後続320。四条件を別々に通しで生成する512回答より128回答少ない。評価上は128経路になるが、提案64・確認64を重ねて数えない。

## 3. 出発点は全32資料を保持する

CT01の全16出発点×反転／補強を使用し、不成立の三経路だけを選ばない。CT01のTOTALS初回実入力32件から、経験5行、以前の本人判断・共同記録、候補ID・順序・割付・共同合計を保持する。旧合意15出発点と未合意M05も維持する。

**CT01の生成した提案・確認・利用は流用しない。** 今回のF0/F1とU0/U1をすべて新しく生成する。CT01と同等の支援範囲に見えるF0_U0にも、共通の追加欄説明文と新seed・記録IDが入るため、CT01との差を新介入の効果と比較しない。

これは既知材料を使う適応的な工程比較であり、未使用材料への再現試験ではない。強弱・本人推奨一致／不一致・元履歴集合・経験条件の構成は維持する。

## 4. 本人用の集計は、本人の経験だけから計算する

追加フィールドは `own_experience_summary` 一つ。M03反転のAなら次の値になる。

```json
{
  "observer": "A",
  "experience_refs": ["E94A9E91EF2", "EE766BA6019", "E78B082EC9B"],
  "attempts_per_medium_total": 80,
  "projected_success_per_40": {"PAPER": 24, "DIGITAL": 22}
}
```

各媒体の予測値は、`40 × holder本人の全回成功人数 / holder本人の全回試行人数`。本人の経験行をobserverで絞り、分数で計算する。全64本人集計・128媒体値は整数で、別の整数交差積でも照合する。経験IDは実入力の本人の全行、順序も維持する。媒体キーは元の紙／デジタル提示順を保つ。

追加するのは役、入力内の出典ID、分母、媒体別の予測値。推奨ラベル、choice、候補ID、共同担当は入れない。本人の二数値を比較して回答する仕事はモデルに残す。集計値は新しい観測ではなく、元経験から計算した派生情報である。localの出力参照も元の本人経験IDを使い、集計用の新IDは作らない。

M03では本人は紙24対デジタル22なので紙を推奨する。一方、共同候補の合計はAデジタル/B紙が49、逆が47なので、共同担当はAデジタルが適切。この二つを別欄の資料から答え分けられるかを見る。

計算根拠は、実入力全経験のhash・本人行hash・役・全経験ID・分母・媒体別成功人数・分数値・追加オブジェクトhashとともに保存する。既定値をそのまま挿入するだけにせず、実際に渡す入力から再計算し固定材料と照合する。

## 5. 各工程に何を渡すか

| 項目 | 提案 PROPOSE | 相手確認 CONFIRM | 利用 USE |
|---|---|---|---|
| 全経験5行 | 全条件共通 | 共通 | 共通 |
| 共同候補と二案の合計 | F0/F1とも提示 | 提示しない | 提示しない |
| 本人用集計 | F1だけ、提案者のもの | 提示しない | U1だけ、holder本人のもの |
| 保存判断・共同記録 | 以前の記録 | 今回の実提案を継承 | 同じFの実判断・実提案・実確認を継承 |

本人集計は提案32入力と利用128入力の計160入力に供給する。相手確認には新しい支援を加えない。相手の本人判断も現行のCONFIRM指示で生成される。U1では更新本人だけでなく、各役が自分の集計を見るため、相手保持への影響も測る。

PROPOSEとUSEには追加欄の意味を定義する一文を挿入し、各工程の支援あり／なしで同じ全文指示を使う。CONFIRMの全文指示、全工程の出力schema・意味採点はCT01と同じ。本人判断や根拠の修理、最適候補への機械的選び直し、対案の自動再承認は加えない。

共同案は選択した候補IDの割付を複製する。本人欄と出典は実回答のまま。後続へは共通形式の保存物を渡し、候補表・候補ID・共同合計・F/Uラベル・採点結果を渡さない。F1で使った本人集計そのものを保存ノートへ混入させず、U1の集計は実経験からあらためて供給する。

したがってU1は外部の計算支援を毎回受ける条件であり、本人記憶だけの自律的保持を検証したとはしない。

## 6. 主比較を形成と利用に分ける

### 形成の比較

**B = 本人判断Lかつ本人参照Z_local**。F0/F1それぞれ32提案で、`B_F1 − B_F0` を主比較にする。方向予想は、本人集計を添えることでBが増えること。本人のchoiceだけ正しく参照が誤る場合はB不成立、LとZ_localも別表示する。

共同最適性Oと適切提案Pも併記し、本人を助けた代わりに共同提案を損なう場合を隠さない。PはCT01と同じく本人L・本人参照・共同O・共同参照の適合。

### 同じ保存物からの利用の比較

**U_target = 更新本人のUSEでLかつZ_local**。F0の実保存物内でU1−U0、F1の実保存物内でU1−U0を、それぞれ32対応資料で主比較する。相手の同じ評価U_peerも各32回答で併記する。U0/U1は同じ親保存物・全経験・seedを受け、本人集計の有無だけが異なる。

方向予想は、利用時集計によりU_targetが改善し、U_peerと共同利用Hを損なわないこと。形成時集計だけで既に全件正しければ、利用時の差ゼロは天井として記述する。F1内のU差とF0内のU差の差も記述量として出すが、相互作用の有意性検定にはしない。

Fが違うと生成された本人判断・提案・相手確認も異なる。Fの下流差はその一連の経路を含む比較、同じF内のU差は同一保存物に対する利用時支援の比較である。この二つを同じ効果として合算しない。

### 保存判断が正しかったかも分ける

実際に渡したown_judgmentのchoiceを本人経験に照らし、各F・U・役で次を数える。

- 正しい保存判断 → 正しい利用／誤った利用。
- 誤った保存判断 → 正しい利用／誤った利用。

保存時の分類はL、出典不備はZ_localで別表示し、該当する実分母を併記する。欠測は別枠。F間で保存判断の構成が変わるので、この層別割合を独立の能力差としない。本人誤りが共同担当や旧判断と同じだった場合も、文字列の一致と原因説明を分ける。

## 7. 全工程と進行目安はCT01から継承する

| 指標 | 分母 | 集計単位 |
|---|---:|---|
| B・L/Z_local・F/O/P | 各32提案 | F0/F1の二条件。Uへ複製して水増ししない |
| 確認L/Z・K/C・応答適合 | 各32確認 | F0/F1。提案Oで層別し実分母を表示 |
| U_target／U_peer | 各32利用 | F×Uの四条件、役別 |
| H・利用Z・現在最適性 | 各64利用 | F×U、二役を含む |
| J | 各32経路 | F×Uの四条件 |
| Q・S_target・I_peer | 各16出発点 | F×U、反転/補強の対応を維持 |

Jは同じ提案・確認のL/Z、最適合意C、二役利用のL/H/Zがすべて成立。Qは同じ出発点の反転・補強のJがともに成立。S_targetは両経験条件の提案と本人USEのL、I_peerは相手CONFIRMと相手USEのLがすべて適合した場合とする。形成時に不備があれば、U1で本人を修正してもその経路のJは成立しない。**この局所的な回復はU_targetで記録する。**

進行目安は下げず、二段にする。

1. **形成目安（F1が対象、F0も併記）**：P≥28/32、弱×同推奨P≥7/8、提案L=Z_local=32/32。
2. **全工程目安（F1_U1が対象、全四条件を併記）**：Q≥14/16、元履歴集合ごとQ≥7/8、弱/強各Q≥7/8、S_target=I_peer=16/16。

成立下限ですべて届けばMET_IN_FIXED_SAMPLE、いずれかが上限でも届かなければNOT_MET、その間はINCONCLUSIVE。これは小比較を進めるための工学的目安で、統計的有意性や一般化の保証ではない。

固定層別は強弱、本人推奨の同異、反転/補強、元履歴集合、旧合意の変更/維持/未合意。弱×同推奨8条件と、本人推奨と最適共同担当が異なる条件を別掲する。既存8交差区分の構成も保持する。

## 8. 順序・seed・受渡しを先に固定する

候補IDと候補順、経験行・媒体・役の表示順はCT01から保持する。F先行順はCT01のBASE→F0、TOTALS→F1を対応させ、強弱×推奨同異×経験条件の各4資料でF0/F1先行を2対2にする。

U先行順は同じ区分内でsource_rootを辞書順に並べた0始まり順位iとFの0/1から、`(i+F) mod 2 = 0`ならU0→U1、それ以外U1→U0。各区分・各FでU0/U1先行が2対2。成否で並べ替えない。各U内の二役順は元のrole_display_orderを保持する。

seed基準2026092807、配置ブロック×元履歴集合×役×工程から算出し、F/U・経験条件を除く。同じseedでもモデル出力のゆらぎが消える保証はない。記録IDはOS01のnamespaceから作り、F/Uや正解を含めない。同じF内U0/U1の親hashは完全一致を必須にする。

## 9. 欠測・推論の境界

CT01の受け口を継承し、生JSONまたは既知の完全外装だけを受理する。値修理・追加生成0。意味不備でも受渡し可能なら続ける。

- PROPOSEの形式不備・未知候補IDで渡せない場合：同じFの確認1＋USE4が依存欠測。未知IDのF/O/Pは既知不成立として保持する。本人Bは有効な本人欄から別評価する。
- CONFIRMが渡せない場合：同じFのUSE4が依存欠測。
- USE一件の形式不備：その回答だけ欠測。他の役・U条件へ波及させない。
- 明示UNDECIDED、誤った本人判断、不適切COUNTER・誤合意：所定の形式で保存し続行。共同保留を適切に扱えたかも測る。

必要成分に欠測があれば合成指標は未確定、既知の成分不備は別に残す。各主差は32を予定分母とし、下限`(支援あり成立−なし成立−なし未確定)/32`、上限`(支援あり成立＋あり未確定−なし成立)/32`。信頼区間ではない。二つのU差の差はこの範囲の保守的な引き算で表示できる。

前半共有による依存、既知材料の反復使用、各セル一回という範囲を維持し、p値・母集団CIを出さない。本人集計の追加には計算・役/出典の明示・配置・入力長の差が含まれる。効果があっても、算術能力だけへの介入や自己概念の成立とは解釈しない。
