# OWNER-RECENCY-01：Colab一セル版・使い方

2026-09-25／接続準備v0.1。承認済みの[設計](../../experiments/OR01/docs/owner-recency-01-plan-v0.1-2026-09-25.md)を実装した。**設定編集・Drive接続・過去ZIPのアップロードは不要。**

## 使い方

[Readable code and current instructions](../../experiments/OR01/generation/README.md) の**全文をColabのGPUランタイムの1セルへ貼り、実行する。** A100 80GBまたはRTX PRO 6000 Blackwell級を想定する。

1. 固定資料・合成例・GPU条件を確認し、専用環境を準備する。
2. 更新案36件を生成し、それぞれを4条件で保存して後続へ渡す。同じ親内の完全に同じ読出し入力は共用する。
3. 終了時の **`npp-or01-result-日時-識別子.zip`** を保存して返す。

自動ダウンロードをブラウザが止めた場合は、Colab左側のファイル欄から、表示された `/content/npp-or01-result-…zip` を取得する。APIキー・Drive認証・追加セルは不要。

## 今回つないだ処理

更新案は一つ。モデルへ4条件の名前を知らせず、実際の回答を起点に保存器が分岐する。

| 条件 | 共同A/B観測 | 本人観測 | 担当客の犬猫情報 |
| --- | --- | --- | --- |
| G0P0 | モデルの記述 | モデルの記述 | モデルの記述 |
| G1P0 | 人物別の最新版を複製 | モデルの記述 | モデルの記述 |
| G0P1 | モデルの記述 | 本人の最新版を複製 | モデルの記述 |
| G1P1 | 人物別の最新版を複製 | 本人の最新版を複製 | モデルの記述 |

機械処理は「observerで候補を絞る → その人物の最大revisionを選ぶ → 出典を含む行全体を複製」。処理前の案・処理した場所・選択元・前後のhashを保存する。担当客customerは、両方ONでもモデルの記述を保持する。

実行時の保存器は、実回答・元入力・schemaだけを受け取る。採点用の正解からノートを組み立てない。候補と資料の不一致、同版の矛盾、人物欠落は契約エラーとして残す。OFF欄の意味不備は修正せず、保存できればそのまま後続へ渡す。

## JSONの囲いと内容の変更を別記録にする

UPDATE／READとも、まず裸のstrict JSONを読む。読めない場合だけ、設計で固定した一組のMarkdown JSONコードフェンスを外す。原文と内側の本文はそれぞれ保存し、除去した12バイトを記録する。

文字列・値・型・人物・版・出典の変更や欠落補完は行わない。必須欄・型・enum等の構造検査は、その後に実施する。原文上限はUPDATE 16,384バイト／READ 4,096バイトで、長さ打切りの応答は救済しない。

`normalization.json` が外装処理、`policy-trace.json` が行の置換処理。この二つを混ぜず、原回答の形式成立数と正規化後の成立数も別に集計する。

## 読出しの共用と件数

READへ渡すのは、その分岐の**実保存PRIVATE/GROUP**と元のholder・場面・課題名。通知・候補・正解・分岐名は渡さない。従来の四値抽出指示を使い、実際に返った四値から案内を計算する。

同じ親内でmessages・schema・モデル設定・seedがすべて一致した場合だけ、一つの物理READを共用する。個別ノートが違えば別入力になり、別材料・別反復をまたぐ共用はしない。共用は回答取得前に決まり、誤答や形式不成立だったから別条件として取り直すこともない。

| 数えるもの | 件数 |
| --- | ---: |
| 独立材料 | 18（修復10・巻戻り防止8） |
| 共通更新案 | 36（各2反復） |
| 評価する保存・読出しの分岐 | 144（親ごとに4条件） |
| 実際のREAD生成 | 最大144。同じ入力の共用で減る |
| 合計の実生成上限 | **180** |

全更新が構造成立し、各親の4分岐が同じなら36更新＋36READ＝72生成。4分岐がすべて異なれば180生成。更新の形式不成立では、その親の4READが依存欠測となる。

集計の `closed_logical_responses=180` は、更新36＋論理READ144の記録を閉じた件数。実際に開始した生成数は `attempted_generations`、回収できた実回答は `performance` に示す。`read_sharing.mapping` で、一つの実回答を共用した条件を確認できる。

## 途中保存・停止・再クリック

6親（24分岐）を処理するごとに、`/content/npp_or01_runs/` へ途中ZIPを作る。完走時まで操作を求めず、終了ZIPだけを自動ダウンロードする。

- **意味不備・形式不備・長さ打切り**：原文と評価を残し、他の独立更新を続ける。更新不成立に依存する4READは欠測として記録する。
- **時間上限・利用者の停止・OOM等の実行例外**：回収済みの記録を保持して閉じる。開始したが回答を回収できなかった呼出しは `INTERRUPTED_UNCERTAIN`。未実行と分ける。
- **同じランタイムで再クリック**：追加生成・環境再構築・モデル再ロードをせず、既存記録を再照合してZIPを返す。

途中ZIPから別ランタイムで生成を再開する機能は設けていない。実行ロックが残る場合は重複生成せず止まる。ランタイムを破棄する前に、結果ZIPを手元へ保存する。
