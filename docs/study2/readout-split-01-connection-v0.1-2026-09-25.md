# READOUT-SPLIT-01：Colabの1セル版・使い方

2026-09-25／接続準備v0.1。承認済みの[設計](../../experiments/RS01/docs/readout-split-01-plan-v0.1-2026-09-25.md)を実装した。**設定編集・Drive接続・過去ZIPのアップロードは不要。**

## 使い方

[Readable code and current instructions](../../experiments/RS01/generation/README.md) の**全文**をColabのGPUランタイムの1セルへ貼り、実行する。A100 80GBまたはRTX PRO 6000 Blackwell級を想定し、モデル取得前にVRAM・空きVRAM・BF16対応を検査する。

1. 固定資料・採点器の合成点検、GPU点検、Python環境の準備を行う。
2. 固定revisionのQwen3.5-27Bで、三条件を各二反復、計96回答生成する。誤答やJSON形式不備も記録して次へ進む。
3. 終了時に **`npp-rs01-result-日時-識別子.zip`** を自動ダウンロードする。このZIPを保管して返す。

自動ダウンロードがブラウザに止められたら、Colab左側のファイル欄から、表示された `/content/npp-rs01-result-…zip` をダウンロードする。APIキー・Drive認証・別セルは不要。

## 今回の三条件

| 条件 | LLMへ渡すもの | LLMの仕事 | 保存する結果 |
| --- | --- | --- | --- |
| DIRECT | 元の個別・共同ノート | 案内を決める | 案内と採点 |
| EXTRACT | DIRECTと同じノート | A/Bの紙・デジタル四値を転記 | 実抽出値、欄別・四値一致、コードで計算した案内 |
| RULE | 原材料から取り出した正しい四値だけ | 案内を決める | 案内と採点 |

EXTRACTのコード計算は**実回答の四値だけ**を使う。欠落を正解表で補わず、誤った四値でもそのまま計算する。「四値は誤りだが案内だけ正解」も別集計に残す。各EXTRACT回答の `derived-decision.json` に、原回答のSHA256・実抽出値・計算結果を保存する。これは追加のモデル生成を伴わない。

RULEの入力はEXTRACTの成否に依存しない。全条件を新規コンテキストで実行し、モデルへ渡すのは固定したメッセージだけ。正解ラベル・採点・別条件の回答は渡さない。RULEは全8種類（主6種類）の四値パターンへ縮約されるため、元材料単位に加えてパターン別の件数を集計する。

## 途中保存・停止・二度押し

各回答を保存し、24回答ごとに途中ZIPを `/content/npp_rs01_runs/` に作る。途中ではダウンロード操作を求めず続行する。終了ZIPだけを自動ダウンロードし、途中ZIPは必要に応じてファイル欄から回収できる。

- **誤答・形式不備・長さ打切り**：原文と成分採点を残して次へ進む。
- **時間上限・利用者の停止・OOM等の実行例外**：回収済みを保存し、残りを未実行として閉じ、ZIPにする。開始済みで回答を回収できなかったものは未確定として区別する。
- **同じランタイムで再クリック**：既存記録を再照合し、ZIPを再ダウンロードする。追加生成・モデルの再ロードは行わない。

この小実験には、途中ZIPを別ランタイムへ復元して残りを生成する機能は設けていない。停止時は結果ZIPを返して次を判断する。実行ロックが残る場合も重複生成せず停止する。ランタイム自体が破棄されると、未回収の一時記録は失われる。
