# READOUT-SPLIT-01：ノートを読む工程と、案内を計算する工程を分ける

2026-09-25／設計v0.1。ユーザーの小実験設計の依頼を受けた具体案。実モデルの取得・ロード・生成は行っていない。

**今度は「四つの値を正しく拾えるか」と「正しい四値があれば案内を選べるか」を別々に測る。** 前回と同じ材料に戻り、ノートを丸ごと読んで判断する対照も同じ実行内に置く。

前回は、正しいノートを渡しても共同判断がFULL3/24、DUAL7/24、CHANNEL7/24だった。犬猫は全正答で、共同判断だけを求めても大半を誤った。ここでは保存・更新の実験を増やす前に、共同判断を任せる工程を切り分ける。

## 1. 三つの条件

| 条件 | LLMへ渡すもの | LLMに求めるもの | 何を測るか |
| --- | --- | --- | --- |
| DIRECT：直接判断 | 前回と同じ正しいPRIVATE／GROUPノート | 共同案内だけ | 同時期の基準。前回CHANNELの指示・schemaをそのまま使う |
| EXTRACT：値の抽出 | DIRECTと完全に同じノート | A/Bそれぞれの紙・デジタルの四値だけ | ノートから必要な事実を取り出せるか |
| RULE：規則の適用 | 原材料から決定論的に抜き出した正しい四値だけ | 共同案内だけ | 値を短い表にしたとき、案内規則を適用できるか |

EXTRACTの回答からは、ローカルのコードで案内方法を計算する（以下、**EXTRACT＋CODE**）。これは追加のLLM要求を必要としない。

```text
同じ正しいノート ── DIRECTのLLM ─────────→ 案内
       │
       └── EXTRACTのLLM → 取り出した四値 → コード → 案内

原材料から作った正しい四値 ── RULEのLLM ────→ 案内
```

**RULEに渡すのは原材料の四値で、EXTRACTが生成した四値ではない。** それぞれ独立した新規コンテキストで実行する。抽出が失敗してもRULEを実行でき、全条件で予定数を保てる。

## 2. 問いと予想

- **抽出の問い**：ノート中の四値を完全一致で取り出す工程は、後述の成績目安を満たすか。案内を選ぶより転記の方が成立しやすいと予想する。
- **規則の問い**：正しい四値だけを渡すRULEは、DIRECTより案内正答が増えるか。情報を絞った入力で改善する可能性を検討する。
- **構成の比較**：EXTRACT＋CODEはDIRECTより案内正答が増えるか。同時に、その正答が正しい四値に基づいているかを点検する。

出力として求めた四値は、モデルの内部思考の記録ではない。この実験で比較するのは、外から指定できる入力・仕事・出力の組合せである。EXTRACTでは対象欄を明示し、RULEでは入力の量・構造と指示を変更する。成績差はその構成全体の差として読む。

## 3. 材料と割付：合計96回答

[READOUT-LOAD-01の固定16入力](../../experiments/RL01/design/README.md)をすべて使う。主12材料と境界4入力、各一役という構成も保持する。前回の正解・失敗に応じて材料を選び直さない。新規の未使用材料での確認試験ではなく、既知材料を使う工程診断と位置づける。

| 集合 | 材料・入力数 | 条件×反復 | LLM回答数 |
| --- | ---: | ---: | ---: |
| 主比較：紙／デジタルが正解 | 12 | 3×2 | 72 |
| 境界：使える方法0個／2個 | 4 | 3×2 | 24 |
| 合計 | 16 | 各6回答 | **96** |

主集合は紙／デジタル各6、担当役A/B各6、犬猫各6、不採用媒体を使えない観測者Aのみ／Bのみ／両方が各4。DIRECT・EXTRACTでは、本人情報・場面・元ID・版番号を含む元ノートをそのまま渡す。

RULEへは`coverage.A.paper`、`coverage.A.digital`、`coverage.B.paper`、`coverage.B.digital`だけを渡す。場面・担当役・犬猫・元ID・版番号・正解ラベルは渡さない。値の並びはA→B、各行digital→paperというJSONの固定整列を三条件の実入力で維持し、提示順の比較を加えない。

情報を四値へ絞ると、**主12材料は6種類の同一入力パターンに縮約される**。境界は0個と2個の各1種類で、RULEの全16入力は計8種類。各パターンは4回生成される（元の2入力×2反復）。材料単位の対応表に加えてパターン別成績を提示し、同一四値への反復を独立した論理問題に数えない。0個となる全組合せをLLMで網羅する実験でもない。

新しいprotocol名からseedを固定し、材料・反復内の三条件には共通seedを使い、二反復目は別seedにする。主12材料では条件の6通りの順を各反復2回ずつ割り付け、二反復目は各材料内の逆順。主材料3件ごとに境界を1件挟む。境界の条件位置は近似均衡とする。前回の回答・seedを流用せず、今回のDIRECTを比較相手にする。

## 4. 四値と案内の規則

EXTRACTは次の型で、入力にある文字列をそのまま返す。各値は`ALL`か`NOT_ALL`。例示値を含む正答例は実プロンプトへ追加せず、schemaだけを示す。

```json
{
  "coverage": {
    "A": {"paper": "ALL", "digital": "NOT_ALL"},
    "B": {"paper": "ALL", "digital": "ALL"}
  }
}
```

この例は紙だけが二人ともALLなので、案内はPAPER。

DIRECTとRULEが答える案内の規則は共通にする。

> 案内方法はA/Bの両方でALLと確認できる方法がちょうど一つならPAPERまたはDIGITAL、0個または2個ならUNKNOWNとしてください。

コードも同じ規則を使う。紙とデジタルそれぞれについてA/B両方がALLかを判定し、成立する方法が一つならそれを選び、0個または2個ならUNKNOWNとする。コードは**実際に抽出された四値だけ**を読み、採点用の正解表で値を補わない。四値すべてが有効な列挙値として揃わなければ計算せず、案内は判定不能として残す。

正しい四値からの機械計算は、全16通りの二値パターンをオフラインfixtureで検証する。この計算が正しく働くことは対照の実装点検であり、LLMの能力を示す結果とは分ける。

## 5. 採点：抽出と案内を二重に見る

### 抽出

EXTRACTについて、四つの欄それぞれの一致と、**四値すべての完全一致**を採点する。主指標の分母は24予定回答で、96個の欄を独立Nにはしない。境界8回答は別表示する。

一つでも有効な値の書き違いが見えれば完全一致は不成立。書き違いは確認できず、必須値が欠ける場合は未確定とする。A/Bの入替えも値が違えば不成立に数える。

### 案内

DIRECT・RULEの`decision.channel`と、EXTRACT＋CODEが算出した案内を、原材料の正解と比較する。UNKNOWNが正答の境界と、主比較でのUNKNOWN誤答を分ける。

EXTRACTは次の内訳も示す。

| 四値 | コードの案内 | 読み方 |
| --- | --- | --- |
| 完全一致 | 正答 | 正しい事実から正しい案内へ接続 |
| 不一致 | 正答 | 誤抽出が案内に現れなかった。抽出成功に数えない |
| 不一致 | 誤答 | 抽出の不備が案内へ到達 |
| 欠落・無効値あり | 判定不能 | 補完せず計算を止めた |

この対応表により、案内正答率だけで抽出の品質を評価しない。正しい四値なのにコードが誤答した場合は、実装の整合性異常として隔離し、成功に読み替えない。

### 形式・欠測・観測単位

無修復JSONの可読性とschema適合を別に記録する。有効な四値または案内値を読み取れる場合は、余分なキー等の形式不備があっても成分採点を残す。JSON修復、コードフェンス除去、重複キーの後勝ち採用、非標準数値、列名・値の自動変換は行わない。非EOS・未実行・無効JSON・無効な案内値は案内の判定不能。抽出の一部欠落では、読めた欄の評価を残す。

全予定回答を分母に正答／誤答／判定不能を並べ、正答率の欠測下限・上限を出す。主比較は各条件24回答、境界は種類ごと4回答。差の下限は後条件下限−DIRECT上限、上限は後条件上限−DIRECT下限とする。p値・母集団信頼区間・事後検出力は算出しない。

反復・正解媒体・担当役・材料・四値パターンごとの結果と、入力／出力token数・生成時間を保存する。RULEには担当役を渡さないため、その担当役別の集計は元材料の対応ラベルであり、役の効果の比較ではない。

## 6. 事前の目安と、結果別の次工程

**工程の目安**は、主20/24以上、紙／デジタルの材料群各10/12以上、各反復9/12以上、境界0個／2個の各3/4以上。EXTRACTの四値完全一致と、各方式の案内について別々に判定する。

- `MET`：観測済み正答だけで全条件を満たす。
- `NOT_MET`：未確定をすべて正答にしても、少なくとも一条件に届かない。
- `INCONCLUSIVE`：未確定の扱いで到達するかが変わる。

これは工程選択用の目安で、形式・出典・長期運用を含むシステム全体の合格判定ではない。

RULE−DIRECTとEXTRACT＋CODE−DIRECTは、主差の欠測下限が＋4/24以上、両反復の下限が正、両媒体群の下限が非負なら「記述的な改善信号」とする。逆方向も同じ規則。届かなければ件数と符号を記述して閉じる。抽出完全一致の成績と案内正答の成績を、同じ意味の指標として勝敗比較しない。

| 四値抽出 | 正しい四値からのLLM判断 | 次に検討すること |
| --- | --- | --- |
| MET | NOT_MET | 抽出＋機械計算を候補にし、LLMの規則適用への依存を減らす |
| NOT_MET | MET | ノートから必要な値を取り出す入力・契約の改善を優先する |
| MET | MET | DIRECTとの差を見て、抽出と判断の仕事を分ける構成を検討する |
| NOT_MET | NOT_MET | この構成では両工程が目安未達。改善箇所を一つ選ぶ別設計か、今回の転移診断の区切りを相談する |
| どちらかがINCONCLUSIVE | — | 未確定の原因と件数を示し、能力の成否を決めない |

DIRECT自体が目安を満たした場合もそのまま報告し、前回より良くなった理由を今回だけで断定しない。先に仮説を立てた「どこかに必ず故障がある」という筋へ結果を合わせない。

**96回答を一巡、または時間上限で閉じる。** どの結果でも同じ実験を成功まで延長しない。生成された抽出値を別のLLMへ渡す連鎖実験、モデル変更、thinking有効化、英語化、提示順変更、独立材料の追加は次の候補棚へ置く。
