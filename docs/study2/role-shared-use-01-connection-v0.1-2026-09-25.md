# ROLE-SHARED-USE-01：Colab一セル版の使い方と接続準備

2026-09-25／v0.1。ユーザーの設計承認を受け、固定した128入力を実行するコードを準備した。**オフライン検証済み、実GPUでのモデル実行は未実施。**

## 使い方

1. ColabでGPUランタイムを選ぶ。前回と同じA100 80GB、またはRTX PRO 6000 Blackwell級を想定している。
2. **[Readable code and current instructions](../../experiments/RU01/generation/README.md)の全文を、Colabのコードセル一つに貼り付けて実行する。** 設定の手編集、過去ZIPのアップロード、Drive接続は不要。
3. 終了時に自動ダウンロードされる **`npp-ru01-result-日時-識別子.zip`** を保管し、そのままこの会話へ返す。

自動ダウンロードを開始できなかった場合は、Colab左側のファイル欄から `/content/npp-ru01-result-*.zip` をダウンロードする。途中の誤答やJSON形式不備は記録して続行する。OOMなどの実行例外や時間上限に達した場合も、その時点の結果とログを最終ZIPへまとめる。

同じランタイムでセルをもう一度押すと、既存記録を再照合してZIPを返す。**追加生成は行わない。** 実行中のロックが残っている場合は重複実行を止め、状況をログへ残す。再クリックを残りの再実行には使わない。

32回答ごとに途中ZIPをColab一時領域 `/content/npp_ru01_runs/` へ保存する。途中ZIPは自動ダウンロードせず、必要ならファイル欄から回収できる。ランタイム自体が破棄されると、未回収の記録は失われる。

モデル・トークナイザーはHugging Faceの固定revision、Python依存はPyPIから取得する。Driveの認証・同期、データの公開・アップロードは行わない。GPU条件を満たさないときはモデル取得・ロードより前に停止する。ローカルPCではColab判定がML import・通信より前に止める。

45分は停止上限で、完走時間の予測ではない。モデル取得・ロードも含む。回答の原文は上限を超えても切り詰めず保存し、採点では未確定とする。裸JSONと既知の完全なjsonコードフェンスだけを扱い、犬猫・観測値・キーを修正しない。

## 確認したこと

**接続テスト28件が初回通過。** 固定入力・seed・条件順、元保存物との対応、全128件を共用せず生成する経路、JSON外装の限定除去、誤答を直さない案内計算、形式不備後の続行、非EOS・中断・生成失敗・準備失敗・入力長超過、二度押しの追加生成防止、ZIP照合を点検した。単独の一セルファイルがColab外で通信・ML importより前に止まること、埋込みだけで作業フォルダに依存せず動くことも確認した。

さらに、実ファイルを保存する合成3経路を走らせ、ZIPからの再集計を照合した。

| 合成経路 | 保存した回答 | 照合内容 |
| --- | ---: | --- |
| 全件正常 | 128 | 全16ペア成立、原回答・案内・集計が一致 |
| 誤答・形式不備・非EOSを混在 | 128 | 不備後も続行。15成立・1未確定、既知の誤答は成分表に保持 |
| 8回目に生成例外 | 7 | 8回目は生成失敗、残り120件は未実施として保存。追加生成なし |

これらは接続検証のための合成回答で、LLMの実験成績には含めない。合計263保存回答の成分判定と案内を、別の照合手順で入力・原文から再計数した。途中ZIP計8個、最終ZIP3個の照合も通過した。元保存・結果64ファイルは元ZIPとbyte一致、旧資料167アンカーを保持した。
