# ROLE-SHARED-USE-01：本人の仕事と共同の仕事を、同じノートから使い分ける

2026-09-25／設計v0.1。略号RU01。既存保存物、4条件の128入力、指示、採点、停止基準を固定し、オフライン検証を完了した。Colab実行器の接続と実モデル生成は次工程。

**二人が共有する案内は揃えつつ、担当客の希望に応じた犬猫の絵柄は別々に選べるか。さらに、本人の希望だけを変えれば本人の選択だけ、共有する観測だけを変えれば共同の案内だけが変わるか。**

[SX01](../../experiments/SX01/docs/self-update-exchange-01-result-2026-09-25.md)では、本人更新→交換→古い通知を経た全16ペアの保存と共同読出しが成立した。今回は、その最終ノートから本人情報も使う段階へ進む。更新・交換は回し直さない。

## 1. 比較する4条件

二人とも同じ共同状況を知り、Aの担当客は犬、Bの担当客は猫を希望し、共同の案内はデジタルになる、という例で考える。

| 条件 | ノートで変えるもの | Aの絵柄 | Bの絵柄 | 二人の共同案内 |
| --- | --- | --- | --- | --- |
| 元のまま P0G0 | なし | 犬 | 猫 | デジタル |
| 本人の希望だけ P1G0 | 犬猫を反転 | 猫 | 犬 | デジタルのまま |
| 観測だけ P0G1 | 紙とデジタルの観測を交換 | 犬のまま | 猫のまま | 紙 |
| 両方 P1G1 | 希望と観測をそれぞれ反転 | 猫 | 犬 | 紙 |

実際にはAが猫の材料、元の案内が紙の材料も均等に使う。同じ場面・役名・版・元IDでも、条件によって正解が変わる。「Aだから犬」や元の回答を繰り返す方法では、全条件を通過できない。

**共同情報を変えるときは、個別ノートにある同じ観測の写しも一緒に変える。** GROUPだけを書き換えると、PRIVATE内の本人観測との矛盾が別の問題になるためである。今回の操作は「観測内容」の変更で、GROUPという保存場所だけの効果を測るものではない。

## 2. 実保存32冊をどう使うか

SX01の全8材料×2反復×2役、計32冊の最終保存ノートを使う。成功例だけを抜き出す再選別は行わず、全件を元ZIPの保存ファイル・結果hashへ結び付けた。元の状態を初期資料や正解表から作り直す処理はない。

各ノートから4つの入力を作る。元のまま条件は保存内容を保持し、対照枝はコピーに対して以下だけを操作する。

- **本人希望：** `PRIVATE.customer.animal` のDOGとCATを入れ替える。
- **観測：** GROUPのA/B両行とPRIVATEの本人観測で、paperとdigitalの値を入れ替える。

人物、subject、observer、元ID、revision、場面、資料名は固定する。入力には自分の担当客と、二人分の共同観測を載せ、相手の担当客情報は渡さない。両役を同じ条件に置くと、担当客の希望は異なり、共同観測は一致する。

対照枝は**研究者が内容を操作した仮想入力**である。実際の新通知や更新ではなく、同じ元IDの観測内容を書き換えているので、元観測の忠実な複製とも区別する。原保存物を保持し、派生枝ごとの変更パス・前後hashを記録する。枝どうしを一つの履歴へ混ぜず、この試験では元ID・版の再引用は測らない。

元の二反復の保存内容は一致しており、32冊は内容としては16種類だった。4条件化した入力は64種類で、それぞれ新しい回答を2回得る。**8材料×2役×4条件×2反復＝128回答**であり、独立した材料数は8である。

各役の各保存物について4条件を同じseedで対応させ、別役・反復ではseedを変える。条件はどの提示位置にも8回ずつ来るよう配置した。全回答は別コンテキストで生成し、同一入力でも二反復を省略・共用しない。条件名・反復・正解・操作履歴はモデルに渡さない。

## 3. LLMとコードが担当すること

LLMには、一つの回答で次の二つを求める。

1. PRIVATEの担当客の `subject` と `animal`。animalをそのまま本人向けカードの絵柄とする。
2. GROUPのA/Bそれぞれのpaperとdigital、計四値。

回答の形は次のとおり。値は実際の入力に従う。

```json
{
  "customer": {"subject": "A", "animal": "DOG"},
  "coverage": {
    "A": {"paper": "ALL", "digital": "ALL"},
    "B": {"paper": "NOT_ALL", "digital": "ALL"}
  }
}
```

共同案内は、**実回答の四値だけから**既存の規則で計算する。二人とも使える媒体がちょうど一つなら紙またはデジタル、0個・2個ならUNKNOWN。正しい四値や正しい犬猫へ回答を補正する処理は置かない。

今回の本人向け選択は、返されたanimalを使う回答上の選択である。実際のカード送信や外部操作は行わない。自由な理由文・LLMによる直接の案内計算・出典再引用も増やさず、まず本人情報と共同情報を同時に取り出して使えるかに集中する。

元のまま条件も、この新しい同時回答の指示で取り直す。SX01の共同のみREADは背景資料として保持し、新しい指示の同時対照にはしない。

## 4. 指標と、合格できない回答

| 評価 | 何を見るか | 予定分母 |
| --- | --- | ---: |
| 本人の利用 | 担当subjectと犬猫が入力に合う | 各条件32回答 |
| 共同の利用 | 四値がGROUPに合い、その実値からの案内も合う | 各条件32回答 |
| 同時成立 | 本人・共同の両方が成立 | 各条件32回答 |
| 本人希望への応答 | 希望反転で犬猫だけ変わり、共同四値は変わらない | 64対応比較 |
| 観測への応答 | 観測反転で四値と案内が所定どおり変わり、犬猫は変わらない | 64対応比較 |
| 二役の適切な違い・一致 | 異なる希望へ別の犬猫を選び、同じ共同情報から同じ案内を得る | 64条件ペア |
| **全条件での二役の両立** | A/B×4条件の8回答がすべて成立 | **16ペア実行** |

主指標は最後の行。案内が偶然正しくても四値が違えば不成立、犬猫が合っていてもsubjectが違えば不成立とする。「出力が変わった／変わらなかった」という記述と、両端が正しく目的どおりに変化したかの診断を分ける。

二役の8回答がすべて構造成立したペア実行を、成立／不成立に判定する。構造・取得欠測が一つでもあれば主値は未確定。既に分かった内容不備は成分表へ残す。全予定16を分母に、欠測を全不成立／全成立に置いた上下限も併記する。

固定目安は **14/16以上、かつ各反復7/8以上**。

- **MET：** 判明した成立だけで両条件を満たす。
- **NOT_MET：** 未確定をすべて成立としても、どちらかに届かない。
- **INCONCLUSIVE：** 未確定の扱いで目安の判定が変わる。

この目安は次工程へ進むための工学的基準。p値・母集団CIは出さず、条件・役・反復や64対応比較を独立材料として加算しない。全4条件のANDだけでなく、元のまま条件の同時成立と各成分を示し、基礎的な読出しの不備と操作への応答不備を区別する。

予想は、二つの情報の用途を分ける指示と既存の案内計算の下で、この目安に届くこと。役名だけで答える、本人の希望変更を無視する、共同観測の変更を無視する、といった回答は合成点検で主指標を通過しなかった。

## 5. 実行案と閉じ方

| 項目 | 固定した案 |
| --- | --- |
| 新規生成 | 後続利用128回答のみ。更新・交換の再生成0 |
| 時間 | 準備込み45分、末尾90秒を終了処理用に確保 |
| 再生成・停止 | 自動再生成0。不成立は記録して独立入力を続行。実行例外・時間上限で到達点を保存して閉じる |
| モデル | Qwen/Qwen3.5-27B、revision `fc05daec18b0a78c049392ed2e771dde82bdf654` |
| 設定 | BF16・SDPA・non-thinking・batch1、temperature 0.7、top_p 0.8、top_k 20、repetition_penalty 1.0 |
| 長さ・環境 | 入力8192／出力2048tokens、原文4096bytes、transformers 5.17.0・accelerate 1.15.0 |
| 受け口 | 裸JSONを受理。既知の完全なjsonフェンスだけを除去し、値・型・キーは修復しない |
| 回収 | 次工程でDriveなし・全文1セル・設定編集／旧ZIPアップロード不要・終了ZIP自動DLへ接続 |
| 保管・費用 | 非公開・削除期限なし。既存Colab枠、有料API・新規購入0 |

新しい回答形式の所要時間は未実測。45分は停止上限で、速度の保証ではない。入力は全部固定できるため、前の応答が不成立でも別の応答へ依存欠測を広げる必要はない。

128回答で結果にかかわらず閉じる。METなら「同じ更新・交換経路の後で、本人と共同の両方を利用できた」と整理し、もう一巡の継続性を次候補にする。不成立なら本人／共同の読出し、形式、役の取り違え、各内容操作への応答を一度診断する。望む差が出るまで反復を足さない。

比較しているのは既知保存物の機能と、そこから作った入力成分の操作である。新しい履歴形成、矛盾する情報の裁定、長期共存、元IDの後続利用は別の試験として残す。

## 6. 固定資料とオフライン検証

**32テストが初回通過。** 原保存物の保持、32冊の全件利用、変更範囲、同じ観測の写しの整合、役・犬猫・案内の配置、反復と条件順、正解や条件名の非提示、厳密JSONと外装除去、誤答を直さない採点、欠測と目安の三分岐を点検した。

保存付きの合成5パターンでは、全正答が16/16・MET、役名だけの推測／本人変更の無視／観測変更の無視はそれぞれ0/16・NOT_MET、全欠測は16未確定・INCONCLUSIVE。これらは採点器の検証で、実モデルの成績には含めない。

別照合では、元ZIPと保存・結果64ファイルがbyte一致し、128入力の内容変更が指定範囲に収まることを確認した。入力64種類×二反復、役×犬猫×案内の8配置が各16回答になること、実回答だけから個別選択と案内を導出することも検算した。ローカルモデル取得・ロード・新しいLLM生成は0。
