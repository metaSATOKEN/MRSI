# SELF-UPDATE-EXCHANGE-01 — Colab一セル版の使い方・接続準備

2026-09-25／v0.1。ユーザーの設計承認を受け、[固定設計](../../experiments/SX01/docs/self-update-exchange-01-plan-v0.1-2026-09-25.md)を実行コードへ接続した。**コード全文をColabのGPUランタイムの1セルへ貼り付ければ実行できる。設定編集・Drive接続・過去ZIPアップロードは不要。**

## 使い方

1. [Readable code and current instructions](../../experiments/SX01/generation/README.md)を開き、全文をコピーする。
2. ColabのGPUランタイム（A100 80GBまたはRTX PRO 6000 Blackwell級）で、コードセル一つへ貼り付けて実行する。
3. 最後にダウンロードされる **`npp-sx01-result-日時-ID.zip`** を保管し、このタスクへ返す。

初期設定のままで研究バッチを開始する。`RUN_MAIN`等の手編集は不要。自動ダウンロードがブラウザに止められた場合は、Colab左側のファイル欄から `/content/npp-sx01-result-*.zip` をダウンロードする。

所要時間の目安は前回と同じBlackwellで生成のみ約24分という粗い換算。**準備込み90分が停止上限**で、GPU・入力長・モデル取得状況によって実時間は変わる。ローカルPCでの実行は不要で、Colab以外では通信・ML importより前に停止する。

## このセルで実行すること

新規8ペア×2反復×2役で、本人更新→実保存観測行の交換→古い通知→読出しを一巡する。共同／本人とも人物別最新版を選んで行全体を複製する構成を固定し、担当客の犬猫希望はモデルの記述を保持する。

| 項目 | 上限・動き |
| --- | --- |
| 生成 | UPDATE96＋READ32＝最大128回答、自動再生成0 |
| 入力 | 初回32入力を固定。後続96入力は実保存物から組立て |
| 時間 | 環境準備込み90分、末尾90秒を終了処理用に確保 |
| 中間保存 | 2ペア実行（最大16回答）を処理するごとに途中ZIP |
| 形式・意味不成立 | 理由と原回答を残し、独立したペアを続行 |
| 実行例外・時間上限 | 到達点を保存し、残りを未実施／依存欠測として閉じる |
| 最終回収 | 集計・照合・終了ZIPの自動ダウンロード |
| 再クリック | 同じ保存先があれば追加生成・環境準備なしで再照合してZIPを返す |
| 保管 | 非公開・削除期限なし。Drive接続なし、既存Colab枠、有料API・新規購入0 |

モデルはQwen/Qwen3.5-27Bの固定revision、BF16・SDPA・non-thinking、samplingあり。生成設定・指示・schema・既知JSONフェンスだけの正規化・採点規則は承認済み設計のまま。実際に動いたGPU・ライブラリ版・tokenizer・生成設定をZIPに記録する。

Colabの一時領域 `/content/npp_sx01_runs/self-update-exchange-01-v01/` に保存する。途中ZIPは同じ親フォルダに作り、終了ZIPを `/content` へ出す。ランタイム破棄で未回収ファイルは消えるため、終了ZIPを手元へ保存する。別ランタイムでの途中生成再開は実装していない。

## ノートの交換と欠測の扱い

①のA/B両方が終わってから②へ進む。交換するのは、相手の①の保存ファイルから読み戻した本人観測一行。自分のノートも自分の実保存ファイルから読み戻し、相手の担当客情報や正解ノートを再配布しない。

保存物のhash・親の結果hash・転送した欄と行hashを、実入力へ結び付けて記録する。候補の検査はLLMへ渡す前にも行い、人物・版・候補の対応が契約に合わなければ当該応答を保留する。

- ①の片方が保存不能なら、そのペアの②は双方とも依存欠測。その後も依存先だけを閉じ、別ペアは続行する。
- ②以降の片方が保存不能でも、依存関係のない相手側は続行する。
- 内容が間違っていても構造成立した保存物は、誤りを含めて後続へ渡す。担当客の誤記を正解で補修しない。
- 開始記録はあるが回答がないものは `INTERRUPTED_UNCERTAIN` として閉じ、同じ応答を再生成しない。

JSON正規化と行の置換は別記録。裸の正常JSONはバイト不変、既知の完全なコードフェンスだけ外側12bytesを除去する。原文・正規化後文・適用規則・前後hashを保持する。値・IDの補修や欠落補完は行わない。

## オフラインで確認したこと

**接続30テストが初回通過した。** 設計で固定した純粋関数は構文木一致で切り出し、前回の生成backend、保存処理、正規化器はバイト一致。環境準備の主要7関数も前回と構文木一致である。

主な確認範囲は、実保存物からの次入力、相手観測だけの転送、原文と正規化文、担当客不備の残留、形式不備後の依存欠測と他ペアの継続、停止・長さ上限・例外、保存物や入力の改変検知、ZIP再集計、プロジェクトフォルダなしでの埋込みコード読込み。模擬の一セル実行では、2回目のクリックで環境準備・生成が増えないことを確認した。

保存付き合成経路2本も監査フォルダへ残した。

| 合成経路 | 合成生成 | 全経路の成立 | 確認したこと |
| --- | ---: | ---: | --- |
| 古いノートをそのまま記述する応答 | 128 | 16/16 | 保存器が公開入力の新通知から更新し、保存・交換・遅配・読出しへ接続 |
| Aの担当客の元IDを①で誤記 | 128 | 0/16 | 担当客の誤りが3保存段階と実READ入力へ残る。共同判断だけの正答で成功にしない |

別照合では各経路の96更新保存物、32READ、親からの128対応辺、32転送行を直接比較した。各ZIPは1360ファイルで、固定コードによる再集計は保存時の報告と一致。再照合前後で原証拠のhashが変わらないことも確認した。これらは**合成回答による接続試験**で、実モデルの成績に合算しない。

実際のモデル取得・ロード・GPU生成は、今回ローカルでは行っていない。Colab実機の可否と研究成績は返送ZIPで確認する。
