# SELF-UPDATE-EXCHANGE-01：自分を更新し、相手の更新を受け取る

2026-09-25／設計v0.1。略号SX01。材料・指示・処理・採点・割付を固定し、オフライン点検を完了。Colabの実行コードは次の接続準備で作成する。

**二人それぞれが自分の新情報でノートを更新し、保存した観測行を交換する。その後に古い通知が届いても、本人情報と共同状態を保ち、次の案内に使えるか。** 今回はこの一連の流れを測る。

[OR01](../../experiments/OR01/docs/owner-recency-01-result-2026-09-25.md)では、共同だけの処理で案内は36/36正答だったが、本人ノートに旧版が4件残った。両方を処理すると全工程36/36が成立した。ただし、本人の観測は最初から最新版だった。SX01は**本人の内容も実際に変わる材料**へ進む。

## 1. 四つの段階

各段階は同じLLMをA/B二役の別コンテキストで実行する。引き継ぐのは実際に保存したノートで、過去の会話全文は再掲しない。

| 段階 | 二人が受け取るもの | 確かめること |
| --- | --- | --- |
| ① 本人更新 SELF | 自分の初期ノート＋自分への新通知 | 本人欄と共同ノート内の本人行を更新し、相手の既知情報・担当客の希望を保つ |
| ② 交換 EXCHANGE | 自分が①で保存したノート＋相手が①で保存した本人観測行 | 相手の新情報を共同ノートへ取り込み、自分の新情報を保つ |
| ③ 遅配 DELAY | 自分が②で保存したノート＋古い通知 | 新しい本人・共同状態を巻き戻さない |
| ④ 読出し READ | 自分が③で保存した個別・共同ノート | 共同A/Bの四値を転記し、その実回答から案内を計算する |

①はA/B双方が終わってから②へ進む。②で渡すのは**相手が実際に保存した `private_note.coverage` 一行**。相手の担当客の希望や初期資料一式は渡さない。後段で研究者が新しい正解ノートを再配布する処理を置かず、保存した誤りや欠測も追跡する。

③の古い通知だけは、事前に固定した初期観測の再配達である。現在のノートを初期状態へ置き換える操作はしない。

## 2. 今回固定する構成

OR01で成立した**共同・本人の両方ON（G1P1）**だけを使う。各UPDATEでLLMに一つの更新案を書かせ、次の処理を行う。

1. 対象人物の候補だけを集める。本人欄ならholder、共同欄ならA/Bそれぞれ。
2. その人物の数値revisionが最大の行を選ぶ。
3. 人物・観測値・版・元出典IDを行全体で複製する。

担当客の人物・犬猫希望・元出典は、今回もLLMが書いた案を保存する。JSONの既知フェンス除去、候補と元資料の対応検査、同版矛盾時の保留、同内容の重複候補の選択規則はOR01から維持する。UPDATEとREADの指示・schema・モデル設定も同一。

比較条件を増やさず、**成立した構成を新しい連続課題へ接続する試験**にする。各回の機械処理前の案も採点・保存し、どの行を直したかを示す。その原案は、処理OFFで何周も運転した対照群ではない。

人物・版・候補が明確な入力の下で、ON欄の正しさは保存器の性質である。予想は「この保存器を実回答に接続し、未処理の担当客情報・形式・交換・読出しまで含む経路が固定目安に届く」。モデル単独の記憶能力の向上を主張するための比較ではない。

## 3. 新しい8ペアと二反復

元回答を選び直さず、今回のために8つの合成ペア資料を作った。場面・観測行・版・元ID・初期から新状態への遷移を固定した。48個の元IDは新規で、OR01のIDと重複しない。「新しい材料」は今回の資料が未使用という意味であり、犬猫・紙／デジタルという課題や有限の値の組合せは引き続き使う。

| 配置の軸 | 値 | ペア数 |
| --- | --- | ---: |
| 最初→交換後の案内 | 紙→デジタル／デジタル→紙 | 各4 |
| 最後に遅れて届く通知 | 本人の旧観測／相手の旧観測 | 各4 |
| 数字上の版番号が大きい人物 | A／B | 各4 |

三つの二値の全8組合せを使い、各ペアでA/B双方を実行する。二人の犬猫希望は異なる。版番号は人物間で大きく離し、低い側の新しい版も相手の古い版より小さくする。これで「A/Bを混ぜて最大版を一つ選ぶ」方法では正しく保存できない。

**すべての役で、本人への新通知により紙／デジタルの少なくとも一値が変わる。** 値・版・元IDを変えるため、最初の本人ノートを保持し続けるだけでは失敗する。本人だけ更新した①では共同案内がUNKNOWNとなり、二人の新情報が揃う②で新しい案内が成立する材料にした。

8配置は小さな網羅点検用で、場面・値配置・犬猫希望等を独立した因果要因として推定しない。独立した材料は8ペア、二反復で16ペア実行。役や段階を独立Nとして足さない。

### 具体例

ある紙→デジタルの材料では、Aの観測が「紙ALL・デジタルNOT_ALL」から「両方ALL」へ、Bが「両方ALL」から「紙NOT_ALL・デジタルALL」へ変わる。

①では各自が自分の変化だけを知り、相手の欄にはまだ古い行が残る。②で二人の実保存行を交換すると、どちらの共同ノートにも最新のA/Bが揃い、デジタルの案内になる。③で古い「紙が使える」という通知が届いても、版を人物ごとに比べて新しい状態を維持する。

①の採点は、その時点で本人に渡した情報に照らして行う。**まだ知らせていない相手の新観測を、①で書けなかったことは誤りにしない。**

## 4. 引継ぎを成立させる契約

初回32入力だけを事前に固定し、後続96入力は実保存物から作る。

- ②は自分と相手の①の保存物を必要とする。受け取った相手行のobserverと送信役の対応を検査し、取り違えは保留する。
- ③は自分の②だけ、④は自分の③だけを必要とする。他役の同段階の回答を勝手に加えない。
- 入力の候補一覧は、その時点で渡すPRIVATE・GROUP・通知の4行から構成する。過去の正解表から補充しない。
- 構造成立した内容不一致はそのまま後続へ渡す。同人物・同版で内容が矛盾する場合等は、既定の入力契約エラーで保留する。
- 本人・相手のどちらかの①が保存不能なら、そのペアの②は双方とも依存欠測になる。他のペアは続行する。②以降で片側が止まった場合、依存関係のない相手側は続行する。

原回答、正規化文、機械処理前後、選んだ元行、保存ファイル、実際の次入力、親の応答ID・hashを別々に残す。後続に渡すのは保存後に読み戻したファイルとする。このファイル接続は次のColab実装工程で検証する。

交換時の検査は、役と保存ファイルの対応を管理する実験上の契約。観測内容の真偽を暗号署名等で認証する仕組みまでは含めない。

## 5. 評価するもの

| 段階 | 主な成分評価 | 予定分母 |
| --- | --- | ---: |
| 本人更新 | 本人観測の更新、既知の相手行保持、担当客保持、保存全欄一致 | 32役回答 |
| 交換 | 本人の新行保持、相手の新行取込み、双方の出典、担当客保持、保存全欄一致 | 32役回答 |
| 遅配 | 本人／共同の巻戻り、担当客保持、保存全欄一致 | 32役回答 |
| 読出し | 実保存四値への忠実性、最新状態に合う案内 | 32役回答 |
| 二役の全経路 | A/Bの全3保存段階と両READがすべて成立 | **16ペア実行** |

保存一致は、値だけでなく人物・版・元IDまで含む。原案の不備と保存器が置換した行、保存後に残る不備を分ける。READの案内は実際にモデルが抽出した四値だけから決定論的に計算する。本人情報の評価は各段階の保存欄で行い、本人の元IDを後続で再引用させる課題は追加しない。

主指標は二役の全経路。必要な8回答がすべて構造成立した場合に、成分のANDで成立／不成立を判定する。構造・依存欠測が一つでもあれば、そのペア実行の主指標は未確定。既に判明した内容不備は成分表に残す。予定分母16を保持し、成立・不成立・未確定と、欠測をすべて不成立／成立に置いた割合の上下限を表示する。

固定目安は**全経路14/16以上、かつ各反復7/8以上**。これは約9割の経路が成立することを求める工学的目安である。

- **MET**：判明した成立だけで両条件を満たす。
- **NOT_MET**：未確定をすべて成立としても、どちらかに届かない。
- **INCONCLUSIVE**：未確定の扱いで目安の判定が変わる。

反復・方向・遅配の相手・版の大小別も併記する。p値・母集団CIは出さない。14/16は一般的な信頼性の保証や対照方式への優越性ではなく、次に検討する構成を選ぶ基準として使う。

## 7. 閉じ方と次の判断

固定した16ペア実行で閉じ、結果を見ながら段階・反復を増やさない。

| 結果 | 次の判断 |
| --- | --- |
| MET | 本人更新と相手更新の持寄りを含む構成が成立したとしてチェックポイントを整理。次はもう一巡の交換か、本人記録を使う後続課題を比較検討 |
| NOT_MET | 形式、未処理の担当客情報、保存器の入力契約、交換接続、読出しのどこに不備が残ったかを一度診断 |
| INCONCLUSIVE | 実行・依存欠測を記録し、取得経路の対処を先に検討。欠けた内容を正解で補って成功にしない |

保留するもの：方式の4条件比較（構成の役割を再分解する必要が出た時）、所有者／版比較の単独要因化（誤りの型を分ける必要が出た時）、曖昧な版や矛盾した通知（明確な契約での連続更新を確認した後）、自由な態度形成や長期共存（保存・更新の足場を点検した後）。今回の本人情報は、明示的に割り当てた担当客と役固有の観測である。

## 8. 準備の検証と次工程

**26テストが初回通過。** 本人の実質的な変化、未知の相手情報の非注入、保存した相手行の利用、欠測時の初期化禁止、遅配、同版矛盾、候補偽装、担当客の誤りが残ること、READの入力、目安の三分岐を点検した。
