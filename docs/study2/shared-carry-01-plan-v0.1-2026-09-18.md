# SHARED-CARRY-01 — 各自のノートと共同ノートを、次の仕事でも使えるか

2026-09-18｜設計草案 v0.1｜**DESIGN_OFFLINE_CHECKED_NOT_DISPATCH_READY**

ユーザーの「本丸の個体と群の両立に戻り、設計パートを進める」という了承を具体化した。今回の範囲は設計・合成点検・記帳。実行器への接続、認証疎通、モデルへの送信は行っていない。

**二人が各自の観測からノートを作り、共有できる観測を持ち寄って共同ノートを編集する。その保存物だけで次回も、各自の担当に合う判断と、皆のための判断を両立できるかを調べる。** 形成16回答＋確認48回答＝通常64要求の小試験案。

## 1. 超文系向けの実験イメージ

Aは犬を希望するお客さん、Bは猫を希望するお客さんを担当している。また、AとBはそれぞれ、自分が担当する人たちに紙の案内・デジタル案内が届いたかを知っている。

まず二人が別々に自分のノートを残す。次に、案内の届き方だけを共有し、一人が共同ノートを下書き、もう一人が一度だけ確認・編集する。担当客の犬猫の希望は、各自のノートに残す。

次回、元の受付票をもう一度配ることはせず、保存したノートを使って仕事をしてもらう。

| 次回に渡すもの | 確かめたいこと | 正しく作成されたノートなら期待する回答 |
| --- | --- | --- |
| **個別＋共同（BOTH）** | 共同情報を使いながら、自分の担当情報も使えるか | 自分の担当客に合う犬／猫と、皆に届く案内方法を選べる |
| 個別のみ（PRIVATE） | 共同ノートを足す前の本人側の基準 | 担当客の犬／猫は分かる。相手の担当範囲は分からないので、全体の案内は保留 |
| 共同のみ（SHARED） | 共同ノートの役割と、個別情報がない場合の反応 | 全体の案内は分かる。自分の担当客の希望は分からないので、犬／猫は保留 |

例えば両方を渡したとき、Aは犬、Bは猫を用意し、二人とも紙で案内すると判断できれば、「違いを使い分けながら協力する」最小の形になる。紙かデジタルかという共通判断の一致は、個体性を失った証拠にはしない。

犬猫は**担当客の希望**であり、AI自身の好みや人格ではない。この課題で測るのは、個体性の入口となる「役ごとに異なる有効な情報が、共有後も判断に働くか」。自己の価値観が自然に育つことや、集団圧力への抵抗は別の課題である。

## 2. ここまでから加える一段と、残す支援

前回チェックポイント (see the evidence index)を受けた設計。IS02では部分観測の交換後に共通判断が成立したが、次回にも原観測を配り直していた。記憶系列では生成メモの保存・再投入を試したが、直近のMR系列は役ごとの保持・更新が中心だった。

今回は、その二つをつなぐ。**研究者が完成した共同記録を毎回配る支援を外し、役たちの生成物から作った共同記録を次回へ渡す。** 記憶の所在はローカルに保存したJSONと、それを参照する次の入力で追跡する。モデル内部の永続記憶を仮定しない。

固定欄、著者表示、直接参照名、案内方法を決める規則、二人の編集順は残す。何を共有するかも研究者が決める。今回は自律的な記憶選択・自由会話・自然発生する組織の試験ではなく、明示した手順で個別と共同の記録を作って持ち越す能力の確認である。

## 3. 材料と初期条件

地域工作会の持帰り袋、小さな展示会の受付名札という2題材に反転2設定を置く。4組ともA/Bの二役。犬猫・紙／デジタルの課題構造は既使用系列と同系統であり、新しい4集団の無作為標本や新領域への一般化とは扱わない。

| 組 | 題材 | Aの担当客 | Bの担当客 | 全員に届いた方法 | 他方の方法の未達を観測する役 | 下書き→編集 |
| --- | --- | --- | --- | --- | --- | --- |
| G01 | 工作会 | 犬 | 猫 | 紙 | A | A→B |
| G02 | 工作会 | 猫 | 犬 | デジタル | B | A→B |
| G03 | 展示会 | 猫 | 犬 | デジタル | A | B→A |
| G04 | 展示会 | 犬 | 猫 | 紙 | B | B→A |

各役は、自分の担当客の予約票と、自分の担当範囲の案内到達の観測票だけを最初に受け取る。参加者は二役の担当範囲で尽くされ、重なりはない。正答・他役の予約票・他役の原観測は初回に見せない。

群全体の案内は、**A/Bの両担当範囲で全員に届いたと確認できる唯一の方法**を選ぶ。片方しか分からない、どちらも成立しない、二方法とも成立する場合はUNKNOWN。材料には一意な正答があるが、その保証はモデルへ教えない。片方の観測から「きっとこちらが正解」と推測するだけでは、規則上の十分な根拠にならない。

各役・犬猫・紙／デジタル、下書き担当の犬猫、未達観測者の犬猫は全体で釣合いを取る。4組で全要因を直交させてはいない。例えば下書き役と題材が対応しており、著者順や題材の個別効果を推定する設計ではない。

## 4. 16回答で記録を形成する

| 段階 | 入力 | 出力 | 通常要求数 |
| --- | --- | --- | ---: |
| ENCODE | 自分の予約票＋自分の原観測 | 個別ノート：担当客の希望、担当範囲の観測、各原票ID | 8 |
| DRAFT | 両役の生成個別ノートから取り出した観測部分のみ | 共同ノートの下書き：両役の観測、推奨案内、観測の来歴ID | 4 |
| EDIT | 同じ観測部分＋相手の下書き | 一度だけ確認・編集した最終共同ノート | 4 |

同一段階を閉じてから次へ進む。下書き担当と編集担当は別の役。毎回新しい文脈で、必要な保存物を明示的に渡す。編集後に下書き担当へ再確認する往復はないので、「全員が最終版に合意した」とは呼ばない。二人の部分観測と順番に行う共同編集からできた保存物、と記述する。

共有する観測は、LLMが生成した個別ノートの`coverage`部分を決定論的に抜き出す。担当客の希望の`customer`部分は共有入力へ入れない。**抜き出しは情報の共有範囲を決める操作であり、真値に合わせる訂正ではない。** 誤った観測や人物・原票IDでも、形式が有効ならそのまま渡す。

運転側が付ける外側の著者は、実際にその生成要求を出した役。ノート内部の「誰を観測したか」はLLMの記録内容として別に残す。この二つが食い違う場合も、ノートを望ましい内容へ書き換えない。

### 形成Fは「次へ進むための成功選抜」にしない

F_g=1は、両役の個別ノートが全欄正確で、最終共同ノートの両観測・推奨案内・来歴がすべて正確な場合。下書きの誤りが提供資料に基づく一度の編集で直った場合は、修正として記録し、Fの失敗にはしない。下書き・最終版・変更箇所はともに保存する。

形式が正常ならF=0でも、予定した全条件の確認へ進む。F=0の組を除外・差替えたり、正しい共同ノートができるまで編集を繰り返したりしない。全組が観測可能でF=0ならNO_JOINT_FORMATION、少なくとも一組が成立すればOBSERVED_JOINT_FORMATION、成立の有無が欠測で決まらなければINCONCLUSIVE_FORMATIONを別記する。

## 5. 同じ保存物から3条件の次回確認を作る

同じ組の同じ個別・最終共同ノートをBOTH/PRIVATE/SHAREDへ振り分ける。BOTHとPRIVATEの個別ノートは同一、BOTHとSHAREDの共同ノートも同一。条件名や他条件の回答、形成の採点結果はモデルへ渡さない。見える記録の違い自体を隠す盲検ではない。

次回の希望・到達条件は変えない。元の予約票・原観測、下書き、編集履歴、過去の確認回答は再掲しない。共同ノートには共有された観測内容が残っている。これは元の原票を運転側から再投入したものではなく、LLMが残した観測の記録である。

4組×2役×3条件×同入力2反復＝48回答。第1波24枠は固定seedと条件順の巡回で配置、第2波はその逆順。同じ組・役・条件の2反復は同じ入力bytesになる。反復は別の呼出しで、後の回答へ前の回答は渡さない。したがって「二回連続の仕事を継続できた」とは数えない。

BOTH−PRIVATEは、共同ノートを足したときの担当情報の保持と共同判断を比べる。ただし、相手範囲の観測情報も増える。差が出ても、共同編集に固有の効果や、同じ情報量での共同ノートの優位とは言わない。今回の目的は保存・再利用の機能確認。情報量を揃えた事実一覧や無交流条件は、機序を問う次の別設計の候補に残す。

## 6. 出力と根拠の扱い

自由理由は要求せず、固定JSONを使う。生成の操作ツールは渡さない構成を、接続準備で既存経路へ結び直す。今回のオフライン組立器には送信・認証機能がない。

| 段階 | 必須の内容 |
| --- | --- |
| 個別ノート | `customer`＝subject/animal/source_id、`coverage`＝observer/paper/digital/source_id |
| 共同ノート | A/B各自の`coverage`、`channel`、`channel_sources`（二つの原観測ID。UNKNOWNなら空） |
| 次回確認 | `mascot`、`mascot_sources`、`channel`、`channel_sources` |

次回確認のsourcesには、**今回直接読んだ記録名PRIVATE/GROUP**を記入する。ノート内部の原票IDは来歴であり、この直接参照名と区別する。MCHAIN01で直接参照名と来歴IDがずれた経験を受け、指示・例・検査を一緒に固定した。旧出力を新基準で再採点しない。

本人の特定選択にはPRIVATEの担当客記録、全体の特定選択にはGROUPの両範囲の観測が必要。その記録の内容が選択と整合し、人物・来歴も真値と一致するかを点検する。単に存在するIDを挙げただけでは十分としない。共同判断にGROUPとPRIVATEを両方引用した場合、PRIVATEの観測も同じ正しい自分範囲の観測なら許容する。共同ノートの誤った推奨を、正しい観測から読み直して訂正した回答は選択・引用の成功になり得るが、保存ノートの不備はFで残る。

UNKNOWNは有効回答。対応sourcesは空配列を求める。情報が欠ける対照条件での妥当な保留を、人格の消失や故障と呼ばない。sources準拠率にはUNKNOWN＋空配列も含むため、それだけで積極的な情報利用が成立したとは解釈せず、特定選択一致と併記する。

重複キー、JSON外の文、余分なトップキー、型や必須欄不備を検知する。次回確認は選択・出所を成分別に読む。出所欄だけ不正なら正しい選択を失わず、選択欄だけ不正なら他の欄を失わない。UNKNOWN以外の未知ID、重複引用、誤人物・誤値は形式が有効なら意味上の不備として保持する。原文の意味・形式を直す再送はしない。

## 7. 指標と先に置く予想

これは既存結果を見た後に設計した新しい試験。予想は設計時カード (see the evidence index)に、合成点検コードを書く前に保存した。

| 指標 | 固定する意味 |
| --- | --- |
| F | 正確な個別・最終共同ノートが形成された組数／予定4組 |
| I_c / G_c | 条件cで担当客／全体案内の特定選択が世界設定と一致する割合。各16回答 |
| J_VALUE,grc | 組g・反復r・条件cで両役の両選択が正しい |
| J_SOURCE,grc | J_VALUEに加え、両役の両選択で十分な直接根拠が成立 |
| **主E_BOTH** | **(1/8)Σ_gΣ_r F_g×J_SOURCE,gr,BOTH**。正確な保存物の形成から次回の両立まで通った割合 |
| E_VALUE | 主指標の引用条件を外した値。選択不備と引用不備を分ける |
| L＝I_BOTH−I_PRIVATE | 共同ノートを加えたとき、本人側の選択一致が低下するか |
| A＝G_BOTH−G_PRIVATE | 共同ノートを加えたとき、全体向けの選択が増えるか |
| BOTH両反復成立 | 両役・両反復でJ_SOURCEが成立した組数／4。反復を独立群扱いしないための補助表示 |

主予想はF=4/4、E_BOTH=1。副予想はL=0、A=1、PRIVATEの共同UNKNOWNとSHAREDの本人UNKNOWNが各16/16。I/GではUNKNOWNを特定選択一致0と数え、別の保留率で妥当性を示す。SHARED/PRIVATEのJが0でも、そのことだけで両条件が故障したとは言わない。

**主予想の判定**は、欠測下限E=1ならMET_IN_FIXED_SAMPLE、上限E<1ならNOT_MET_IN_FIXED_SAMPLE、それ以外はINCONCLUSIVE。途中の既知の不備があれば、別の欠測や後の正答で消さない。完走そのものを予想成立にしない。

例えば「共同ノートの案内だけ誤り、次回はノート内の観測を読み直して正答」なら、Jは成立してもFが0となり、主Eではその組が未達になる。逆に下書きの誤りを予定した編集で修正し、その最終記録を使って正答したなら、一連の成立と数える。何を保存し、どこで直ったかを分ける。

4組・2題材という小さな記述試験であり、64回答や8組反復を独立集団Nにしない。p値・同等性・非劣性の認定は行わない。世界の真値がある合成課題なので決定論的に照合でき、今回は採点LLMを増やさない。出所IDの一致から内部で実際に参照した経路までは断定しない。

## 8. 欠測と依存・停止

形式が有効な誤記・UNKNOWNはそのまま後続へ渡す。初期ノート・下書き・編集の構造不備だけが、組内の依存停止を起こす。

| 構造不備が生じた場所 | 依存未発行にする枠 |
| --- | --- |
| 一方のENCODE | 同組の下書き1＋編集1＋全条件確認12＝14枠 |
| DRAFT | 同組の編集1＋全条件確認12＝13枠 |
| EDIT | 同組の全条件確認12枠 |
| PROBE | その回答の不備成分だけ未知。他の予定枠を続ける |

比較元が揃わない組は、PRIVATEだけを特別に走らせることはしない。この制約を取得前に固定し、他組は続ける。停止した組も分母4に残す。入力形成不成立と、形式は成立したが意味上の予想が外れたケースを区別する。

欠測・未取得・依存未発行はUNKNOWNや0に置換せず、未知成分として扱う。FとJの結合では既知の0があれば0、全部1なら1、それ以外は[0,1]。同じFを同じ組の両反復で共有し、予定分母でEの下限・上限を出す。L/Aは条件別の下限−対照上限、上限−対照下限で表示する。これは欠測による範囲であり信頼区間ではない。

部分応答、timeout、未知の輸送失敗、保存・封印・入力整合性異常は全体停止。意味/形式の修復再送、群の追加・差替え、結果を見た会話延長は行わない。空の明示的な混雑応答だけに、下記の有限再送案を用いる。

## 10. オフライン点検と設計中の修正

20テスト、17の合成ケース、保存入力と主指標の別実装470照合がPASS。正常例に加え、誤った個別ノート、編集で直る下書き、最終ノートの誤りを正答で隠す例、誤帰属、来歴IDと直接参照名の混同、成分欠測、JSON重複キー、依存停止、既知不備と別組欠測の混在を点検した。

| PRIVATEは正確、BOTHで本人側が低下 | 共同ノート追加と低下が生じた場所を保存物・実入力で確認。即「同一化」とせず、配置・内容・引用のどこに差があるかを整理 |
| ノート形成が不成立 | 個別の符号化、共有への受渡し、下書き、編集のどこで崩れたかを区別。望むノートができるまで延長しない |
| 判断は合うが保存・出所が不適合 | 主Eの未達として残し、選択だけの成功と分ける |
| 欠測で結論が定まらない | 取得上の未確定として閉じ、再送・再試験は別判断 |

価値観の自発形成、個別情報を共有へどこまで載せるかの自律判断、反証イベント、長期化、多人数化、情報量を揃えた無交流対照は、対応する問いを次の優先対象に選んだ時の候補とする。今回の結果を見て同じ枠内へ継ぎ足さない。
