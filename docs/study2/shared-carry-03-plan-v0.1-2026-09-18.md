# SHARED-CARRY-03：書式を揃えた共同ノートで、本人情報と群の判断を両立する

2026-09-18 / v0.1 / **設計・オフライン点検済み、接続準備前**

**自分の担当客を取り違えず、みんなのための判断にも共同ノートを使えるか。** 前回止まった受け口の書式を明確にして、この問いへ戻る48回答の小試験。

Aは犬の絵柄を希望する客、Bは猫の絵柄を希望する客を担当する。各自が、自分の担当情報と、自分の範囲で紙・デジタルが使えるかをノートに残す。観測部分だけ持ち寄って共同ノートを作り、次の仕事で「自分の客の絵柄」と「全員に使える案内方法」を両方選ぶ。

比較するのは、**自分のノート＋共同ノート**と、**自分のノートだけ**。共同情報を足すことで全体判断が可能になり、同時に本人担当情報の利用が落ちないかを見る。

## 1. 前回から変えること

[SC02](shared-carry-02-results-v0.1-2026-09-18.md)は、初期8ノートは正確だったが、共同下書き4件が配列/objectの不一致で構造欠測となり、後続36枠を発行しなかった。主Eは[0,1]で評価不能のまま保存する。

[CODEC-01](shared-note-codec-01-local-v0.1-2026-09-18.md)で用意した候補指示と変換器を、新しい試験へ組み込む。

| 項目 | SC03で固定する扱い |
| --- | --- |
| DRAFT/EDITの指示 | coverageはA/B固定キーのobjectと明記し、共通スキーマを添える。CODEC-01候補指示と同じbytes |
| DRAFT/EDITの受け口 | 明示observerがA/B各1件の二件配列だけ、値を変えずobjectへ変換。その後に固定parserで検査 |
| ENCODE/PROBEの指示・parser | SC02から変更しない |
| 材料・順序・条件・主/副採点 | SC02から維持。実験IDのみSC03へ変更 |
| 生成ノート | 初回から全て新規生成。旧SC02の8成功ノートや4下書きを流用しない |

今回測るのは、**明示した書式と変換器を含むシステムの共同形成・次回利用**。SC02との数値差を改善効果として推定せず、指示追記と変換器のどちらが効いたかも単独では判定しない。形式だけの追加実測は挟まず、合成点検を済ませた受け口を本来の小課題で確認する。

## 2. 固定する48回答

| 段階 | 渡す情報・作業 | 回答数 |
| --- | --- | ---: |
| ENCODE | 自分の原票から個別ノートを作る | 8 |
| DRAFT | 両役の生成観測欄だけから共同下書きを作る | 4 |
| EDIT | 相方が同じ観測欄と下書きを見て、一度だけ確認・編集 | 4 |
| PROBE・BOTH | 自分の個別ノート＋同じ最終共同ノートから次回判断 | 16 |
| PROBE・PRIVATE | 自分の個別ノートだけから次回判断 | 16 |
| 合計 | **初回8＋生成ノートに依存する後続40** | **48** |

4組×2役、次回判断のみ同じ入力で2反復。全呼出しは新規context。下書きと編集の担当は半数ずつ入れ替える。最終共同ノートは管理側が同じ版を両役に提示する。

| 組 | 場面 | Aの客／Bの客 | Aの紙・デジタル | Bの紙・デジタル | 全体正解 | 下書き→編集 |
| --- | --- | --- | --- | --- | --- | --- |
| G01 | 地域工作会・持帰り袋 | DOG／CAT | ALL・NOT_ALL | ALL・ALL | PAPER | A→B |
| G02 | 地域工作会・持帰り袋 | CAT／DOG | ALL・ALL | NOT_ALL・ALL | DIGITAL | A→B |
| G03 | 小さな展示会・受付名札 | CAT／DOG | NOT_ALL・ALL | ALL・ALL | DIGITAL | B→A |
| G04 | 小さな展示会・受付名札 | DOG／CAT | ALL・ALL | ALL・NOT_ALL | PAPER | B→A |

A/Bの範囲で参加者全体を尽くし、重複はない。両範囲でALLと確認できる唯一の方法を選び、確定できる方法がゼロか二つならUNKNOWN。PRIVATEだけでは相手の範囲が見えないので、全体案内はUNKNOWNが適切。

元の原票はENCODEでだけ提示する。その後は生成ノートから投影し、共同作業には客の犬猫情報を送らない。BOTH/PRIVATEは同じ生成個別ノート・同じ役・同じ判断指示を使い、BOTHにGROUPだけ追加する。旧材料と同じ2題材なので、新場面への一般化試験ではない。

## 3. 原文から次の入力までの契約

```text
原応答を保存
  → DRAFT/EDITだけ固定codecへ
  → 原文・処理結果・受理文・hash・対応を保存
  → strict parserで読取り
  → 受理したノートの必要部分を投影
  → 親との一致を照合して次の入力を保存・送信
```

今回はこの流れのオフライン関数と合成点検まで。実ファイル保存・取得器への接続は次工程。接続時には、原文や変換記録を保存できない、親との照合が合わない、という場合に後続を送らないようにする。

変換規則は既存の`shared-note-codec-v1`を固定する。二件配列にobserver=A/Bが一つずつ明記されている場合だけ、配列順によらず対応づける。欠落・重複・曖昧な対応は拒否。人物・観測値・元ID・判断・参照配列の値と順序は変えない。特定の組、ID、正解にだけ合わせる例外は設けない。

元からobjectの場合の誤帰属や、UNKNOWN、参照重複などは、固定構造が読めればそのまま引き継いで意味採点へ回す。codecで内容を正解に直さない。モデルによる一度のEDITは全組で予定した研究工程として実行できるが、追加の補修再送はしない。

保存するcodec情報は、原文・受理文、両hash、codec版、schema hash、処理区分、変更path、元位置とA/Bの対応、拒否理由。**変換したというフラグ、検査エラー、研究者の正解は後続LLMへ追加しない。** 受理したノートの内容だけを、実際に作った役をauthorとして渡す。

## 4. 書式の成績を別に報告する

共同出力はDRAFT4＋EDIT4＝予定8枠を全て一覧に残す。

| 区分 | 意味 |
| --- | --- |
| NATIVE | 元から固定書式に適合し、原文のまま受理 |
| NORMALIZED | 事前に固定した一種類の変換で受理 |
| REJECTED | 本文は受領したが、変換規則・固定構造で受理できない |
| NO_RESPONSE | 本文を受領していない。通信・時間上限等の理由は取得記録で別記 |
| DEPENDENCY_UNISSUED | 親の構造欠測により未発行 |

NATIVE/NORMALIZED/REJECTEDの割合は**本文受領数＝この三つの合計**を分母とし、DRAFT・EDIT別と合計で報告する。受領0なら割合はnull。必ず予定分母4/4/8に対する全区分の件数と受領coverageも添える。未受領・未発行をcodecの拒否と混ぜない。

NATIVEだけの群を選んで主成績を出すことはしない。変換済みノートを読んだ後続回答を使って、「変換器がなかった場合」のEも計算しない。書式が通った割合と、内容・本人情報・共同判断の成立は別の観測である。

## 5. 主判定・予想・感度分析

SC02と同じ定義を、今回実際に受理・提示するノートへ適用する。

- **F_g**：その組の二枚の個別ノートと最終共同ノートが、値・人物・元ID・直接参照・元根拠IDまで全て正しい。下書きの意味誤りは、予定した一度のEDITで直ればよい。
- **J_g,r**：BOTH条件の反復rで、A/B両役の次回6欄が正しく、実際に渡した資料も回答を支える。
- **E_BOTH**：4組×2反復の8枠で、`F_g AND J_g,r`が成立する割合。予想はF=4/4、E_BOTH=1。各組で両反復とも成立したかも併記する。

Eの下限1なら`MET_IN_FIXED_SAMPLE`、上限1未満なら`NOT_MET_IN_FIXED_SAMPLE`、残りは`INCONCLUSIVE`。有限標本での予想答え合わせであり、一般性能の合格保証ではない。全共同回答がNORMALIZEDでも内容と利用が正しければ主Eは成立し得るし、全てNATIVEでも意味が誤っていれば成立しない。

| 補助指標 | 内容・予想 |
| --- | --- |
| I_BOTH / I_PRIVATE | 本人担当客の絵柄正答率、各16枠 |
| L＝I_BOTH−I_PRIVATE | 共同ノート追加による本人情報利用の変化。予想0 |
| G_BOTH / G_PRIVATE | 世界の正しい全体案内を選んだ割合、各16枠 |
| A＝G_BOTH−G_PRIVATE | 共同情報を足したときの全体判断の変化。予想+1 |
| PRIVATEのUNKNOWN率・6欄遵守・資料支持 | 情報不足への適切な保留と、根拠なしの偶然正解を区別 |
| E_NOREF | 共同判断の根拠2欄と次回回答の根拠を免除する事前感度分析 |

E_NOREFでも、個別ノート全体と、共同coverageのobserver/origin_idは免除しない。主Eを置換しない。選択だけ正解、ノートだけ正解、片方の役だけ正解では主Eの成立にしない。

形成の補助分岐は、F=Trueの組が一つ以上なら`OBSERVED_JOINT_FORMATION`、全4組Falseなら`NO_JOINT_FORMATION`、その他`INCONCLUSIVE`。一組の成立と、全4組の予想達成は区別する。

## 6. 欠測と有限な終点

構造が利用できない場合だけ依存先を止める。ENCODE一件なら同組の後続10枠、DRAFTなら9枠、EDITなら8枠。PROBEのBOTH/PRIVATEとも同じ両ENCODEとEDITを親とする。意味誤りやUNKNOWNだけを理由に組を落とさない。

予定全4組・条件別16回答・主8枠を分母に残す。True/False/不明の三値で、ANDは既知Falseを優先。不明を失敗/成功に置いた上下限を併記し、観測済みの誤答と区別する。上下限は信頼区間ではなく、p値は出さない。48回答や同入力2反復を48の独立場面として数えない。

割付seedは2026091807のまま。ENCODE→DRAFT→EDITの各段階内をshuffleし、各段階を閉じて次へ進む。PROBEは8組役対のBOTH先/PRIVATE先を4対ずつ、反復2は反復1の逆順。同じ組・役・条件の二反復は送信bytesを一致させる。

**結果の符号にかかわらず、固定一巡で閉じる。** 成功するまで追加N、会話延長、形式/意味の書直し再送、変換規則の途中改訂をしない。

## 8. 終了後に何を決めるか

主予想を満たして本人情報の利用と共同判断が両立したら、共同状態の更新・配送へ進む次設計の候補とする。未達なら初期記録／共同形成／出典／次回利用の発生箇所をオフラインで一度整理し、次の変更を一つ選ぶ。評価不能なら取得・形式の不足を整理する。どの枝でも今回の追加Nはしない。

SU01で残ったUPDATE余分キーとRECEIVEの過去直接参照コピーは、今回扱わず、解決済みにしない。大規模HS02も保留継続。

この短い課題でいう「本人情報」は担当客の情報であり、犬猫はモデル自身の人格・好みではない。生成メモの保管と提示は管理側が担う。自律的な長期記憶、自然発生した合意、長期の同一化・硬直化回避、長期共存全体は未検証として残す。
