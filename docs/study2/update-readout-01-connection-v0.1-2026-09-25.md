# UPDATE-READOUT-01：Colabの1セル版・使い方

2026-09-25／接続準備v0.1。承認済みの[設計](../../experiments/UR01/docs/update-readout-01-plan-v0.1-2026-09-25.md)を実装した。**設定編集・Drive接続・過去ZIPのアップロードは不要。**

## 使い方

[Readable code and current instructions](../../experiments/UR01/generation/README.md) の**全文**を、ColabのGPUランタイムの1セルへ貼り付けて実行する。A100 80GBまたはRTX PRO 6000 Blackwell級を想定し、モデル取得前にVRAM・空きVRAM・BF16対応を確認する。

1. 固定資料・採点器の人工回答点検、GPU点検、専用Python環境の準備を行う。
2. 更新72回答と、その実保存ノートを読む最大72回答を生成する。合計最大144回答、準備込み90分。回答の不成立を理由に独立系列を止めない。
3. 終了時に **`npp-ur01-result-日時-識別子.zip`** を自動ダウンロードする。このZIPを保管して返す。

自動ダウンロードがブラウザに止められたら、Colab左側のファイル欄から表示された `/content/npp-ur01-result-…zip` を取得する。APIキー・Drive認証・別セルは不要。

## 更新して、実際に保存したものを読む

| 工程 | 本文再記述（REWRITE） | 行選択＋複製（SELECT） |
| --- | --- | --- |
| UPDATE | 個別ノートと共同A/B行をモデルが記述 | 個別ノートを記述し、共同A/B行は候補位置C1〜C4から選ぶ |
| 保存 | 形式が成立した実回答を保存 | 選んだ原行を、人物・値・版・出典ごと機械複製して保存 |
| READ | 当該系列の実保存ノートを読む | 当該系列の実保存ノートを読む |
| 案内計算 | 実回答の四値から機械計算 | 実回答の四値から機械計算 |

READの指示・schemaはSVR01と同一。更新時の通知・候補一覧・正解・採点はREADへ再注入しない。各呼出しは新規コンテキストで、別方式や別反復の回答も渡さない。

**古い行や誤出典でも、形式が成立していれば保存してREADへ渡す。** 保存器が最新版を代わりに選ぶことはない。更新がJSON・型・enum等で不成立なら、そのノートを作らず、その系列のREADだけを `DEPENDENCY_MISSING` として記録する。他のUPDATEは続行する。原文の修復・候補位置への自動変換・意味修正の再生成は行わない。

更新で本人情報と共同観測を保てたか、読出しが実保存物に忠実か、最新の状況に合うかを別々に集計する。更新全体と後続までの完全一致を両方報告し、修復と巻戻り防止、反復、保持役、通知先、通知位置、元保存方式、材料別の内訳を残す。全予定系列を分母にした成績と、保存できた系列だけの補助成績を併記する。報告JSONの `read_input_count` は構造検査を通った保存物の数であり、実生成数は `performance` と `attempted_generations` で区別する。

## 原回答から後続入力までの照合

各UPDATEに、入力messages・token列、原回答・出力token列、seed、終了理由、時間、採点を保存する。構造成立時は実回答から作った `saved-memory.json` と、複製位置・元行hash・コピー先を含む `selection-trace.json` を保存する。REWRITEの複製履歴は空配列として方式を明記する。

READの `input.json` は、渡した実ノートと親UPDATEの結果hash・保存物hashを結ぶ。原回答から保存物を再構成し、後続messagesとの一致まで照合する。案内計算は `derived-decision.json` に原回答hash・実抽出四値・計算結果を残す。採点器が知る正解は、保存や案内計算の関数へ渡さない。

返送ZIPには固定資料・割付・コード・原回答・保存物・集計・環境情報・hash一覧が入る。`requests.json` は取得前に固定したUPDATE72件だけで、READ本文は親の実保存物から実行時に構成する。ローカル照合ではZIP内コードを実行せず、配布時に固定した採点器で再集計する。

## 途中保存・停止・再クリック

24・48・72・96・120・144の**予定応答の処理完了時点**で、`/content/npp_ur01_runs/` に途中ZIPを作る。この数には依存欠測も含まれ、実際の生成数とは異なる。途中で操作を求めず、終了ZIPのみ自動ダウンロードする。

- **誤答・形式不備・長さ打切り**：原文と成績を残し、依存関係に沿って次へ進む。
- **時間上限・利用者の停止・OOM等の実行例外**：回収済み回答を保持し、残りを未実行／依存欠測として閉じる。開始済みで回答を回収できなかった呼出しは `INTERRUPTED_UNCERTAIN` と区別する。
- **同じランタイムでセルを再実行**：既存記録を再照合してZIPを返す。追加生成・環境再構築・モデル再ロードは行わない。

途中ZIPを新ランタイムに戻して生成を再開する機能は設けていない。停止した場合はそのZIPを返して次を判断する。実行ロックが残る場合は重複生成せず止まる。ランタイム自体が破棄されると、未ダウンロードの一時記録は失われる。
