# SELF-UPDATE-EXCHANGE-02：もう一巡しても、本人と共同の仕事を両立できるか

2026-09-25／設計v0.1。略号SX02。材料・処理・採点・上限を固定し、オフライン点検を完了した。Colab一セル版の接続と実モデル生成は次工程。

**各自の担当客の希望を保ち、二人それぞれの新情報を取り込み、共同の案内を更新する。この一連の仕事を、前回の保存ノートからもう一巡できるか。**

[RU01](../../RU01/docs/role-shared-use-01-result-2026-09-25.md)では、本人の犬猫と共同の案内を全128回答で使い分けた。今回は、その使い分けが次の更新・交換を経ても続くかを測る。既知の材料と実保存ノートから一巡先へ進む継続試験である。

## 1. 一巡の流れ

| 工程 | 渡すもの | 確かめること |
| --- | --- | --- |
| ① 自分を更新 | 前回保存した本人のノート＋本人の新しい観測通知 | 担当客の希望を保ち、自分の観測を最新版にする |
| ② 相手と交換 | ①で自分が保存したノート＋相手が実際に保存した観測の一行 | 自分の新情報を守り、相手の新情報も取り込む |
| ③ 古い通知が届く | ②の保存ノート＋前回版の観測通知 | 到着順に引かれて古い状態へ戻らない |
| ④ 二つの仕事に使う | ③で保存した本人・共同ノート | 担当客の犬猫と、新しい共同案内を同時に使い分ける |

①〜③では各回のノートを保存し、その実保存物を次へ渡す。交換するのは相手の観測一行だけで、担当客情報は各役の個別ノートに置く。④ではRU01と同じ指示・回答形式を使う。

**後続入力へ本人の正解情報を差し戻さない。** 誤った担当客を書いて保存した場合も、その実保存物を次へ渡し、どこで不備が生じ、利用へ持ち越されたかを評価する。保存不能なら依存する後続を欠測として記録する。

## 2. 基点と新しい通知

基点は[SX01](../../SX01/docs/self-update-exchange-01-result-2026-09-25.md)の最終保存ノート32冊。8材料×二反復×二役を全件使う。RU01は読出し専用だったため、次のノートの起点はこの実保存物になる。元ファイルと結果ファイルのhashを結び付け、保存内容をそのまま固定した。

新通知は研究者が設計する架空の次時点観測。各人の版を一つ進め、新しい元IDを付ける。**二人とも観測内容が変わり、正しい共同案内も前回から反転する。**

例えば、前回は次の状態だったとする。

| 観測者 | 前回：紙 | 前回：デジタル | 次の通知：紙 | 次の通知：デジタル |
| --- | --- | --- | --- | --- |
| A | 全員使える | 全員使える | 全員使える | 全員は使えない |
| B | 全員は使えない | 全員使える | 全員使える | 全員使える |

共同案内は「デジタル」から「紙」へ変わる。一方、担当客の犬猫の希望は引き継ぐ。案内だけを前回どおり答える方法では成立しない。

実材料では紙→デジタル・デジタル→紙を各4材料、遅れて来る通知が本人のもの・相手のものを各4材料にする。人物間で版番号の大小が異なる配置も保持する。版は各人の中で比較する。

古い通知には基点の実観測行を使う。既存行を書き換える操作は行わず、元の保存物と、新しい版・元IDを持つ通知を分ける。32保存ファイルは内容として16種類であり、同じ8材料の二反復を新しい生成で進める。

## 3. 今回固定する分担

保存処理は前回と同じ構成を使う。LLMが記述したノートを検査し、観測は**誰の行かを先に分け、その人の最新版を行ごと複製**する。担当客の欄はLLMの記述を残す。

最後の回答もRU01と同じで、LLMが本人subject・犬猫と共同A/Bの紙・デジタル四値を返す。絵柄は回答された犬猫をそのまま使い、案内は実回答の四値からコードで計算する。

保存前のLLM原案と、保存処理後のノートは別々に採点する。処理が補った箇所と、モデルが正しく書けた箇所を区別できるようにする。UPDATEの指示・schemaはSX01、READの指示・schemaはRU01から変更しない。

今回は保存方式の比較枝やRU01の4条件操作を追加せず、一つの継続経路に集中する。担当客の希望自体の更新や矛盾する通知は別の検証候補に置く。

## 4. 何を満たせば成立か

| 評価対象 | 判定内容 | 予定分母 |
| --- | --- | ---: |
| 保存前の原案 | 担当客、本人観測、相手・共同観測が各工程の期待状態に合うか | 96更新 |
| 実際の保存ノート | 人物・値・元ID・版を含め、同じ項目が正しく引き継がれたか | 96保存 |
| 最後の本人利用 | 正しい担当客のsubject・犬猫を使ったか | 32回答 |
| 最後の共同利用 | 四値が最新の観測に合い、実四値からの案内が正しいか | 32回答 |
| 二役の両立 | 担当客ごとに犬猫が異なり、新しい共同案内が一致するか | 16ペア |
| **全工程成立** | A/B×4工程の8応答がすべて成立したか | **16経路** |

読出しでは、**「受け取ったノートに忠実だったか」と「今回の正しい状態に合っていたか」を分ける。** 古いノートをそのまま読めた場合には忠実性を記録し、全工程成功にはしない。最終案内が偶然合っていても、四値や本人情報の不一致を残す。

主指標の目安は **14/16以上、かつ各反復7/8以上**。

- **MET：** 判明した成立だけで両条件を満たす。
- **NOT_MET：** 未確定をすべて成立としても、どちらかに届かない。
- **INCONCLUSIVE：** 未確定の扱いで判定が変わる。

構造・取得欠測がある経路は主値を未確定とし、既知の意味不一致は成分表に残す。予定16を分母に欠測上下限を示す。独立材料は8であり、反復・役・工程を独立標本として足さない。p値・母集団CIは今回算出しない。

予想は、前回の保存構成と同時利用の指示を継承して、目安に届くこと。主な反証候補は、担当客情報の書き違いの蓄積、本人と相手の新観測の取りこぼし、古い通知への巻戻り、正しい保存物からの読出し不一致である。

## 5. 規模と閉じ方

**8材料×二反復×二役×4工程＝最大128回答**。更新96、最後の同時利用32。初回32入力を固定し、後続最大96入力はその実保存物から組む。

| 項目 | 固定案 |
| --- | --- |
| 上限 | 最大128生成、準備込み60分、末尾90秒を終了処理へ確保 |
| 再生成 | 自動再生成0。意味不一致も実保存物を次へ渡す |
| 欠測・停止 | 保存不能は依存先を欠測とし、独立経路を続行。実行例外・OOM・時間上限で記録して閉鎖 |
| モデル | Qwen/Qwen3.5-27B、revision `fc05daec18b0a78c049392ed2e771dde82bdf654` |
| 設定 | BF16・SDPA・non-thinking・batch1、temperature 0.7、top_p 0.8、top_k 20、repetition_penalty 1.0 |
| 長さ・環境 | 入力8192／出力2048tokens、UPDATE原文16384／READ4096bytes、transformers 5.17.0・accelerate 1.15.0 |
| JSON | 裸JSON、または既知の完全なjsonフェンスのみ受理。外装以外の構文・内容修復なし |
| 回収 | 次工程でDriveなし・全文一セル・設定編集／過去ZIPアップロード不要・終了ZIP自動DLに接続 |
| 保管・費用 | 非公開・削除期限なし。既存Colab枠、新規購入・有料API0 |

過去のBlackwell実行では同規模のSX01が約24分48秒だった。今回は60分を停止上限にするが、GPUや取得・ロード時間によって完走時間は変わる。

予定した一巡で結果によらず閉じる。METなら二巡の継続と本人・共同利用をチェックポイントにまとめる。不成立なら保存・読出し・形式・実行系を一度診断する。結果を見てそのまま三巡目へ伸ばす運用にはしない。

## 6. オフライン検証と固定資料

**24テストが初回通過。** 元32保存物、両役の内容変更・新版・新元ID、案内の反転、人物別の版比較、実保存行の交換、本人情報の非補修、古いノートへの忠実性と正答の分離、依存欠測、JSON受け口、目安の三分岐を確認した。

保存物をファイルから読み戻す合成5経路も照合した。

| 合成入力・回答 | 全工程成立 | 判定 |
| --- | --- | --- |
| 原案は現在ノートのまま、観測は既定の保存処理で更新 | 16成立 | MET |
| 途中でAの担当客の犬猫を書き違える | 16不成立 | NOT_MET |
| 保存は正しいが、最後に前回の共同観測を答える | 16不成立 | NOT_MET |
| 最初の1更新だけ構文不正 | 15成立・1未確定 | MET |
| 全初回更新が構文不正 | 16未確定 | INCONCLUSIVE |

最初の合成例が通るのは、既定のコードが観測行を更新するためであり、LLMが自力で最新版を選べた証拠にはしない。後二例では、欠測した依存先だけが止まることを確認した。これらは設計・採点の検証で、実モデルの成績ではない。
