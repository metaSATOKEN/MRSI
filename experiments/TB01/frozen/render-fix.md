# TB01 実装訂正 v0.1.1 — 入力末尾改行の誤検出

2026-10-13、実モデル回答の取得前の修正。ユーザーの返送ZIPはモデルロード成功後、最初のFORMの入力検査で停止。生成開始0・回答0。元の記録はINCONCLUSIVEのまま別保管する。

返送された `preparation-observed.json` は、system文末の改行一文字を除いて意図した文を保持し、userのJSONを完全に保持している。固定tokenizerの整形結果は各messageの前後をstripしたrole区切り文字列と完全一致。旧検査は未整形のsystem全文を部分文字列検索したため、末尾改行を内容改変として誤検出した。

変更は次の四点。

1. 検査を、固定されたsystem/user二messageの前後空白処理とrole区切りを含む**整形後全文の完全一致**へ変更する。本文中の文字・数値・改行、role、順序、余分なmessageの変更は拒否する。
2. モデルロード前に固定revisionの実tokenizerでFORM/VOTE/READの126予定形を検査する。後続用の親は合成fixtureで、研究回答として保存・使用しない。生成時には実回答由来の入力を再び検査する。chat templateのSHA-256を初回実測値に固定する。
3. 合成backendにもrole区切りと同じ前後空白処理を反映し、返送された実整形入力を回帰fixtureに加える。
4. Colab保存先を `three-role-boundary-01-v011` に分け、旧v01と旧配布payloadを保持する。旧v01に生成開始/回答があれば追加生成を拒否する。同じv011の再クリックは従来どおり照合・回収のみ。モデルキャッシュ・成功済み環境を再利用する。

材料、指示文、schema、本人集計、候補、順序、seed、モデルrevision・生成設定、採点、最大126回答・45分上限は変更しない。旧設計と取得前規則はbyte単位で保持する。採点に使えるモデル出力を見てからの変更ではない。
