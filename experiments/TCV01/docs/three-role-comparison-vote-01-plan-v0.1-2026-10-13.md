# TCV01 — 共同案の比較と投票を分けて書くと、判断を使い分けられるか

THREE-ROLE-COMPARISON-VOTE-01、2026-10-13。

**本人の判断を保ったまま、共同案の高低を正しく比較し、その比較に沿って投票できるかを測る。** 前回と同じ18入力を使い、従来方式と比較欄を追加する方式を新しく並べる。

## 1. 今回の問い

前回TVR01は本人情報54/54に対して投票52/54だった。Cは90対84の90案を一度保留し、Aは76対83の76案を一度承認した。本人欄はどちらも正しい。

今回は、最終票だけでは見えなかった「提示候補を高いと書いたか、低いと書いたか」を記録する。

| 条件 | モデルが書く欄 | 元入力との違い |
|---|---|---|
| DIRECT：従来方式 | 本人情報 → 投票 | 元の指示・schemaを維持 |
| COMPARE：比較欄あり | 本人情報 → **共同候補の高低比較** → 投票 | 比較欄の指示とschemaを追加 |

本人ノート、経験資料、候補表、計算済み合計、候補順は同じ。正しい高低ラベルや投票をホスト側で追加することはしない。前回の正誤を次のモデルへ教えない。

比較欄は次の三項目。値の具体例は配布promptへ入れず、両案に使える定義を渡す。

| 項目 | 意味 |
|---|---|
| `candidate_id` | 今回提示された候補 |
| `other_candidate_id` | 比較相手のもう一つの候補 |
| `relation` | 三人分の合計でHIGHERかLOWERか |

本人推奨と共同担当は違ってよいという前回の契約を維持する。比較欄も票も生成されたまま保存し、原経験から計算した正解と照合する。

## 2. 何を分けて観察できるか

| 比較欄 | 投票 | 出力上で分かること |
|---|---|---|
| 適切 | 適切 | 比較と票が両方成立 |
| 適切 | 不適切 | 高低は正しく記録したが、票が対応しなかった |
| 不適切 | 適切 | 票だけでは比較欄の誤りを見落とす |
| 不適切 | 不適切 | 比較と票の両方に不備。誤った比較に沿う票かも別点検 |

候補IDを取り違えた比較、形式不備・未実行はさらに分ける。「比較と票が一貫している」と「正答である」は別集計にする。

両方式の主比較は、共通の本人三項目＋投票が全部適切だった数。比較欄を含む全成立は追加条件側の診断として別に出す。形式成立には各条件のschemaを使うため、追加欄の形式負担も条件差に含まれる。比較欄は観測できる出力であり、内的な思考過程を説明する資料にはしない。

## 3. 固定する規模

**18入力×2条件×3反復＝108回答。** 3材料、A/B/C、高低両案をすべて残す。揺れた2入力だけを優遇しない。

各入力・反復の二条件を同じ新seedで対応させ、先に動かす条件を各反復9対ずつに均等化する。対応対の順も取得前に固定する。生成文が変わるため、同seedでも二条件の乱数消費が同一になるとは限らない。

モデルと生成設定は前回と同じQwen3.5-27B、BF16、SDPA、non-thinking、temperature0.7。既存の18入力は研究内の既使用材料であり、未使用材料への一般化は今回の対象にしない。旧TVR01成績は背景に置き、今回のDIRECTも新しい54回答を取る。

一セル・Driveなし・旧ZIP不要。準備込み30分、108生成上限、再生成0。キャッシュがある同程度のGPUなら12〜20分程度を仮目安とする。形式不備・誤答でも他入力を続行し、例外・OOM・時間切れは記録を回収する。

## 4. 終了後の判断

対応54対の共通成立を、両成立・従来のみ・比較欄のみ・両不成立・未確定に分ける。差の方向と、本人保持・誤保留・誤承認・比較欄の内訳を合わせて読む。3反復の違いも残し、旧結果と合算しない。欠測があれば全対を分母に上下限で示す。

比較欄で共通成績が増える予想を置くが、両方式とも全件成立した場合は差未確認とする。改善・悪化・差なしのいずれでも一巡で閉じる。全件成立の運転ゲートと方式差の方向は別で、ゲートFAILでも方式差の内訳を残す。

今回の結果を受けて比較の取り違え、票への対応、本人保持のどこを次に扱うか判断する。新しい票を後続の合意・実行へ渡す実験や、遅着票・新版・新経験はまだ追加しない。
