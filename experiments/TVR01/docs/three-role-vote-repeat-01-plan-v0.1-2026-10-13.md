# 三者の投票判断は、同じ入力でどのくらい揺れるか

THREE-ROLE-VOTE-REPEAT-01（TVR01）、2026-10-13。

**TB01で一回だけ出た「よい共同案を保留する」応答が、固定入力の新しい三反復でも現れるかを確かめる。** 全役・高低両案を残して18入力×3回＝54回答にする。前回動いた読込み・生成・受け口・保存を引き継ぐ。

## 1. 同じ答案用紙で、投票だけを繰り返す

前回は全体90点の案をCが一度保留し、同じ入力の二回目では承認した。本人のデジタル推奨は両回とも正しく、後続三人も実際の票に従っていた。今回は「本人ノートを新しく作ったから票が変わる」という要素を増やさず、前回投票時に渡したノートを固定する。

| 項目 | 今回の固定範囲 |
|---|---|
| 材料 | TB01の全3材料 |
| 役 | A/B/Cの全3役 |
| 提示案 | 高合計と低合計の両方 |
| 入力の種類 | **18種類**。旧反復1を採用し、旧反復2との入力同一性も照合 |
| 新しい反復 | **各3回、計54回答** |
| 変えるもの | 生成seedと測定順。モデルへの文章・JSONは変更0 |
| 主に見ること | 本人保持、適切な承認／保留、入力ごとの揺れ |

今回の入力は、前回の実message・整形prompt・token列まで照合して固定する。本人形成と後続読出しは再生成しない。旧票や新しい反復の票を次の回答へ教えない。T02/Cだけに試行数を多く配ることもしない。

## 2. 何が分かるか

高合計案にはACCEPT、低合計案にはHOLDが課題の正答。本人の持ち主・推奨・根拠IDも同時に保持する。

| 新3回の結果 | 今回書けること |
|---|---|
| 3回とも適切 | この固定入力では新3回すべて適切だった |
| 適切と不適切が混ざる | 同一入力の判断変動を再観測した |
| 3回とも不適切 | この固定入力の不成立が新3回でも続いた |
| 一部が形式不備・未実行 | 確認できた誤りと未確定を分け、三回の安定性は未確定 |

「三回とも同じ票」と「三回とも正しい票」は別に数える。本人情報だけが壊れた場合も、投票の誤りと分ける。前回2回の結果は背景として別表へ置き、新3回へ合算しない。

全54回答が全軸適切なら `PASS_IN_FIXED_REPEAT`、解釈可能な意味不成立があれば `FAIL`、欠測等が残れば `INCONCLUSIVE`。どの結果でも追加せず閉じる。反復数から一般的成功確率を推定する規模ではなく、全体合意の成否も今回は測らない。

## 3. 規模と運転

Qwen3.5-27B、固定revision、BF16・non-thinking、温度0.7など前回設定を維持する。モデルロード前に実tokenizerで旧入力との一致を確認。生成は54回、準備込み上限30分。

TB01の同stageの生成時間を基に接続報告で目安を示す。GPU、Hub取得、混雑で時間は変わる。同じランタイムなら重みcacheを使え、旧ZIPのアップロードとDrive接続は不要。ローカルマシンではモデルをロードしない。

形式不備や誤答は保存して次の入力へ進む。OOM・実行例外・時間上限はログを回収して終了。自動再試行0。終了時にZIPを自動ダウンロードし、返送後に照合する。

## 4. 次の判断

入力ごとの揺れが分かったところで、共同案の確認手順を変える必要があるか、遅れた票や案の版変更へ進めるかを決める。今回の反復だけで「自己優先が原因」といった機序を決めない。方針変更・自由会話・多数決・長期共存は別の設計に残す。
