# 第2報の関連研究調査：更新・帰属・保存と利用の接続

2026-09-26〜27に調査／内部検討用。対応稿は日本語v0.3 (see the evidence index)。

## 1. 調査から得た位置づけ

**第2報は、工程別の記憶評価と更新制御の研究に接続する、保存先別の比較と実経路の診断として書く。** 近接研究には、最終回答と保存物の区別、保存・検索・利用の切り分け、LLMの候補抽出とコードによる鮮度選択の分担まである。これらを本稿で初めて提案したとは位置づけない。

今回の材料で詳しく示せるのは、次の対応である。

- 同じ36更新案から本人・共同の処理有無を四分岐し、共同の正答に隠れた本人欄の不備と、全工程の成否に隠れた局所修復を同じ案の中で対応づけた。
- 新しい希望を正しく保存し、それを次入力にも渡した後、古い通知で旧行へ戻り、後続回答がその旧記録へ忠実に従う経路を追った。
- 二巡の実保存継続と別の希望更新診断を、保持・新情報の採用・変更後の維持という要求別に整理した。

これは観測と比較の具体性に基づく位置づけである。近接研究の成績と本稿の成績を同じ尺度で並べず、本稿から先行方式への性能上の優位も推定しない。追加実験は現稿の完成条件に加えない。

## 2. 調べ方と確認範囲

更新と時間、工程別評価、個別・共有記憶、決定論的制御の四方向から検索し、近接論文の参考文献を遡った。以下は選択した版の一次HTML・要旨・書誌を用いた焦点型調査であり、系統的レビューや新規性の網羅的証明ではない。主な検索語は `LLM agent memory knowledge updates temporal reasoning`、`memory stale propagation provenance shared memory`、`memory out-of-order updates temporal invalidation`、`agent memory conflicting updates`。StateAuditorとA-TMAの参考文献から、鮮度選択、MemTrace、MemProbe等へ広げた。

本文に採用した資料は、下表の該当方法節まで確認した。モデルや公開実装の再実行はしていない。版を固定して引用し、読んだv1を最新版とは呼ばない。MemProbeはv2で**MemAudit**へ改題されているため、本文は確認したv2へ揃えた。同名の**MemTraceが二本**あるため、著者とarXiv IDを併記して区別した。

Hugging Faceの論文検索ツールは呼出し時に `Tool paper_search not found`、論文Markdownの一取得はInternal Errorとなった。検索とarXiv一次HTMLへ切り替えた。二次資料の要約だけを根拠に本文へ採用していない。

## 3. 本文へ反映する近接研究

「本稿との対照」は今回の証拠に照らした著者側の整理であり、各論文自身の主張とは区別する。要約は評価対象に絞る。

| [HaluMem, Chen et al., v1](https://arxiv.org/html/2511.03506v1)、§4–6、特に§5.2 | 記憶の抽出・更新・質問応答を操作単位で評価し、更新の誤りと脱落を区別する | 工程別評価の明確な先行例。本稿は固定コードで欄ごとの一致を測り、同じ更新案に対する保存先分岐を置く |
| [A-TMA, Shi et al., v1](https://arxiv.org/html/2607.01935v1)、§3–5・付録A.5 | 記憶バンク、検索証拠、回答を分け、現状態と履歴の状態適合性を点検する | 「保存と利用を分ける」を新規性にしない。本稿は検索を挟まず渡した実保存物と回答を照合する |

| [MemTrace, Deng et al., v1](https://arxiv.org/html/2605.28732v1)、§2–4 | 記憶操作と中間変数の実行グラフを使い、誤りの種類と発生操作を追跡・帰属する | 中間物を追う研究は既にある。本稿は同一原案の四分岐と、保存先ごとの修復／残存不備に焦点を絞る |
| [MemTrace, Long et al., v1](https://arxiv.org/html/2606.17328v1)、§3.1–3.4 | 同一の知識点について現在・過去・変化経路と証拠条件を変え、到達と利用を診断する | 現在に合うことと、過去を正しく答えることは違う。本稿の最大版選択は現在状態を使う課題契約に対応する |
| [GroupMemBench, Yang et al., v2](https://arxiv.org/html/2605.14498v2)、§1–3 | 多者会話の情報を話者に帰属させ、質問者に応じた答えや共存する希望を評価する | 帰属を守ることは回答を違わせることではない。本稿では二役それぞれの担当客と観測者を明示する |
| [Don't Ask the LLM to Track Freshness, Reddy & Challaram, v1](https://arxiv.org/html/2606.01435v1)、§3・4.3・5.7・7 | 候補抽出をLLMへ、順序・時刻に基づく鮮度選択をコードへ分担する | 分担原理そのものは先行例あり。本稿は人物別選択を、本人欄／共同欄のどこへ適用するか比較する |
| [StateAuditor, Sun & He, v1](https://arxiv.org/html/2608.01619v1)、§4.4–4.5 | LLMの状態遷移案に対し、引用の根拠と時間順をコードで検証し、古い依存を使う回答の修復へ接続する | 出典・時間の検証と意味上の正しさを分ける先行例。全修復が検証済み遷移だけを通るわけではなく、基底監査へのフォールバックもある |
| [Zep, Rasmussen et al., v1](https://arxiv.org/html/2501.13956v1)、§2.1–2.2 | 出来事の時刻とシステムへの取込時刻を区別し、事実の有効期間と失効を扱う | 古い通知の到着と、新しい事実の発生を分ける足場。これだけでCU01型の後着旧版を必ず防ぐとは推定しない |
| [MemConflict, Tao et al., v1](https://arxiv.org/html/2605.20926v1)、§3.2–3.6・4.4 | 真の更新、後着の誤情報、条件ごとに共存する事実を分け、回答と検索証拠を評価する | 一律の最新版選択を広げる前に、どの情報が上書き可能かを契約として決める必要がある |

既存稿のMemGPT、Collaborative Memory、PROV-DM、CaMeLは背景として残す。Collaborative Memoryは[一次本文の個別／共有領域と読書き方針](https://arxiv.org/html/2505.18279v1)も追加確認した。個別・共有を設けることや来歴を表すことと、どの欄の最新版を選び直すかの実測を対応づける。CaMeLのcapability制御はセキュリティ上の処理分担であり、記憶鮮度の効果検証の代用にはしない。

パラメータ内の知識編集や、検索情報とモデル内知識の競合だけを主対象にした研究も検索結果に現れたが、保存ノートを受け渡す本稿の中心比較から外した。全候補を精読したことや、検索に現れなかった手法の不在は主張しない。

## 5. 原稿への反映方針

§2を「更新と時間」「記録・検索・利用の評価」「帰属と処理分担」に整理し、最も近い研究と本稿の比較単位を表2で示す。§6には、状態維持と利用の区別、既知の決定論的分担原理、最大版選択の適用契約を結ぶ短い参照を加える。実験の表・集計・正式結果・目安未達・事後参考の区別は保持する。

採用しない一般化は次の通り。

- 「先行研究は最終正答だけを見る」「工程分離が本稿で初めて可能になった」：HaluMem、A-TMA、MemAudit、二本のMemTrace等と合わない。
- 「最新版選択をコードへ渡す発想自体が独自」：Reddy & Challaramに直接の先行例がある。
- 「古い記録は一律に捨てるべき」「後から来たものが真」：履歴質問や条件付き共存を扱えなくなる。
- 「本稿の巻戻り原因を先行研究が証明した」：課題・モデル・介入が違い、提示位置や内部機構の原因同定にはならない。
- 「先行研究の区間が重なるので同等」：Don't Ask...の統計的な表現をそのまま借りず、ここでは処理設計だけを参照した。

## 6. 次の実験候補棚

| 候補 | 明確になる問い | 再検討する条件 |

| 担当客欄で同一原案・同一通知の処理OFF／ON比較 | 所属と版を固定する処理で、CU01の巻戻りをどこまで抑えるか | 本文で担当客欄への対策効果を主張したくなった時。正当変更・非対象保持・旧版拒否を事前に分ける |
