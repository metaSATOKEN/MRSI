# OS01オフライン監査：余分な集計を隔離すると、形式不備と判断不備を分けて読めた

2026-09-28。**56件の形式不備は、既知の追加欄を別保管すれば全件で指定回答欄を評価できた。そのうち54回答は内容・参照・共同利用が適切で、2回答には本人判断の誤りが残った。** 正常な328回答は原文バイト・採点とも不変だった。

ユーザー承認に基づく、OS01終了後の事後監査。正式結果 (see the evidence index)の56未確定は保持し、以下は「限定した受け口を使って同じ答案を読んだ場合」の参考値として分ける。新しいモデル回答・Colab実行・外部送信は0。

## 1. 何を切り分けたか

全384原回答を同じ規則で点検した。JSONの構文は全件成立しており、不備56件はすべて、利用回答の `local` 内に入力専用の `own_experience_summary` が追加されたものだった。

監査用の受け口は、**この一つの追加欄だけを隔離し、残りが元の出力schemaに完全適合するときに限って、指定回答欄を読む**。役・選択・根拠ID・共同割付は一切補正しない。対象の選定にも意味上の正解は使わない。

| 点検対象 | 結果 |
|---|---:|
| 元から構造適合していた回答 | 328/328で原文バイト・採点不変 |
| 既知の追加欄を持つ回答 | 56/56で限定隔離後に構造適合 |
| 隔離後の必須内容・参照・共同利用 | 54適切・2不適切 |
| 隔離欄の予測人数に誤りを含む回答 | 20/56 |
| 隔離欄を派生回答候補へ残した例 | 0 |

追加欄は原文と別の隔離記録に残した。56派生コピーからその欄を戻すと元のJSON値全体を完全に復元でき、指定欄の値・配列順序・IDの改変がないことを照合した。派生コピーのJSON空白やキー配置の再シリアライズは、値の変更とは区別する。

意味が正しかった54回答も、元の契約では指定外の欄を出している。その事実は出力契約遵守の指標へ残す。一方、隔離した欄を信用して次入力へ混ぜると、20回答に含まれた計算ミスまで持ち込むことになる。**回答欄の救済と、余分な内容の採用は別処理にする。**

## 3. 残った不備は二つの段階に分かれた

### 本人の利用：正しく保存した判断から外れた一条件

M12反転のAは、実経験から紙24人・デジタル22人で、直前に保存した本人判断も紙。U0の回答はデジタルで、U1では紙だった。同じパターンがF0/F1にあり、物理回答は2件、材料・経験条件としては一つである。

U0が余分に作った集計は紙23人・デジタル22人で、紙の数値も誤っていた。ただし、その誤集計でも紙が上回る。したがって「計算だけ直せば選択も必ず直る」とは今回の答案から決められない。受け口はこの誤答をそのまま不適切と数えた。

### 相手の確認：正しい提案を、実行できない対案へ変えた三条件

次の三条件はF0/F1で同一原文だった。入力された提案はすべて「Aに紙、Bにデジタル」で、実行可能な二案のうち最適だった。

| 条件 | A紙・Bデジタルの予測合計 | Aデジタル・B紙の予測合計 | 相手が返した対案 |
|---|---:|---:|---|
| M11反転 | 49人 | 47人 | 両者とも紙 |
| M12補強 | 48人 | 47人 | 両者ともデジタル |
| M14反転 | 49人 | 47人 | 両者とも紙 |

対案はすべて、確認役自身の本人推奨と同じ媒体を二人へ割り当てていた。本人推奨を共同案へ流用した可能性はあるが、答案に理由文はなく、生成原因の確定には使わない。M14では本人参照への相手の経験ID混入も残った。

合意が成立していないこの三条件で、後続回答は共同作業を適切に保留していた。隔離後はU0も含めてその処理を確認できる。**保留は適切だったが、共同方針を決める仕事は未成立だった。**

## 4. 次の受け口に採用する候補仕様

今回の実装は監査専用で、本番コードにはまだ接続していない。次設計への推奨は、次の対を固定すること。

**入力・出力の説明案：**

> `own_experience_summary` は入力資料に添えた参考集計です。出力する `local` は `subject`、`choice`、`evidence_refs` の三つだけです。参考集計を回答や保存ノートへ再記載しません。

**機械側の扱い：**

1. EOS・原文上限・厳密JSON・出力schemaを検査する。
2. 旧契約に適合する回答は原文のまま受理する。
3. USEの `/local/own_experience_summary` だけが余分なら、その一欄を隔離し、指定回答欄を構造検査する。値・参照の正誤で受理対象を選ばない。
4. 未知の追加欄、必須欄の欠落、型違反、別工程での同欄追加は拒否する。意味不備は意味採点へ残す。
5. 原文・隔離欄・派生回答・適用規則・hashを対応づけて保存する。隔離記録を書けなければ派生回答を引き渡さない。

報告は「原出力の契約遵守」「限定隔離後の受理」「意味上の適合」の三段に分ける。入力の定義を明確にする変更と、その既知逸脱を扱う受け口を同じ版に置き、次の比較では両条件に共通適用する。今回の56件に合わせた規則のため、未見回答での効き方は次の固定試験で測る。

次の研究対象は、**本人用集計を利用時に保ち、相手確認へ実行可能な共同候補と計算根拠を添えると、本人判断を保ちながら適切に受諾・差戻しできるか**。成功例も含む固定材料で比較する設計へ進むのがよい。確認役へ何を供給するかはその設計で固定し、今回の三失敗だけを成功するまで回す形にはしない。

| その他の案 | 今回の扱い・再検討条件 |
|---|---|
| 厳密拒否だけを続ける | 正式OS01の基準として保持。新受け口が指定欄を変えたり隔離記録を残せなければ、この枝へ戻す。 |
| すべての未知キーを捨てる | 採らない。新しい逸脱が観測されたら原文と正常対照を使い、別の限定規則として検討する。 |
| 本人形成の支援をさらに増やす | 今回は両条件32/32。別材料で形成不備が現れたときに再検討する。 |
