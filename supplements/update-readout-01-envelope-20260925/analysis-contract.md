# UR01外装正規化・事後参考分析の固定手順

2026-09-25。ユーザーが「別枠で正規化処理を点検し、その後に参考値として全体マージした分析」を明示承認した。この文書は結果取得後の分析手順であり、取得前登録とは呼ばない。元の正式成績と原記録を保持する。

すでに分かっていること：更新72回答のうち35件は正式受理、37件は一組の ` ```json ` と終端 ` ``` ` による形式不成立。37件の内側はJSON可読・schema適合と原因診断済みだが、内側の意味採点・合算は未実施。後続は35件だけ実行されている。

1. 正規化器はEOS・UTF-8・16384原文bytes以内を要求する。可読な裸JSONはbyte不変で通す。JSONとして不可読なら、厳密に先頭 ` ```json\n ` と末尾 ` \n``` ` が一致する一つの外装だけを外す。前置き・後書き、複数ブロック、別ラベル、改行違い、括弧不備、重複キー、NaN等、追加の修復が必要な出力は拒否する。空白・キー・値・配列／object・ID・版は変更しない。schemaと候補位置の検査は凍結済みコードでそのまま行う。
2. 受理・拒否fixtureで境界とbyte保持・再実行時の不変性を確認後、全72UPDATEを一律に処理する。元35件は無変更、37件だけ外装除去となる見込みを確認する。原文と正規化文・hash・除去箇所を別フォルダへ保存する。
3. 凍結済みscore_updateに正規化文を渡す。SELECTは実際の選択位置から元行を機械複製し、期待する最新行へ置換しない。再構成物は「事後再構成」と明記し、実験時のsaved-memoryへ書き戻さない。
4. 正式受理35件・今回再評価37件・合算72件をそれぞれ示し、修復／維持・方式・反復・本人保持・共同欄の値／人物／版／出典・入力実在行との一致を分ける。過去の主判定を保持し、同じ数値目安を参考分析へ当てはめた場合の判定と、方式差を併記する。p値・信頼区間・追加LLM生成は設けない。
5. 後続READは実測35件だけを保持し、欠測37件は残す。更新内容から機械計算した案内を出す場合は「再構成ノートからの静的計算」と呼び、実READ成功率へ合算しない。後続までの完全一致は凍結関数を使用し、未実施READを補完しない。
6. 原材料から別コードで最新版・担当事実を作り直し、原文の内側、SELECT位置と複製行、各成分と合算を検算する。失敗・残存不備も記録する。本番セルの契約や旧結果を変更せず、この別枠の分析で閉じる。

今回の予想：外装が外れれば37件の構造検査は通ると見込む。内容の整合性と方式差は未評価であり、外装の修復成功から意味の成功を推定しない。
